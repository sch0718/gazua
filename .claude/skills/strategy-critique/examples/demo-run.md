## 약세
- 전체 구간에서 전략은 보유 기준선보다 못했어요. 식: `-3.11 − 9.81 = -12.92`. 수익률 자체도 `-3.11`로 마이너스예요.
- 앞 반은 보유 기준선에 크게 못 미쳤어요. 식: `3.91 − 75.8 = -71.89`. 강세가 내세운 앞 반 `3.91`은 보유 대비로는 약점이에요.

- 승률 100%는 뜻이 약해요. `roundTrips = 4`(앞 반 3, 뒤 반 2)뿐이라 표본이 너무 작아요. 게다가 `winRatePct = 100`인데 `000660.pnl`은 음수예요. 청산된 거래가 전부 이익이라면 그 손실은 미청산(`openPositions = 1`)에서 나왔을 가능성이 커요. 어느 종목이 미청산인지는 입력에 없어서 확인 필요예요.
- 매수 조건(`rules.buy[0]`)은 RSI 상향 돌파 하나뿐이라 추세·거래량 같은 걸러내는 장치가 없어요. 매도는 +15% 익절 한 가지뿐이에요.

## 리스크
- MDD가 전체 `mddPct = -19.93`이에요. 앞 반 `-5.7`, 뒤 반 `-10.32`보다 깊어요. 구간별 결과를 합친 값은 아니고, 전체 기간을 따로 돌린 값이에요.
- 손실을 끊는 장치가 없어요. `rules.sell.stopLoss.on = false`, `rules.sell.trailing.on = false`, `rules.sell.timeExit.on = false`, `rules.sell.signal.on = false`예요. 청산 경로는 +15% 익절 하나뿐이에요.
- 거래 수 대비 신뢰가 낮아요. 왕복 4회(앞 반 3회, 뒤 반 2회)는 모두 10회 미만이에요. 결과 차이를 우연으로 볼 수 있어요.
- 동의하지 않음(강세에게): "세 구간 모두 지수 기준선을 앞섰다"는 주장은 근거로 약해요. `benchmarkReturnPct`는 세 구간 모두 `null`이라 지수 비교의 의미를 이 입력만으로 판단할 수 없어요. 지수 기준선은 `indexReturnPct = -65.96`(앞 반 `-58.28`, 뒤 반 `-19.73`)로 전체 구간에서 `holdReturnPct = 9.81`과 부호가 반대예요. 그래서 보유 기준선을 더 엄격한 비교 대상으로 봐야 해요.
- 동의하지 않음(약세에게): "한두 종목에 쏠렸다"는 해석에는 단서가 붙어요. 종목이 둘뿐이라 쏠림과 분산을 가르기 어려워요. 그리고 `000660`이 두 구간 모두 마이너스인 것(`-70441.1656`, `-391002.5584`)은 한 번의 사건이 아니라 반복된 패턴일 수 있어요.
- 기준선 부호 검산: 전체 `-3.11 < 9.81`(전략이 보유보다 낮음), 앞 반 `3.91 < 75.8`(낮음), 뒤 반 `0.52 > -37.39`(높음). 뒤 반만 보유 기준선을 앞서요.
- 거래 비용(`costs.feePct`)이 시뮬레이션에 반영됐는지 확인 필요예요.

## 정리
### 합의와 이견
- 합의: 전체 구간에서 전략은 보유 기준선보다 못하고(`-12.92`), 거래 수가 적어(`roundTrips = 4`) 승률 100%를 믿기 어려워요. 손실을 끊는 매도 규칙이 모두 꺼져 있다는 점(`stopLoss`·`trailing`·`timeExit`·`signal`의 `on = false`)도 세 역할이 함께 짚었어요.
- 이견: 지수 기준선 대비 초과를 강점으로 볼지에 대해서는 강세와 리스크의 의견이 갈렸어요(`benchmarkReturnPct = null`, 보유 기준선과 부호 반대).
- 신호: 매수 조건이 맞는 종목 0/2예요(`asOf = 2026-10-30`, `includesToday = false`). 이 스킬은 종목을 사고팔거나 들고 있으라고 말하지 않고, 전략 규칙을 따지는 참고 의견만 내요.

### 아이디어 1: 미청산 손실을 끊는 손절
- **겨냥:** `simulate.summary.openPositions = 1`, `simulate.perSymbol[1].pnl = -1235975.2587`, `rules.sell.stopLoss.on = false`
- **바꿀 곳:** `rules.sell.stopLoss` 값 바꾸기 (손절 사용 › 손절폭)
```json
{"on":true,"pct":10}
```
- **확인할 숫자:** `summary.totalReturnPct`, `summary.mddPct`, `summary.winRatePct`, `perSymbol[].pnl`

### 아이디어 2: 추세가 꺾인 뒤에도 안 팔리는 포지션을 닫는 조건 매도
- **겨냥:** `rules.sell.signal.on = false`, `simulate.summary.openPositions = 1`, `simulate.perSymbol[1].pnl = -1235975.2587`
- **바꿀 곳:** `rules.sell.signal` 값 바꾸기 (조건 매도 사용 › 조건 매도 묶음 1 › ＋ 조건 › RSI)
```json
{"on":true,"groups":[{"conds":[{"kind":"rsi","period":14,"level":70,"op":"crossDown"}]}]}
```
- **확인할 숫자:** `summary.totalReturnPct`, `summary.openPositions`, `summary.roundTrips`, `perSymbol[].pnl`

### 아이디어 3: 하락 추세 진입을 줄이는 이동평균 필터
- **겨냥:** `rules.buy[0]` 조건이 RSI 하나뿐임, `simulate.perSymbol[1].pnl = -1235975.2587`, `simulate-second-half.summary.mddPct = -10.32`
- **바꿀 곳:** `rules.buy[0]` 조건 추가 (매수 묶음 1 › ＋ 조건 › 이동평균 위·아래)
```json
{"kind":"maPrice","period":60,"side":"above"}
```
- **확인할 숫자:** `summary.totalReturnPct`, `summary.mddPct`, `summary.roundTrips`, `perSymbol[].pnl`

### 검증 순서
1. 앱에서 전략을 복사한다(원본은 그대로 둔다).
2. 아이디어 하나만 바꾼다.
3. 같은 기간과 앞·뒤 반 기간을 다시 시뮬레이션해 원래 결과(입력 요약 표)와 비교한다.
4. 거래 수가 적으면(왕복 10회 미만) 결과 차이를 우연으로 본다.

### 확인 필요
