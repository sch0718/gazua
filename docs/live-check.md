# 실연결 점검 목록

단위 테스트는 녹화된 응답(fixture)으로 도는 거라, **실제 키로 한 번 확인해야 하는 가정**이 남아 있어요. 아래 항목을 실제 계정으로 확인하고, 결과에 따라 표시한 곳을 고쳐요. 확인한 날짜와 결과는 각 항목 끝의 `결과:` 줄에 적어 둬요.

- 준비: 프록시와 키가 연결된 상태(설정 › 연결 진단이 모두 통과). 장중·애프터마켓·휴장일을 나눠 보려면 시간을 달리해 여러 번 확인해야 해요.
- 응답을 열어 볼 때는 키·토큰이 터미널 기록이나 이슈에 남지 않게 조심해요.

## ① KIS 분봉 시각이 봉의 끝인가

- **무엇을**: `stck_cntg_hour`가 봉의 끝 시각인지(09:01 행에 09:00:xx 체결이 들어 있는지). 그리고 15:30 종가 단일가 체결이 15:20–15:30 구간 봉에 들어오는지.
- **어떻게**: 장중에 `inquire-time-dailychartprice`(FHKST03010230)를 한 종목으로 호출해 첫 행들의 시각과 시가·고가·저가·종가를 거래 앱의 분봉과 비교해요. 장 마감 뒤에는 15:20–15:30 행의 종가가 그날 종가와 같은지 봐요.
- **바꿀 곳**: `src/lib/providers/kis.ts`의 `KIS_MINUTE_TIME_IS_BAR_END`. 시작 시각이면 `false`. 분봉 시각 해석은 이 상수 한 곳에서만 해요.
- 결과:

## ② KIS 일봉의 `NX`·`UN` 응답

- **무엇을**: 시장 구분 코드 `NX`(NXT)·`UN`(통합)으로 일봉을 요청하면 값이 오는지, `J`(KRX)와 어떻게 다른지.
- **어떻게**: NXT 지원 종목 하나로 `J`·`NX`·`UN` 세 번 호출해 날짜 범위·종가·거래량을 비교해요.
- **바꿀 곳**: `src/lib/providers/kis.ts`의 `MARKET_DIV`와 일봉 요청부. 빈 응답이면 해당 거래소 일봉은 KRX로 대체하는 규칙(`KRX 대체` 배지)을 확인해요.
- 결과:

## ③ KRX 일봉 종가에 애프터마켓 체결이 포함되는가

- **무엇을**: `J`(KRX) 일봉의 종가·고가·저가·거래량이 15:30 이후(NXT 애프터마켓) 체결을 포함하는지.
- **어떻게**: 애프터마켓이 있었던 날, 같은 날의 KRX 일봉 종가를 거래 앱의 정규장 종가(15:30)와 비교해요.
- **바꿀 곳**: `src/lib/data/candleService.ts`의 `DAILY_CLOSE_INCLUDES_AFTER_MARKET`. 포함하면 `true`로 바꾸고 1일 차트 기준값 보정(`adjustmentFactor`)을 확인해요.

## ⑥ 장중·애프터·휴장일 화면 점검

- **무엇을**: 시간대별 화면이 스펙대로 보이는지.
- **어떻게**: 아래를 각각 실제 시간에 열어 봐요.

- **바꿀 곳**: 꺼지면 `src/lib/screen/precompute.ts`(지표 배열)와 `src/lib/screen/holdSelection.ts`, Worker의 데이터 보관(`src/lib/screen/workerHandler.ts`).

## ㉑ 실제 수집기가 FRED와 KIS 테마를 받는가

- **무엇을**: `pnpm collect`가 FRED(`DEXKOUS`, `DCOILWTICO`)와 KIS `theme_code.mst`를 실제로 받아 버전 2 파일을 만드는지. 형식이 맞지 않는 테마 행이 얼마나 빠지는지.
- **어떻게**: 키를 환경변수로 넣고 `pnpm collect -- --years 5`(또는 `--update`)를 돌린 뒤, 스크립트 끝 요약의 `환율 N일 · 유가 N일 · 테마 N개`와 `형식이 맞지 않는 행` 줄을 읽어요. 환율·유가 일수가 5년치(약 1,300일 이상)인지, 테마 수와 종목 수가 KIS 테마 화면과 비슷한지 봐요.
- **함께 볼 것**: 네트워크를 끊거나 FRED 주소를 잘못 줘서 일부러 실패시켰을 때 경고만 내고 끝까지 끝나는지, `--update`에서 FRED가 실패하면 이전 환율·유가가 남는지.
- **바꿀 곳**: `scripts/fetch-fred.mjs`, `scripts/parse-theme.mjs`, `scripts/collect-market-data.mjs`의 테마·환율 구간.
- 결과: 환율 __일 / 유가 __일 / 테마 __개 / 빠진 행 __ / 실패 시 동작 __

## ㉒ 실제 데이터로 테마 + 원/달러 민감도 선정

- **무엇을**: 앱에서 실제 수집 파일로 테마 하나와 원/달러 민감도 조건을 같이 켜고 미리 보기와 검증 실행이 되는지.
- **어떻게**: ㉑에서 받은 파일을 설정 › 데이터에서 가져와요. 새 기준에서 후보 범위의 테마(예: 방산·반도체 등 실제 있는 것) 하나를 고르고, 원/달러 민감도를 켜서 최소 1.0으로 둔 뒤 미리 보기, `검증 실행`을 눌러요. 선정 이력 행을 펼쳐 `원/달러 민감도 0.82 · 최근 20일 +3.4%` 모양의 값 줄을 확인해요.
- **함께 볼 것**: 결과 도움말에 테마 메모(`테마·내 묶음은 지금 구성을 과거에도 써요…`)가 나오는지, 값이 상식과 맞는지(수출주는 원/달러 민감도가 +쪽), 5년 파일에서 실행 시간이 ⑳과 비슷한지.
- **바꿀 곳**: `src/lib/screen`의 민감도 계산(`macro`)과 테마 후보 범위, 스펙 `2026-10-16-macro-theme-criteria-design.md`.
- 결과: 테마 __ / 민감도 값 상식과 일치 __ / 실행 시간 __
