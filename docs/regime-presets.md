# 시황별 프리셋

시황(상승·하락·횡보·급락)에 따라 사람이 프리셋을 고를 수 있게 하려고, 과거 시장 데이터로 프리셋을 시황 구간마다 시험한 결과와 화면 설계예요. 과거 결과일 뿐 앞으로를 약속하지 않아요.

## 전제와 범위

- 사용자 1명이 쓰는 앱이에요. 「지금 시황」 자동 판정, 시황에 따라 연습 전략을 바꾸는 기능, 시장 지수 조건 같은 새 조건은 만들지 않아요.
- 이미 있는 프리셋 6개로 시황마다 근거가 서면 새 프리셋을 더하지 않아요(연습이 프리셋마다 원장을 하나씩 만들기 때문이에요).

## 시황 구분 규칙

데이터: 수집 데이터(toss 수정주가, 2021-11-16~2026-11-05)의 KOSPI 일봉. 120일선을 쓰려고 첫 120거래일은 라벨이 없어서 구간은 2022-05-12부터예요.

하루마다 다음 순서로 정하고, 20거래일 미만인 구간은 더 긴 이웃에 합쳐요.

1. 급락·고변동: 최근 10거래일 −8% 이하, 또는 20일 일간 변동성 2% 이상이면서 60일 고점 대비 −8% 이하
2. 상승장: 종가가 120일선 위이고 60거래일 수익률 +5% 이상
3. 하락장: 종가가 120일선 아래이고 60거래일 수익률 −5% 이하
4. 그 밖은 횡보장

## 시험 방법

- 종목: 일반 주식(ETF·ETN·리츠 제외, 관리·거래정지 제외) 중 최근 1년 거래대금 상위 150종목에서 무작위 8종목 묶음 40개(씨앗 고정). 구간마다 같은 묶음을 써요.
- 앱의 `simulate()`를 그대로 불러 구간마다 돌렸어요(프리셋 6개 + 숫자를 바꾼 변형 27개 = 33개 전략, 구간 15개, 묶음 40개).
- 지표: 묶음 평균 총수익, 최대 낙폭(MDD), 승률, 거래 수, 같은 종목·기간 그냥 보유. 아래 표는 같은 시황 구간들의 평균이고, 「+구간」은 구간 평균 수익이 플러스인 구간 수예요.
- 변형: RSI(2) 프리셋은 필터(200·120·60일선·없음)×기준(5·10·15), 급락 프리셋은 낙폭(−7·−10·−15%)×RSI(5·10), 신고가는 기간(20~250일)×거래량 조건, 추세는 이동평균(60·120·200일), 교차는 5/20·20/60이에요. 몇 개를 바꿔도 방향이 같은 것만 채택했어요.

## 읽는 법과 한계

- **사후 분류예요.** 구간은 지나고 나서(짧은 구간 합치기 포함) 나눈 거라, 그 당시에 시황을 알아보고 골랐다는 뜻이 아니에요. 카드 문구에도 「지나고 나서 나눈 구간」이라고 밝혀요. 당시 데이터만으로 시황을 판정하는 검증은 「지금 시황 자동 판정」과 함께 이번 범위 밖이에요.
- **탐색 결과예요.** 같은 구간에서 변형 33개를 보고 골랐어요. 따로 떼어 둔 평가 기간이 없어서(구간이 적어요) 「몇 개를 바꿔도 방향이 같은지」만 기준으로 삼았고, 새 프리셋은 더하지 않았어요.
- **종목 표본.** 거래대금 상위 150은 2026년 기준이라 과거 상장폐지·탈락 종목이 빠진 생존 편향이 있어요. 거래대금은 수정 종가×거래량 근사예요.
- **재현.** `regime.mjs`(구간), `bt.ts`(시험), `agg.mjs`(집계), 구간 목록·전체 결과는 공유 노트 폴더 `research/`에 있고, 묶음 씨앗·규칙은 스크립트에 고정돼 있어요. 승률은 청산된 거래만의 값이고 거래 수는 미청산을 포함해요.

- 상승장: 어떤 프리셋도 그냥 보유를 못 따라가요(보유 +53%). 그중 이동평균 추세 계열(60·120·200일선)이 4구간 모두 플러스이고 변형 사이 방향이 같았어요. 신고가 돌파도 4/4 플러스지만 수익이 작아요. 그래서 상승장은 「덜 먹더라도 추세를 따라가는」 규칙으로 보여 줘요.
- 하락·급락장: 낙폭 −7·−10·−15%와 RSI 5·10 여섯 변형이 모두 플러스이고, 같은 기간 보유(−2.4%, −10.1%)보다 나았어요. 이동평균 추세·신고가는 하락·급락에서 승률이 낮고 손실 쪽이었어요.
- 횡보장: 어떤 프리셋도 보유를 못 따라가요. 거래가 적고 MDD가 낮은 RSI(2) 눌림목이 5구간 중 4구간 플러스(승률 62%)여서 고르지만, 수익은 작아요. 근거가 가장 약한 시황이에요.
- 표본: 급락 2구간·하락 3구간이 전부예요. 수집 데이터가 2026-11-05에서 끝나 2026-11-25 급락은 빠졌어요. 구간 수가 적어 「이 시황에서 이런 경향이 있었다」까지만 말해요.
- 앱 기본값은 진입 1회에 처음 자금의 10%만 써서 평균 현금 비중이 커요. 그냥 보유는 전액을 처음부터 담으니, 보유와의 수익 차이는 규칙보다 노출 차이가 큰 몫이에요. 시황별 상대 순위와 낙폭을 보는 용도예요.

## 프리셋 정리(설계)

새 프리셋은 더하지 않아요(6개 유지, 연습 원장 수도 그대로). `StrategyTemplate`에 `regimes: Regime[]`(`'up'|'down'|'range'|'crash'`)와 한 줄 `evidence`를 더해요.

| 프리셋 | regimes | evidence(카드 한 줄) |
|---|---|---|
| 200일선 추세 추종 | up | 과거 상승장 4구간 모두 수익(그냥 보유보다는 작음, 구간은 지나고 나서 나눔) |
| 52주 신고가 돌파 | up | 과거 상승장 4구간 모두 수익(그냥 보유보다는 작음) |
| RSI(2) 눌림목 | range, down | 과거 횡보장 5구간 중 4구간 수익, 하락장 3구간 중 2구간 수익 |
| 급락 후 단기 반등 | down, crash | 과거 하락장 3구간 모두, 급락장 2구간 모두 수익 |
| 하락 후 반등 | (없음) | |
| 골든크로스 50/200 | (없음) | |

- 같은 프리셋이 시황 두 곳에 나오는 건 허용해요(카드가 두 번 보여요). 시황 표시가 없는 프리셋은 「그 밖의 전략」 묶음에 둬요.
- 화면: `StrategyList.svelte` 선택 시트의 프리셋 목록을 「상승장 → 횡보장 → 하락장 → 급락 뒤 → 그 밖의 전략」 제목 아래로 묶어요. 카드는 지금 모양에 `evidence` 한 줄(「과거 …에서 시험」)만 더해요. 프리셋 비교(`compareTemplates`)는 `TEMPLATES`를 그대로 쓰니 그대로 동작해야 해요.
- 시황 순서·이름·그룹핑은 `templates.ts`의 작은 상수로 두고, 목록 계산 함수 하나(`templatesByRegime`)로 화면을 단순하게 해요.

## 구현 계획

1. `src/lib/sim/templates.ts`: `Regime` 타입, `StrategyTemplate.regimes`·`evidence`, 표의 값, `REGIMES`(id·제목만)와 `templatesByRegime()`. `templates.test.ts`에 시황 표시 시험(그룹 순서, 그룹별 정확한 프리셋 id 목록, 표시 없는 프리셋은 「그 밖」, 6개 유지).

4. 릴리스 준비: v0.14.0(`package.json`, `proxy/package.json`), README 릴리스 표 맨 위 한 줄, `src/lib/help/release-notes.ts` 맨 앞 항목.
