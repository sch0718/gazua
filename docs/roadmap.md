## 최우선 1: 나만의 투자 전략과 시뮬레이션 재생

전략 빌더(PR #62)와 재생(PR #60)은 구현됐어요. 아래 재생 계획과 한계는 2026-10-31 조사 기록이에요.

### 지금

- 전략(`src/lib/sim/types.ts`의 `Strategy`)은 v2 형식이에요(`src/lib/sim/strategyV2.ts`).
  - 이동평균·RSI·거래량·가격·반등 패턴 조건을 조합해요. 묶음 안은 AND, 묶음끼리는 OR예요(`src/lib/sim/rules.ts`).
  - 분할 매수, 1~3단계 익절·손절에 트레일링 스톱·기간 청산·조건 매도를 더했어요(`src/lib/sim/position.ts`, `src/lib/sim/simulate.ts`).
  - 최대 8종목이며, 처음 자금·총자산·남은 현금의 비율 또는 종목별 같은 금액으로 배분해요.
- 선정 기준이 전략을 참조해 매매하는 연결은 이미 있어요(`src/lib/screen/runValidation.ts`).
- 이 기기 시장 파일이 없으면 맥 프록시에서 요약·미리 보기·검증 결과만 조회한다(설계 `2026-11-12-market-remote-design.md`).

### A: 전략 빌더 (구현됨)

- 지표·가격·거래량 조건을 조합하는 편집기와 자금 배분 선택을 구현했어요(`src/lib/ui/simulate/StrategyEditor.svelte`).
- 기존 v1 전략은 읽을 때 v2로 옮겨요(`src/lib/sim/strategyV1.ts`의 `toV2`, `src/lib/sim/strategyStore.ts`).
- 엔진(`src/lib/sim/simulate.ts`, 순수 TS)은 일반 조건식으로 실행해요.
- 설계: `docs/superpowers/specs/2026-11-01-strategy-builder-design.md`. PR #62(`f5377a2`)로 병합됐어요.

### B: 재생 (구현됨, PR #60)

- 엔진이 거래일마다 아래 값을 내보내게 해요.
  - 종목별 보유 수량·평단·종가·평가액
  - 손절가·다음 추가 매수가·익절가
  - 신호 발생일
- 지금 `SimResult`에는 자산 곡선 `equity[]`와 체결 `trades[]`만 있어요. 일별 포지션은 없어요.
- 결과 화면에 아래를 더해요.
  - 재생/일시정지
  - 배속(예: 1·2·4·8배)
  - 하단 타임라인: 누르면 그 거래일로 이동해요.
  - 날짜 패널: 특정 날짜를 누르면 그날의 보유·현금·신호 상태를 보여 줘요.
- 차트는 기존 `lightweight-charts`를 써요.

### 백테스트 보완 (구현됨, PR #76)

- 끝난 거래가 20번 미만이면 경고하고, 보유 중 매도 비용을 안내해요. 1년 미만 검증은 연환산을 빼요. 슬리피지가 없다는 점은 도움말에 적었어요.
- 결정(D1~D5): `docs/superpowers/specs/2026-11-04-backtest-decisions-design.md`, 점검표 `docs/proposals/2026-11-03-backtest-checklist.md`.

### 한계

- 일봉 단위라 「시간대」는 거래일 단위예요. 장중 체결 시각은 없어요.
- 계산은 메인 스레드에서 돌아요(`src/lib/ui/simulate/runController.svelte.ts`). 웹 워커로는 옮기지 않기로 했어요(2026-11-07). 10년·8종목(종목 수 상한)도 맥 M2에서 약 24ms라 화면이 멈추지 않아요(`src/lib/sim/simulate.perf.test.ts`). 시간이 오래 걸리는 쪽은 일봉 받기인데, 이미 비동기로 받고 진행 표시와 취소가 돼요. 폰에서 멈춤이 보이면 그때 선정 기준 검증의 워커(`src/lib/screen/worker.ts`) 방식으로 옮겨요.

## 최우선 2: AI가 쓰는 가즈아 CLI

읽기 전용 단계 A는 구현됐어요. 실계좌 주문은 결정이 필요해요.

### 지금

- 토스 토큰을 맥 프록시가 맡음(2026-11-13). 웹·CLI·수집기가 관리 여부를 확인해 키 없이 쓰고, 주문 발급 실패는 미전송으로 처리해요. [운영 안내](../proxy/README.md#토스-토큰을-맥-프록시가-맡기).
- `cli/` 워크스페이스에 읽기 전용 `gazua` 진입점이 있어요(`cli/src/main.ts`). PR #63(`729e072`)으로 병합됐어요.
- 동기화 API(`sync-worker`)는 브라우저의 Origin 검사·`X-Gazua-Session` 세션과 별도로 CLI 기기 코드 로그인·읽기 전용 토큰 인증을 지원해요(`sync-worker/src/cli.ts`). 로그인은 사람이 앱에서 기기 코드를 승인해야 끝나요.
- 공급자 코드(`src/lib/providers/toss.ts`·`kis.ts`)를 Node에서도 재사용해요. CLI는 프록시와 같은 허용 목록을 적용해 증권사를 직접 호출해요(`cli/src/direct.ts`).
- 같은 코어를 감싸는 읽기 전용 MCP 서버 `gazua mcp`(stdio, 도구 7개)가 있어요. 설계는 `docs/superpowers/specs/2026-11-02-readonly-mcp-design.md`예요.
- MCP 결과로 전략의 약점을 따지는 역할 토론형 Claude Code 스킬 `.claude/skills/strategy-critique/`가 있어요(외부 도구 검토 3절 (a)안, 설계 `docs/superpowers/specs/2026-11-03-strategy-critique-skill-design.md`). 출력은 참고 의견이며 매매 신호가 아니고, 개선 아이디어는 전략 빌더 조건식으로 내요.
- 프록시는 주문 경로를 막아요(`proxy/src/allowlist.ts`). 주문 코드는 없어요.
- 「주문 없음」은 최초 설계부터의 결정이에요(`docs/superpowers/specs/2026-10-11-stock-compare-design.md` §1.3, `docs/proposals/2026-10-25-server-and-db.md`).

### 단계 A: 읽기 전용 CLI·MCP (구현됨)

- `gazua profiles`·`watchlists`·`strategies`: 동기화한 프로필·관심 그룹·전략 조회
- `gazua quote`: 시세 조회, `gazua holdings`: 토스 국내 보유 수량·평단 조회(KIS 보유 조회는 지원하지 않아요)
- `gazua signals`·`simulate`: 전략 신호 계산과 시뮬레이션 요약
- 기계가 읽기 좋은 JSON 출력(기본 한 줄)
- `gazua login`·`logout`: 기기 코드 로그인과 토큰 철회
- `gazua mcp`: CLI 읽기 명령과 일대일인 MCP 도구 7개(`login`·`logout` 제외). Claude Code 등록 방법은 `cli/README.md`의 「MCP 서버」 절에 있어요.
- 설치·명령·제약·배포 순서는 `cli/README.md`, 설계는 `docs/superpowers/specs/2026-11-01-readonly-cli-design.md`에 있어요. 운영 Worker에는 D1 `0005` 마이그레이션·`CLI_IP_SALT` 시크릿과 함께 배포했어요(2026-11-01).

### 단계 B: 주문 제안·모의투자

- 주문처럼 보안이 더 필요한 동작에는 2차 인증을 둬요. 방식(패스키 등)은 이 단계 설계에서 정해요(사용자 결정, 2026-11-06).

- AI가 전략 신호로 주문안을 만들어요. 사람이 확인해야 실행돼요.
  - 가장 작은 버전으로 `gazua signals --propose`(MCP `signals`의 `propose`)가 주문안을 내요(2026-11-07). 주문은 보내지 않고 사람이 증권사 앱에서 직접 주문해요. 단계 A를 아직 거의 쓰지 않아 여기서 멈추고, 실제로 쓰는지 2026-12-07에 확인해요.
- KIS 모의투자 환경으로 먼저 검증해요. 모의투자로 할 수 있는 범위는 실연결로 확인해야 해요.

### 단계 C: 실계좌 주문 (작은 버전 구현됨, 2026-11-12)

- 전략 자동 실행기(`gazua auto`, 2026-11-13): 장중 네이버 임시 일봉으로 한 번 판정하고, 연습·실전 원장과 ntfy 알림을 남긴다. 실전은 기존 토스 프록시 경로를 쓰며 주문 전 원장 기록으로 중복 전송을 막는다. 기본은 연습이고 예약 작업은 사용자가 설치한다. [설계](superpowers/specs/2026-11-13-auto-trader-design.md) · [사용법](../cli/README.md#자동-실행기).
- 2026-11-27: 연습 모드 두 주의 알림 기록을 보고 사용자가 실전 전환 여부를 정한다. 전환했다면 2026-12-27에 감사 로그의 자동 실행 주문을 확인한다.


- 사용자 결정(2026-11-12): 실계좌 주문을 만든다. 주문 가능한 최대 금액을 정하고 그 금액 이상은 자동으로 거래할 수 없게 한다. 단계 B(모의투자·2차 인증)는 하지 않는다. 설계: [실계좌 주문 1회 최대 금액](superpowers/specs/2026-11-12-order-cap-design.md).
- 정한 것:
  - 프록시 주문 경로: 맥 Node 프록시의 `POST /order/toss`만. 토스 국내 지정가·당일 매수·매도만 받고 정정·취소·조건주문·시장가는 막아요. Worker 판과 `PROXY_TOKEN`이 없는 서버는 받지 않아요.
  - 주문 한도: 1회 주문 금액(수량×지정가)이 `ORDER_MAX_AMOUNT` 이상이면, 보낸 매수 − 접수 성공을 확인한 매도 잔액이 총 가용 금액 `ORDER_TOTAL_MAX_AMOUNT`를 넘으면 프록시가 거절해요(둘 중 하나 이상 필요, 1회 한도가 없으면 총 가용 금액이 최대). 하루 금액(선택), 분당 매수 3건·하루 20건 상한. 한도는 맥의 `proxy/.env`에서만 바꿔요.
  - 즉시 중지: 중지 파일(`~/gazua-order.stop`)이 있으면 모두 거절해요(재시작 없이).
  - 감사 로그: `~/Library/Logs/gazua-orders.jsonl`(권한 600, 키·토큰 없음). 재시작 때 오늘 합계를 되살려요.
  - 사람 승인: 수동 주문은 `gazua order … --yes`를 직접 실행하고, 자동 실행은 사용자가 `AUTO_MODE=live`로 바꿔 승인해요. MCP 도구로는 내보내지 않아요.
- 남은 것: 허용 종목 목록, 취소 경로, 웹 상태 표시, KIS 주문. Claude는 실제 주문을 실행하지 않아요. 첫 소액 주문은 사용자가 `.env`에 한도를 넣고 켠 뒤 직접 확인해요. 2026-12-12에 감사 로그에 `send`가 있는지 확인해요.
- 최초 설계의 「주문 없음」 결정을 이 범위만큼 바꿨어요. 위험은 AI 오판, 프롬프트 주입, 키 노출, 실제 손실이에요.
- 약관상 자동 주문 허용 범위(2026-11-06 검토): 본인 계좌의 API 자동주문은 두 증권사 모두 막지 않아요.
  - KIS: 「오픈 API 서비스 이용 약관(고객)」(version 28, 최종 수정 2024-04-11, [공개 약관 API](https://apiportal.koreainvestment.com/api/terms/public?termsType=MARKET)) 제3조가 매매주문업무를 적용 범위에 넣어요. 자동주문을 막는 조항은 없어요. 키 대여·누설 금지(제5조 ②), 시세 제3자 제공 금지(제5조 ③), 서버 부하·불법 대여 계좌 때 이용 중지(제9조)가 있고, 고객 과실로 키가 새어 생긴 부정 사용 손해는 회사가 책임지지 않아요(제17조).
  - 토스: 주문·정정·취소와 조건주문 API를 공식으로 제공해요([개요](https://openapi.tossinvest.com/openapi-docs/overview.md)). [FAQ](https://openapi.tossinvest.com/openapi-docs/faq.md)에 따르면 짧은 시간의 대량 반복 주문은 어뷰징으로 보고 매매를 일정 시간 제한해요. 데이터는 본인 매매 목적으로만 써요. 앱에서 동의하는 Open API 이용약관 원문은 공개본을 찾지 못해 확인 필요예요.
  - 법규: 2023-04-25 시행된 고속 알고리즘 매매 등록제는 증권사 전산센터와 같은 건물에 서버를 둔 주문이 대상이라, 저빈도 API 주문은 대상 밖으로 보여요(언론 보도 기준, 확인 필요).
  - 설계에 반영할 것: 주문 빈도 상한, 키 보호와 2차 인증, **본인 계좌 전용**. 지인 초대 멤버 계좌에 전략·AI 주문을 내 주는 것은 투자일임·투자자문업에 걸릴 수 있어 범위에서 빼요(법률 확인 필요).

## 보류: 과설계로 판단한 것

2026-11-03에 사용자가 「사용자 1명, 여러 기기, 무료 운영」이라는 전제(제안서 7절)에 비해 과하다고 보고 보류했어요. 필요가 생기면 다시 범위를 정해요.

- **서버·DB 3단계 중 공동 그룹·정기 계산·알림**
  - 공동 그룹: 사용자가 1명이라 함께 쓸 사람이 없어요.
  - 정기 계산: 무료 Cron 5개를 나눠 써야 하고, 무거운 계산은 이미 맥에서 해요.
  - 알림: 범위 밖인 「가격 알림·푸시」와 거의 겹쳐요.
- **성과 이력**: 서버 동기화는 하지 않아요. 필요하면 제안서 5절대로 로컬 스냅샷부터 작게 만들어요.
- **주문 캐시 E2EE 동기화**: 주문 캐시는 증권사에서 다시 받으면 돼요. 프록시 주소·토큰은 2026-11-06에 키 동기화에 넣었어요([키 동기화 설계](superpowers/specs/2026-10-31-key-sync-design.md) 1.3-1).
- **Drive 새 시장 파일 알림 확대(첫 화면·선정 기준)**: Drive 전달(#68)을 켜고 실배포 점검 ㉜를 한 뒤에 필요하면 다시 봐요.
