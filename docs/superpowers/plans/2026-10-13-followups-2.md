# 후속 2차 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docs/superpowers/followups/2026-10-12-gazua-followups.md`의 "새 후속" 절(PR #7 리뷰에서 남긴 항목)을 처리한다.

**Architecture:** 기존 구조를 유지한 채 작은 수정과 테스트 보강을 영역별 작업으로 묶는다. 사용자 결정 두 건은 비교 화면 동작을 바꾼다. 연결 오류 배너는 연결 오류를 합쳐서 세고, 키보드 포커스가 리더보드 안에 있으면 순서를 고정한다.

**Tech Stack:** Svelte 5 runes, TypeScript, Vitest + @testing-library/svelte, Playwright + axe, GitHub Actions.

**Spec:** docs/superpowers/specs/2026-10-11-stock-compare-design.md

## 사용자 결정 (2026-10-13)
- **D1 섞인 연결 오류:** `proxy-unreachable`과 `timeout`을 합쳐서 센다. 합계가 행의 과반(> total/2)이면 배너를 띄운다. 배너 코드는 둘 중 더 많은 쪽이고, 같으면 `proxy-unreachable`이다. 그 밖의 코드는 지금처럼 코드별로 판단한다.
- **D2 실시간 재정렬:** 키보드 포커스가 리더보드 목록 안에 있는 동안은 행 순서를 고정한다. 값은 계속 갱신한다. 포커스가 목록을 벗어나면 다시 정렬한다. 스크럽 중 `frozenOrder`와 같은 방식으로 한다.

## 범위 밖 (후속 문서에 그대로 남김)
- UN 일봉 실패의 하루 메모: 실연결 점검 ②가 먼저 필요하다.
- AUTO 16:00 전환과 실제 KRX 시간표의 대조.
- 기간 내내 거래정지인 종목의 띠: 문서화된 한계다.
- D1 초과수익의 캔들 값: 허용 동작이다.
- 스크린리더 실기기 확인.
- 시트가 열린 중 다른 스낵바 동작: 스펙 §7.3이 허용한다.
- `window.confirm` 대체 UI.

## Global Constraints
- UI 문구는 ~해요체. 주석은 한국어로 적게.
- 새 런타임 의존성 없음. 기존 토큰과 컴포넌트를 재사용한다.
- 공유 컴포넌트의 기본 동작은 유지한다. 새 prop은 선택으로 둔다.
- 키·토큰을 로그·오류·URL·배너에 넣지 않는다. 프록시 주소는 origin만 쓴다.
- 프록시는 시세 경로 허용 목록만 둔다. 주문·계좌 경로는 `403 proxy-path-blocked`를 유지한다.
- 동작이 바뀌면 같은 커밋에서 스펙을 고친다.
- 검증: `corepack pnpm test`, `check`, `check:e2e`, `build`, `e2e`. 프록시를 건드리면 `--filter proxy test`도 돌린다.

## Review Focus
1. **D2 고정:** 포커스가 목록 안에 있는 동안 새 종목 추가나 삭제가 일어나도 행이 사라지거나 중복되지 않아야 한다. 고정 순서에 없는 종목은 끝에 붙인다.
2. **D2 해제:** 포커스가 시트로 옮겨 가거나 클릭으로 빠지면 재정렬이 즉시 일어나야 한다. Task 10에서 만든 재정렬 후 포커스 복원 효과와 충돌하면 안 된다.
3. **D1 유지:** 키 오류처럼 연결 오류가 아닌 코드의 우선순위는 그대로여야 한다. `token-throttled` 배너도 그대로다.
4. **proxy-cleared 되쓰기:** 정리된 설정을 저장할 때 다른 설정 값이 바뀌거나 지워지면 안 된다. 저장소 쓰기가 실패해도 앱이 메모리 전용 모드로 넘어가면 안 된다(`trySet`).
5. **상세 시트 삭제 뒤 스낵바:** 삭제 뒤 포커스가 행에 있는 동안 타이머를 멈춘다. 포커스가 다른 곳으로 가면 남은 시간부터 다시 센다. 포커스가 없으면 기존처럼 5초다.

### Task 1: 비교 화면 정리와 연결 배너 합산 (D1)

**Files:** `src/lib/ui/compare/rows.ts`, `src/lib/ui/compare/loadIssue.ts`, `src/lib/ui/compare/compareController.svelte.ts`, `src/lib/data/candleService.test.ts`, 각 테스트 파일, 스펙 §9 #9·§11

- [ ] **`priceOf`의 `rowSeries` 이중 계산:** 행마다 한 번만 계산하게 한다. 동작은 같다.
- [ ] **`ensureMetas` 주석:** "지금 종목 전체"를 종목별로 바로잡는다(`compareController.svelte.ts:214` 부근).
- [ ] **테스트 보강:**

### Task 2: 리더보드 순서 고정과 포커스 정리 (D2)

**Files:** `src/routes/Compare.svelte`, `src/lib/ui/compare/Leaderboard.svelte`, 테스트, 스펙 §7.3(또는 리더보드 절)

- [ ] **D2:**
  - Leaderboard가 목록 안 `focusin`/`focusout`을 알린다(선택 콜백 prop). `focusout`은 `relatedTarget`이 목록 밖이거나 null일 때만 해제한다.
  - Compare는 포커스가 안에 있는 동안 지금 순서를 고정 순서로 쓴다. 스크럽 고정과 같은 `sortRows(rows, frozen)`을 쓰고, 둘 중 하나라도 켜져 있으면 고정한다.
  - 고정 중 새로 생긴 종목은 끝에 붙이고, 사라진 종목은 뺀다.
  - 테스트: 포커스가 목록 안이면 값이 바뀌어도 DOM 순서가 그대로다. 값은 갱신된다. 포커스가 빠지면 재정렬된다. 고정 중 종목을 추가·삭제해도 행 수가 맞다.
- [ ] **`selectedIndex` 정렬 중복 제거:** `Compare.svelte:294-300`의 `boardOrder` 대신, 상세를 열 때와 삭제할 때 Leaderboard DOM에서 인덱스를 읽는다(예: `board.indexOf(symbol)`). Task 10의 포커스 복원 테스트가 그대로 통과해야 한다.
- [ ] **`detailRestoredFocus`가 그룹도 확인:** 복원된 그룹이 지금 보이는 그룹일 때만 그 행을 포커스한다. 테스트: 삭제 → 그룹 전환 → 되돌리기 → 다른 그룹의 같은 심볼 행에 포커스가 가지 않는다.
- [ ] **상세 시트 삭제 뒤 스낵바 (WCAG 2.2.1):**
  - 삭제 뒤 포커스를 받은 요소(다음 행, 빈 상태 추가 버튼, 또는 패널 요소)에 포커스가 머무는 동안 `holdSnackbar()` 한다.
  - 그 요소의 `focusout`에서 `releaseSnackbar()` 한다. 스낵바 버튼으로 이동하는 경우는 Snackbar 자체 hold가 이어받는다.
  - 테스트: 삭제 뒤 6초가 지나도 스낵바가 남아 있다. 포커스를 옮기면 남은 시간 뒤 사라진다. 포커스 이동이 없는 경로(마우스로 삭제해서 포커스가 body)는 기존 5초다.
- [ ] **Commit:** `fix(compare): leaderboard holds its order while keyboard focus is inside; undo stays while focus rests after a delete`
