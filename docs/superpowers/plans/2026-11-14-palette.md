# 색 팔레트 적용 (설계·계획)

`@sch0718/ui-svelte` 0.3.0의 팔레트 10종을 가즈아에 붙인다. 화면 모드(라이트·다크·시스템)와 따로 고르는 강조색 묶음이다.

- 전제: 운영자 1명, 개인·소수 사용, 무료 운영.
- 이미 있는 것으로 안 되는 이유: 지금은 강조색이 보라 하나로 고정이고, 세 앱이 같은 팔레트를 쓰기로 했다.
- 가즈아 기본은 `violet`(공용 기본과 같다). `index.html`에 `data-palette`를 적지 않는다.

## 결정

1. **저장 위치**: `Settings.palette: PaletteId`, 기본 `'violet'`. `theme`과 같은 기기 전용 설정이다.
   - `schema.ts`·`validate.ts`는 `sync/dto.ts`를 거쳐 동기화 Worker·CLI에서도 돈다. `@sch0718/ui-svelte` 진입점은 `.svelte` 컴포넌트도 다시 내보내 Worker 번들이 깨지므로, 이 두 파일은 패키지에서 `import type`만 쓴다.
   - 그래서 `schema.ts`에 `export const PALETTE_IDS = ['violet', …10종] as const satisfies readonly PaletteId[]`를 두고 기본값과 `ENUMS.palette`가 이것을 쓴다. 목록이 패키지와 같은지는 `app.test.ts`의 팔레트 시험에서 `PALETTES`와 비교해 지킨다(앱 시험은 Svelte 환경이라 런타임 import가 된다).
   - 예전 설정에 없으면 기본값, 틀린 값이면 기본값(기존 규칙 그대로).
   - 동기화: `SYNCED_SETTINGS`(허용 목록)에 넣지 않는다. 그래서 동기화·공유 문서에 들어가지 않는다.
   - `sync/forbidden.ts`에는 **넣지 않는다**. 이 목록은 동기화 Worker(`sync-worker/src/market.ts`)도 함께 써서, 바꾸면 Worker 재배포가 필요하다. 팔레트는 비밀도 아니고 허용 목록으로 이미 막힌다.
   - 내보내기·가져오기는 `sanitizeSettings`가 `DEFAULT_SETTINGS`의 키를 돌기 때문에 따로 손댈 것이 없다.
2. **적용**: `app.svelte.ts`의 `applyDisplay()`에서 `applyTheme` 다음에 `applyPalette(settings.palette)`. `src/lib/ui/theme.ts`가 `applyPalette`도 다시 내보낸다(기존 `applyTheme` 방식).
3. **등락색·차트 색**: `--up/--down`, `--s1~--s10`, `--line-bench`, `--etf-*`는 앱 `tokens.css`에 있고 팔레트 블록은 이 토큰을 건드리지 않는다. 앱 CSS에 `--accent` 덮어쓰기가 없으므로 지울 것도 없다.
   - 알려진 한계: 팔레트 20개 블록의 `bg`·`surface`·`surface2` 위 등락색(한국·글로벌 관례, 라이트·다크)을 계산하니 4.5:1 미달은 paper 라이트 `--surface2`(#f3eee3, hover 행) 위 `--up`(#d4202f) 4.485:1 하나다. 차이가 0.015이고 hover 순간에만 보여 이번에는 고치지 않는다. 값을 바꾸면 고정 시험(`tokens.test.ts`)과 대체 색(`markers.ts` 등)까지 번진다. 보고에 남기고 사람이 정한다.
4. **차트 다시 읽기**: `--accent`를 읽는 차트(EquityChart·PerfChart)는 `theme` prop이 바뀔 때만 색을 다시 읽는다. 호출하는 쪽에서 `theme`에 모드와 팔레트를 합친 문자열(`` `${theme}:${palette}` ``)을 넘긴다.
   - 고칠 곳: `src/App.svelte`(SharedView), `src/routes/Performance.svelte`(PerfChart), `src/routes/Simulate.svelte`(ValidationResult·RunPanel 두 곳).
   - 그대로 둘 곳: `Compare.svelte`(CompareChart는 `--accent`를 읽지 않는다), `HelpFigure`(`theme`으로 그림 파일을 고른다, 타입이 `Settings['theme']`), TradeChartSheet·cardImage(열 때·그릴 때 읽는다).
5. **설정 화면**: `src/routes/Settings.svelte` 「표시」 카드의 테마 행 바로 아래에 `PalettePicker`(`value={app.settings.palette}`, `onchange={(id) => app.updateSettings({ palette: id })}`). 저장 실패 처리는 `updateSettings`의 기존 경로를 따른다. `PalettePicker`는 칸 폭을 스스로 정하므로 행(`.row`) 안의 가로 배치가 아니라 카드 안 별도 블록으로 둔다(라벨은 컴포넌트 기본 「색 테마」).

6. **강조색 위 글자**: `src/sheets/TossImport.svelte`의 `.chip[aria-pressed='true']`는 배경이 `var(--accent)`인데 글자색이 `#fff`로 고정되어 있다. 다른 강조색 버튼처럼 글자색을 `var(--on-accent)`로 바꿔 팔레트에 맞는 전경색을 쓰게 한다.

## 순서

1. `package.json` `@sch0718/ui-svelte` → `0.3.0`, `pnpm install`(이 세션이 직접).
2. `schema.ts`·`validate.ts`·`theme.ts`·`app.svelte.ts` 수정.
3. 차트 호출 네 곳의 `theme` 값 수정.
4. `Settings.svelte`에 `PalettePicker`.
5. `src/sheets/TossImport.svelte`의 선택된 칩 글자색을 `var(--on-accent)`로 수정.
6. 시험 하나: `src/lib/state/app.test.ts`에 「저장된 palette가 `<html data-palette>`에 적용되고, `updateSettings({ palette })`가 저장·적용하며, 등락색 클래스(`global-colors`)는 그대로」. 틀린 값→기본값은 기존 theme 시험과 같은 경로라 따로 쓰지 않는다.

## 검증

- `pnpm --filter sync-worker check`, `pnpm --filter sync-worker test`, `pnpm --filter gazua-cli test`(공유 검증 경로가 Worker·CLI에서 그대로 도는지).
- `pnpm check`, `pnpm test`(특히 `src/lib/ui/tokens.test.ts`, `src/lib/ui/theme.test.ts`, `src/lib/state/app.test.ts`), `pnpm build`, `pnpm e2e`(a11y 포함).
- 사람이 볼 것: 운영 화면 설정 → 색 테마를 바꿔 강조색·자산 곡선 색이 바뀌고 등락색은 그대로인지.
- 사람이 볼 것: 각 팔레트의 라이트·다크 모드(특히 다크 `pastel`)에서 그룹 관리 시트의 「토스에서 가져오기」를 열어 「보유 종목」·「섹터」를 각각 선택하고, 선택된 칩의 글자색이 `--on-accent`를 따라 읽기 쉬운지.
