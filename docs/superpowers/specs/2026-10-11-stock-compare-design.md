### 1.2 전제 (대화에서 확정)

- 사용자: 본인과 지인 몇 명. 개발 지식이 있는 사용자로 보고, 안내는 설정 화면 체크리스트 + README 수준.
- 국내 주식(KOSPI·KOSDAQ·ETF·ETN)만. 미국 주식은 범위 밖.
- 회원가입·서버 계정 없음. "사용자별" = 같은 브라우저 안의 **로컬 프로필**.
- 시세 조회 전용. 주문 기능 없음.
- 데이터 공급자: **공급자 선택형**(KIS + 토스, 키 없이 보는 데모 포함).

### 1.3 범위 밖 (v1)

주문·계좌 조회, 가격 알림·푸시, 미국 주식, 기기 간 동기화, 실시간 WebSocket, 추세선 그리기 같은 차트 도구, 뉴스·공시.

## 2. 확인된 외부 제약 (2026-10-11 확인)

### 2.1 토스증권 Open API

출처: 공식 OpenAPI 스펙 `openapi.tossinvest.com/openapi-docs/latest/openapi.json`, FAQ, 실제 요청 시험.

| 항목 | 사실 | 설계 영향 |
|---|---|---|
| CORS | `OPTIONS /oauth2/token` 응답에 `Access-Control-Allow-Origin` 없음 | 브라우저에서 직접 호출 불가 → **프록시 필수** |
| 허용 IP | 필수. 미등록 IP는 403 (`ip-not-allowed`). FAQ: 모바일·서버리스처럼 IP가 바뀌면 차단 | 프록시가 **고정 IP**여야 함 → 집 PC/NAS의 Docker + Cloudflare Tunnel |
| 인증 | OAuth2 Client Credentials, 토큰 24시간, 리프레시 없음 | 토큰을 만료 시각과 함께 캐시 |
| 국내 시세 | **KRX+NXT 통합만**. 거래소 지정 파라미터·식별 필드 없음 | 토스 사용 시 거래소 모드는 `통합`만 활성 |
| 종목 정보 | `koreanMarketDetail.nxtSupported`, `krxTradingSuspended`, `nxtTradingSuspended`, `liquidationTrading`, `sharesOutstanding`, `securityType` | 종목별 거래 가능 시간 계산, 시가총액 지표 |
| 캔들 | `GET /api/v1/candles`, `interval` = `1m`·`1d`만, 최대 200개, `before` 페이지네이션, 최신순 정렬, 1분봉 `timestamp`는 **봉 종료 시각** | 1일 = 1분봉, 그 밖 = 일봉으로 충분(집계 불필요). 1분봉 시각을 봉 시작으로 정규화 |
| 1분봉 범위 | 08:01~20:00 (통합 운영 시간) | 1일 차트 X축 08:00~20:00 |
| 장 운영 | `GET /api/v1/market-calendar/KR`: 전일·당일·익일, 통합 기준 세션(프리·정규·애프터), 휴장이면 `integrated: null` | 휴장·세션 시각의 1차 출처 |
| 현재가 | `GET /api/v1/prices?symbols=` 최대 200종목 다건 | 폴링 1회로 전 종목 갱신 |
| 전체 종목 | `GET /api/v1/stocks/all?market=` (초당 1회, 하루 1회 캐시 권장) | 종목 검색용 목록 |
| 지수 | `GET /api/v1/market-indicators/{symbol}/candles` | 벤치마크 지표 |
| 호출 한도 | 그룹별 초당: `MARKET_DATA_CHART` 20, `MARKET_DATA` 10~15, `STOCK_ALL` 1. 429 + `Retry-After` | 요청 큐 + 그룹별 토큰 버킷 |
| WebSocket | 접속 시 `Authorization` 헤더 필요 | 브라우저 WebSocket은 헤더 불가 → v1 제외 |
| 키 권한 | 같은 키로 주문 가능 | 프록시에서 주문 경로 차단, 키 잠금 권장 |

### 2.2 한국투자증권(KIS) Open API

| 항목 | 사실 | 설계 영향 |
|---|---|---|
| CORS | `OPTIONS` 요청에 `501 Not Implemented` | 프록시 필수 |
| 허용 IP | 필수 아님(확인 필요) | 서버리스(Cloudflare Worker) 프록시 가능 |
| 시장 구분 | `FID_COND_MRKT_DIV_CODE`: `J`=KRX, `NX`=NXT, `UN`=통합 | 거래소 모드 4종 모두 지원 |
| 종목 정보 | `CTPF1002R` 응답에 NXT 거래 가능 여부 필드 | `nxtSupported` 매핑 |
| 토큰 | 24시간 유효, 발급 1분당 1회 제한 | 토큰 캐시 필수, 재발급 디바운스 |
| 분봉 | 당일 분봉 TR(FHKST03010200)은 **당일만**·1회 30건. 일별 분봉 TR(FHKST03010230)은 날짜 지정·1회 120건·최대 1년 보관 | 1일 차트는 일별 분봉 TR로 받음(휴장일에 캐시 없이도 최근 거래일 표시) |
| 지수 분봉 | FHKUP03500200에 날짜 파라미터 없음 | 지난 거래일의 시장 대비 초과수익(1일)은 KIS에서 비활성 |

**계획 단계에서 실제 호출로 확인할 것**: 일봉 TR의 `NX`·`UN` 지원 여부, 일별 분봉 TR에 당일 날짜를 넣었을 때 장중 진행 봉 포함 여부, 다종목 현재가 TR, 허용 IP 정책, 초당 호출 한도.

### 2.3 시장 운영 시간 (기본값 — 캘린더 API가 우선)

2026-09-14부터 **KRX 애프터마켓(16:00~20:00, 접속매매)**이 열렸고, KRX 시간외 단일가는 폐지됐다. KRX 애프터마켓에서 **ETF·ETN은 거래 대상이 아니다**. KRX 프리마켓은 2027년 말로 연기됐다.

### 3.2 공급자 인터페이스

```ts
type Venue = 'KRX' | 'NXT' | 'UNIFIED';
type VenueMode = 'AUTO' | Venue;
type RawInterval = '1m' | '1d';

interface ProviderCapabilities {
  venues: Venue[];                 // KIS: ['KRX','NXT','UNIFIED'], 토스: ['UNIFIED']
  quoteBatchSize: number;          // 다건 현재가 1회 최대 종목 수
  hasIndexCandles: boolean;        // 벤치마크 지표 가능 여부
}

interface StockMeta {
  symbol: string; name: string;
  market: 'KOSPI' | 'KOSDAQ' | 'KR_ETC';
  securityType: 'STOCK' | 'ETF' | 'ETN' | 'REIT' | 'OTHER';
  nxtSupported: boolean;
  krxSuspended: boolean; nxtSuspended: boolean | null;
  liquidationTrading: boolean;
  sharesOutstanding?: number;
}

interface Candle { t: number; o: number; h: number; l: number; c: number; v: number; value?: number }
// t = 봉 "시작" 시각(epoch ms). value = 거래대금(제공 안 하면 undefined → 지표에서 c×v로 추정 표시)

interface MarketDataProvider {
  id: 'kis' | 'toss' | 'demo';
  capabilities: ProviderCapabilities;
  authenticate(creds: Credentials, proxy: ProxyConfig): Promise<TokenInfo>;
  getUniverse(): Promise<UniverseItem[]>;
  getStockMeta(symbols: string[]): Promise<StockMeta[]>;
  getCandles(q: { symbol: string; venue: Venue; interval: RawInterval; from: Date; to: Date }): AsyncIterable<Candle[]>;
  getQuotes(symbols: string[], venue: Venue): Promise<Quote[]>;
  getCalendar(date: string): Promise<TradingDay>;
  getIndexCandles?(index: 'KOSPI' | 'KOSDAQ', interval: RawInterval, from: Date, to: Date): AsyncIterable<Candle[]>;
}
```

- 화면은 `capabilities`만 보고 동작을 바꾼다. 예를 들어 토스일 때는 거래소 세그먼트에서 `KRX`·`NXT`를 비활성으로 보여주고 이유를 툴팁으로 알려준다.
- 모든 공급자는 **같은 계약 테스트**(12절)를 통과해야 한다.

### 3.3 프록시

- 소스는 하나, 실행 환경은 둘(`proxy/src/handler.ts`). Worker 진입점과 Node 진입점(`proxy/node/server.ts`)이 같은 핸들러를 쓴다.
- 요청 형식: `GET|POST {프록시}/{provider}/{upstream path}`. 상위 호스트는 provider로 고정한다. 임의 URL 중계는 하지 않는다.
- **경로 허용 목록**: 토큰 발급, 시세, 종목, 캘린더, 지수만 허용한다. 주문·계좌·자산 경로는 `403 proxy-path-blocked`로 거절한다.
- CORS: 환경변수 `ALLOWED_ORIGINS`(예: `https://<id>.github.io`)에 있는 출처만 허용한다.
- 무단 사용 방지: 선택 환경변수 `PROXY_TOKEN`. 앱은 `X-Proxy-Token` 헤더로 보낸다.
- 요청·응답 본문이나 인증 헤더를 로그에 남기지 않는다. 상태 저장 없음.
- 배포 가이드: Worker는 `wrangler deploy` 한 줄. 토스용은 `docker compose up` + `cloudflared tunnel`. 허용 IP 등록 방법과 집 공인 IP가 바뀔 때 대처법은 README에 둔다.

### 3.4 요청 처리

- 공급자별 **토큰 버킷**(그룹별 초당 한도의 80%)과 우선순위 큐. 우선순위: 화면에 보이는 종목 현재가 > 지금 그리는 차트의 봉 > 미리 받아 두기.
- 429를 받으면 `Retry-After`만큼 쉬었다가 다시 보낸다. 5xx와 네트워크 오류는 지수 백오프로 최대 3회 재시도한다.
- 같은 요청이 동시에 여러 번 나가면 하나로 합친다.

### 3.5 빌드·배포

- `pnpm build` → `dist/`를 GitHub Actions(`actions/deploy-pages`)로 Pages에 배포한다. 해시 라우팅(`#/`)을 써서 Pages의 404 문제를 피한다.
- 폰트(Pretendard)와 차트 라이브러리는 번들에 넣는다. **런타임에 외부 스크립트를 불러오지 않는다** — 키가 저장된 페이지이므로 공급망 공격면을 줄이기 위함.
- PWA 매니페스트 + 서비스 워커(앱 셸만 캐시)로 홈 화면에 추가할 수 있게 한다.

## 4. 데이터

### 4.1 기간 → 봉 단위

| 기간 선택 | 표시 봉 | 원본 | 첫 로딩(토스 기준, 1종목) | 비고 |
|---|---|---|---|---|
| 1일 | 1분 | 1m (+ 기준 종가·RVOL용 일봉) | 약 4회 + 일봉 1회 | 오늘(장 마감 후·휴장일엔 최근 거래일) 08:00~20:00 |
| 1·2·3·4주 | 일 | 1d | 1회 | 봉이 5~20개뿐이라 점 마커를 함께 표시 |
| 1~6개월 | 일 | 1d | 1회 | |
| 1년 | 일 | 1d | 2회 | |

- 분봉은 1일 차트에서만 쓴다. 그래서 봉 집계(1분→n분, 일→주·월) 로직이 없다.
- 일봉 차트에서 주말·휴장일은 X축에서 **접어서 없앤다**(빈칸 없음). 1일 차트의 X축은 08:00~20:00 고정.
- 봉이 20개 이하(1~4주)면 선 위에 점 마커(8px)를 함께 그려 데이터 지점이 적다는 것을 드러낸다.

### 4.2 기준값

- 등락률의 기준은 **기간 시작 직전 거래일의 KRX 종가**다. 1일 차트라면 전일 종가.
- NXT 시세도 같은 기준가(KRX 전일 종가)를 쓴다. 그래서 거래소를 바꿔도 기준선 0%는 그대로다.

### 4.3 캐시

- IndexedDB `gazua-cache`
  - `candles`: 종목 **1분봉**(키 `provider|symbol|venue|1m|YYYY-MM-DD`, 당일 60초 TTL, 지난 거래일 영구)과 **지수 일봉**(지난 날짜 영구, 수정 대상 아님).
  - `universe`: 전체 종목 목록, 하루 1회 갱신. 공개 정보라 프로필끼리 공유한다.
  - `meta`: 종목 메타, 장 시작 전 1회 갱신.
- **종목 일봉(수정주가)은 저장하지 않는다.** 차트를 그릴 때 지표용 선행 구간부터 오늘까지(`lookbackFrom..오늘`)를 한 번에 받아 메모리에서만 재사용한다(장중 60초, 장 밖 10분). 종목당 1~3회 호출이라 비용이 작다. 기준 종가·선행 구간·오늘 봉이 늘 같은 응답에서 나오므로, 액면분할 등으로 과거 수정주가가 바뀌어도 이전 값과 섞이지 않는다. 1일 차트의 기준 종가와 RVOL 평균도 이 일봉에서 읽는다.
- 1분봉은 수정되지 않은 원래 가격이다. **지난 거래일**을 보여주는 1일 차트에서 일봉(수정주가)과 어긋나면, 그날 일봉 종가와 같은 정의의 KRX 1분봉 종가(기본은 정규장 종가 봉, 일봉에 애프터마켓이 포함되는지는 실연결 점검으로 확정)의 비율로 기준 종가와 RVOL 평균을 1분봉 기준으로 환산한다. 오늘 차트, 비율 1% 이내, NXT·통합처럼 비교할 봉이 없는 경우에는 환산하지 않는다.
- 갱신에 실패하면 그 종목의 마지막 성공 결과(기준가·봉·가격·지표 한 묶음)를 통째로 보여주고 리더보드 행과 종목 상세에 `17:20 기준`처럼 표시한다. 새 봉이나 5초 시세를 이전 결과에 덧붙이지 않는다. 마지막 성공 결과는 이 탭의 메모리에만 있으므로, 새로고침 뒤 연결이 안 되면 그 종목에 오류를 표시한다.
- 용량이 넘치면 가장 오래 안 쓴 종목부터 종목 단위로 지운다. 설정 화면에 사용량과 `캐시 비우기`를 둔다.

### 4.4 갱신

- 현재 시각이 어느 거래 세션 안이면 5초마다 현재가를 다건 조회한다. 지금 차트의 마지막 봉은 1분마다 다시 받는다.
- 세션 밖이거나 탭이 백그라운드(`visibilitychange`)면 멈춘다. 다시 돌아오면 즉시 1회 갱신한다.
- 툴바에 `● 실시간 · 17:42:05` 또는 `◌ 17:20 기준 (장 마감)`을 표시한다.

## 5. 거래소(KRX/NXT)와 거래 가능 시간

### 5.1 거래소 모드

| 모드 | 의미 | 공급자 |
|---|---|---|
| **자동**(기본) | 세션마다 거래소를 골라 이어 붙임 (5.2) | KIS. 토스는 `통합`으로 대체 |
| KRX | KRX 체결만 | KIS |
| NXT | NXT 체결만. NXT 미지원 종목은 KRX로 대체하고 배지 표시 | KIS |
| 통합 | KRX+NXT 합산 | KIS, 토스 |

### 5.2 자동 규칙

**불변 원칙: KRX 우선.** 그 시각에 KRX가 그 종목을 접속매매로 거래하면 KRX, 그렇지 않을 때만 NXT, 둘 다 아니면 거래 불가. 세션 시각이 바뀌어도(예: KRX 프리마켓 도입) 이 원칙은 바꾸지 않고, 세션 데이터만 갱신하면 결과가 따라 바뀐다.

```
autoVenue(t, stock) = krxTrades(t, stock) ? 'KRX' : nxtTrades(t, stock) ? 'NXT' : null
```

2026-10-11 세션 기준 결과:

| 구간 (KST) | NXT 지원 종목 | NXT 미지원 일반 주식 | NXT 미지원 ETF·ETN |
|---|---|---|---|
| 08:00–08:50 프리 | **NXT** | 거래 불가 | 거래 불가 |
| 08:50–09:00 시가 단일가 | KRX (체결 없음, 단일가 음영) | KRX 단일가 | KRX 단일가 |
| 09:00–15:30 정규 | **KRX** | KRX | KRX |
| 15:30–16:00 | **NXT** (KRX 접속매매 없음) | 거래 불가 | 거래 불가 |
| 16:00–20:00 애프터 | **KRX 애프터** (NXT 지원 ETF·ETN이면 NXT) | **KRX 애프터** | 거래 불가 |
| 20:00–08:00, 휴장 | 마지막 값 유지 | 〃 | 〃 |

- 1일 차트: 위 규칙으로 구간마다 다른 거래소 데이터를 이어 붙인다. 차트 위 띠에 `NXT 프리 │ KRX 정규 │ NXT │ KRX 애프터`처럼 구간 라벨을 단다.
- 주·월·년 차트(일봉): **KRX 일봉**을 쓴다. KRX 일봉이 애프터마켓 체결을 포함하는지는 계획 단계에서 확인한다.
- 머리말 현재가: 지금 시각이 속한 구간의 거래소 가격. 종목 상세에서는 KRX·NXT 가격을 나란히 보여준다.
- 토스: 자동 대신 `통합`이 기본이고, 거래소 세그먼트 옆에 `토스는 통합 시세만 제공해요` 안내를 둔다.

### 5.3 종목별 거래 가능 구간 계산

`market/tradable.ts`

```
tradableIntervals(day: TradingDay, meta: StockMeta, venueMode, sessionsConfig) → Interval[]
```

- 입력: 당일 세션 시각(캘린더 API → 없으면 config), `nxtSupported`, `securityType`, 거래정지·정리매매 플래그, 선택한 거래소 모드
- 출력: `[{start, end, venue: 'KRX'|'NXT'|'UNIFIED', kind: 'continuous'|'auction'}]`. 이 구간들의 여집합이 그날의 **거래 불가 구간**이다.
- 거래정지(`krxSuspended`/`nxtSuspended`)면 해당 거래소 구간을 통째로 빼고 사유 배지를 단다.

### 5.4 차트에서 거래 불가 시간 표현 (세 겹)

아래 세 겹은 **1일(분봉) 차트**에 적용한다. 일봉 차트에서는 휴장일을 축에서 빼고, 기간 중 거래정지일만 사선 해칭 세로 띠와 `거래정지` 라벨로 표시한다.

1. **세션 배경**: 프리·애프터는 옅은 음영, 단일가 구간은 사선 패턴, 정규장은 음영 없음. 맨 위에 구간 라벨.
2. **세션 레인**: 차트 바로 아래, 종목마다 높이 6px 막대 한 줄(시리즈 색 점 + 막대). 거래 가능 = 채움, 거래 불가 = 사선 해칭. 막대 안에 거래소 첫 글자(`K`/`N`)를 표시하고, X축을 차트와 공유한다. 종목 수만큼 쌓여 "누가 언제 거래되는지"를 한눈에 보여준다.
3. **선 표현**: 거래 불가 구간은 마지막 값에서 **점선·40% 불투명도**로 수평 연결한다. 이 구간에는 크로스헤어 값 옆에 `거래 없음`을 표시한다.

차트 하단 범례에 `▧ 거래 불가  ▨ 단일가` 설명을 늘 둔다. 색만으로 의미를 전하지 않는다.

## 6. 비교 지표

원칙: 모든 지표는 **Y축 하나**(서로 다른 단위를 한 차트에 섞지 않음). 지표를 바꿔도 종목 색은 바뀌지 않는다.

| # | 지표 | 정의 | 무엇을 비교하나 | 기간 | v1 |
|---|---|---|---|---|---|
| 1 | **등락률** (기본) | `P_t / P_base − 1` | 같은 출발선에서 누가 더 올랐나 | 전체 | ✅ |
| 2 | 고점 대비 하락률 | `P_t / max(P_≤t) − 1` (기간 내 고점 기준) | 하락 방어력, 낙폭 | 전체 | ✅ |
| 3 | 시장 대비 초과수익 | `등락률_종목 − 등락률_지수`. 지수는 종목 시장에 따라 KOSPI/KOSDAQ 자동, 수동 변경 가능 | 시장보다 잘했나 | 전체 (지수 캔들 지원 시) | ✅ |
| 4 | 상대 거래량 (RVOL) | 일봉: `V_t / 직전 20일 평균`. 1일: `당일 누적 V / 직전 20일 평균 일 거래량` (장중엔 0에서 커지는 진행률로 읽힘) | 평소보다 관심이 쏠렸나 (1.0 기준선) | 전체 | ✅ |
| 5 | 시가총액 | `sharesOutstanding × P_t` (조 원) | 덩치 변화 | 전체 (발행주식수 제공 시) | ✅ |
| 6 | 변동성 | 20일 일간 수익률 표준편차 × √252 | 위험도 | 1개월 이상 | v1.1 |
| 7 | RSI(14) | Wilder 방식 | 과열·침체 비교 (0–100 공통 척도) | 1개월 이상 | v1.1 |

- 지표 6·7과 RVOL 일봉은 앞쪽 20일치 데이터가 더 필요하다. 이건 앱이 알아서 더 받는다.
- 가격(원) 자체는 비교 지표에서 뺐다. 종목마다 단위가 달라 한 축에 놓으면 오해를 낳기 때문이다. 원 단위 가격은 리더보드와 상세에서 보여준다.
- 거래대금을 주지 않는 공급자는 `c×v`로 추정하고 `≈` 표시를 붙인다.

## 7. 화면 설계

시각 목업: [`docs/design/2026-10-11-mockups.html`](../../design/2026-10-11-mockups.html)

### 7.1 정보 구조

```
[프로필 선택] (프로필이 2개 이상일 때만)
   └ 비교 (홈) ─┬ 종목 추가 시트
                ├ 지표 선택 시트
                ├ 종목 상세 시트
                └ 그룹 관리 시트
   └ 설정 ─┬ 데이터 소스 (공급자·프록시·키·연결 진단)
           ├ 키 보호 (잠금)
           ├ 표시 (테마·상승/하락 색 관례)
           ├ 데이터 (내보내기·가져오기·캐시)
           └ 프로필
[온보딩] 첫 실행 시: 공급자 → 프록시 → 키 → 진단 → 완료 / "데모로 둘러보기"
```

이동은 2곳(비교·설정)뿐이라 하단 탭바를 두지 않는다. 설정은 우상단 아이콘으로 연다. 화면 대부분은 **바텀 시트**로 처리해 맥락을 유지한다.

### 7.2 비교(홈) — 모바일

위에서 아래 순서:

1. **앱 바**: 그룹 탭(가로 스크롤, `반도체 · 2차전지 · +`) / 우측에 상태 칩 + 설정 아이콘
   - 상태 칩: `● KRX 애프터 17:42` (세션명 + 지금 쓰는 거래소 + 시각). 누르면 오늘 세션 시간표 팝오버
2. **헤드라인**: 지표 이름 + 크로스헤어가 가리키는 시각. 스크럽하지 않을 때는 `오늘 · 등락률`. 스크럽하면 `14:32 · 등락률`
3. **차트**: 화면 높이의 약 45% (최소 260px). 세션 배경·구간 라벨·0% 기준선. 끝점에 종목 짧은 이름 직접 라벨(4종목 이하일 때)
4. **세션 레인**: 종목 수만큼 6px 막대 (5.4)
5. **컨트롤 줄**:
   - 기간: `일 │ 주 │ 월 │ 년` 세그먼트. 주·월을 고르면 아래에 `1 2 3 4` / `1 2 3 4 5 6` 칩이 펼쳐진다
   - 지표 칩 `등락률 ▾` → 지표 시트
   - 거래소 세그먼트 `자동 │ KRX │ NXT │ 통합` (자동일 때 지금 고른 거래소를 작은 글씨로)
6. **리더보드**(범례 겸용): 지표 값 기준 정렬. 행 = 색 점 + 종목명·코드 + 배지(`NXT`·`거래정지`·`ETF`) + 지표 값(▲▼ + 색) + 현재가
   - 탭 → 종목 상세 시트. 색 점 탭 → 차트에서 숨기기·보이기(행은 흐리게)
   - 길게 누르기 → 드래그로 순서 변경
   - 스크럽 중에는 그 시각 값으로 바뀌고 정렬은 고정(값이 튀며 행이 움직이지 않게)
7. **리더보드 머리줄** `등락률 순 · 4/8` + `＋ 종목 추가` 버튼 → 종목 추가 시트 (플로팅 버튼은 리더보드 값을 가려서 쓰지 않음)

빈 상태: "비교할 종목을 추가해 보세요" + `＋ 종목 추가` + `예시 그룹 불러오기(반도체 대형주 4종)`.

### 7.3 시트들

| 시트 | 구성 | 핵심 상호작용 |
|---|---|---|
| 종목 추가 | 검색창(자동 포커스, **초성 검색**: `ㅅㅅㅈㅈ`→삼성전자), 최근 추가, 결과 행(이름·코드·시장 배지·NXT 배지·`추가됨` 체크) | 여러 개 연속 추가, 하단 `n개 추가됨 · 완료`. 그룹당 8종목 한도에 닿으면 버튼 비활성 + "한 차트에 8개까지 비교할 수 있어요" |
| 지표 선택 | 지표별 행: 이름, 한 줄 설명, 미니 예시 그래프, 사용 불가 사유(예: "1개월 이상에서 볼 수 있어요") | 선택 즉시 반영, 시트 닫힘 |
| 종목 상세 | 큰 현재가(지금 거래소) + `KRX 71,200 · NXT 71,350` 비교, 오늘 세션 타임라인(5.3 결과), 상태(거래정지·정리매매·투자유의), 그룹 이동·삭제 | 삭제 → 스낵바 `삭제했어요 · 되돌리기` (5초). 되돌리기는 **그 시점의 그룹** 기준: 8종목이면 `그룹이 가득 차서 되돌릴 수 없어요`, 원래 색 슬롯이 쓰이고 있으면 비어 있는 슬롯으로 복원 |
| 그룹 관리 | 그룹 목록(이름 변경·순서·삭제) | 삭제는 확인 대화상자(종목 수 표시) + 되돌리기 |

### 7.4 설정

- **데이터 소스**: 공급자 라디오 카드(KIS / 토스 / 데모). 카드마다 "되는 것·안 되는 것"을 한 줄씩(예: 토스 — `KRX·NXT 구분 불가 · 고정 IP 프록시 필요`)
  - 프록시 URL, 프록시 토큰(선택), 키 입력(마스킹, 붙여넣기 시 앞뒤 공백 자동 제거)
  - **연결 진단** 버튼 → 4단계 체크리스트가 차례로 진행: `① 프록시 응답` → `② CORS 허용` → `③ 토큰 발급` → `④ 시세 조회(삼성전자)`. 실패한 단계에 원인과 해결책(예: `403 ip-not-allowed → 토스 WTS > 설정 > Open API > 허용 IP에 프록시 공인 IP 등록`)
- **키 보호**: `암호로 잠그기` 토글. 켜면 앱을 열 때마다 암호를 입력한다(10.2). `이 기기에서 키 삭제`
- **표시**: 테마(시스템·라이트·다크), 상승/하락 색(한국식 빨강▲/파랑▼ · 글로벌 초록▲/빨강▼)
- **데이터**: 관심종목 JSON 내보내기·가져오기(키 제외가 기본, 포함하려면 별도 체크 + 경고), 캐시 사용량·비우기
- **프로필**: 추가·이름 변경·삭제·전환

### 7.5 온보딩 (첫 실행)

1. 환영: 한 줄 소개 + `내 API로 시작` / `데모로 둘러보기`
2. 공급자 선택 (설정의 카드와 같은 컴포넌트)
3. 프록시: URL 입력 + `배포 방법 보기`(README 해당 절로 연결)
4. 키 입력
5. 연결 진단 (7.4와 같은 컴포넌트) → 성공하면 `예시 그룹으로 시작` / `빈 그룹으로 시작`

중간에 그만두면 데모 모드로 들어가고, 상단 배너 `데모 데이터를 보고 있어요 · 연결하기`를 띄운다.

## 10. 저장과 보안

### 10.1 저장 스키마 (localStorage, 접두사 `gazua:v1:`)

```
meta                    { schemaVersion, activeProfileId, profiles: [{ id, name, createdAt }] }
p:{id}:settings         { provider, proxyUrl, venueMode, period: { unit: 'D'|'W'|'M'|'Y', n }, metric,
                          benchmark, theme, colorConvention, lastGroupId }
p:{id}:watchlists       { groups: [{ id, name, items: [{ symbol, colorSlot, hidden, addedAt }] }] }
p:{id}:secrets          평문: { kis?: { appKey, appSecret }, toss?: { clientId, clientSecret }, proxyToken? }
                        잠금: { enc: base64, iv, salt, kdf: 'PBKDF2-SHA256', iter: 310000 }
p:{id}:token            { provider, accessToken, expiresAt }   // 잠금 모드면 메모리에만
```

- 스키마를 바꿀 때는 `schemaVersion` 기반 마이그레이션 함수를 거친다.
- 저장소 접근 실패(사파리 프라이빗 모드 등)에 대비해 모든 읽기·쓰기를 try/catch로 감싸고, 실패하면 메모리 저장으로 동작하면서 배너로 알린다.

### 10.2 키 보호

- localStorage는 같은 브라우저를 쓰는 누구나 읽을 수 있다. **프로필은 편의 기능이지 보안 경계가 아님**을 설정 화면에 명시한다.
- 선택 기능 `암호로 잠그기`: PBKDF2(310,000회) → AES-GCM으로 `secrets`를 암호화한다. 복호화한 키와 토큰은 **메모리에만** 두고, 탭을 닫으면 다시 잠긴다.
- 토스 키는 주문 권한이 있으므로 토스를 고르면 잠금을 권한다(기본값 켬, 끌 수 있음).
- 프록시가 주문·계좌 경로를 막는다(3.3). 그래서 이 앱을 거쳐서는 키를 주문에 쓸 수 없다.
- CSP(meta): `default-src 'self'; script-src 'self'; connect-src 'self' https:; img-src 'self' data:; style-src 'self' 'unsafe-inline'`
- 키 값은 로그·오류 리포트·URL에 절대 넣지 않는다.
