## 1. 목표와 범위

### 1.1 목적

사용자가 **자기 투자 방식이 괜찮은지 확인**하는 기능이다. 평소 쓰는 매수·매도 규칙을 과거 일봉에 적용해 결과를 내고, 아무것도 하지 않았을 때(보유)와 시장과 비교한다.

성공 기준: 규칙 하나를 정해 실행하면, "같은 종목을 그냥 들고 있었을 때·시장 지수·지정 ETF보다 나았나"를 숫자와 곡선으로 바로 읽을 수 있다.

### 1.2 대화에서 확정한 것 (2026-10-12)

| 항목 | 결정 |
|---|---|
| 매수 방식 | 매수도 규칙으로 정한다 |
| 사용자의 기본 매수 패턴 | 하락이 이어지다 저점을 찍고 반등할 때, **N거래일 연속 반등**하거나 **전 고점을 돌파**하면 산다 (둘 중 하나, OR) |
| 전 고점 | A(하락 시작 전 고점)·B(하락 중 마지막 반등 고점) 중 규칙마다 고른다 |
| 연속 반등 | 종가가 전일 종가보다 높은 날이 연속 N거래일 |
| 하락 판단 | 고점 대비 N% 하락 / N거래일 신고가 없음 — 각각 켜고 끔. 기본 `10% 하락`만 켬 |
| 고점·저점 기준 | 종가 |
| 추가 규칙 재료 | 이동평균(돌파·골든크로스·필터), 분할 매수, 분할 매도 |
| 자금 | 공용 자금(계좌 하나). 같은 날 신호는 그룹 순서대로, 현금 부족이면 건너뛰고 기록 |
| 손절 기준 | 규칙마다 고른다: 분할 완료 후 평균 단가 / 항상 평균 단가 / 첫 매수가 |
| 분할 매도 | 익절 최대 3단계, 손절은 남은 수량 전부, 1단계 익절 뒤 손절선 `그대로`·`본전` 선택 |
| 재매수 | 전량 매도 뒤 **새 하락 패턴**이 생겨야 다시 산다 |
| 체결 가정 | 신호 다음 날 시가 매수, 하루 가격 경로 시가→저가→고가→종가, 손절 우선 (5장) |
| 비교 기준 | 같은 종목 균등 보유, 시장 지수(KOSPI·KOSDAQ), 지정 종목 하나 보유(예: ETF) |
| 구조 | 브라우저 안에서 받고 계산(접근 A). 서버·프록시 변경 없음 |

### 1.3 범위 밖 (이번 단계)

- **규칙으로 종목 고르기**(스크리닝): 전 종목 일봉이 필요하다. 매일 전 종목 일봉을 미리 수집해 정적 파일로 배포하는 별도 프로젝트(접근 B)로 분리한다. 엔진은 "종목 목록 + 일봉"만 받으므로 그대로 이어 쓴다.
- 분봉 시뮬레이션, 배당·세후 수익률, 공매도·레버리지, 실시간 신호 알림, 주문.
- 결과 저장(수정주가가 바뀔 수 있어 다시 실행한다).

## 2. 구조

```
[전략 편집] ──저장──▶ localStorage  p:<profile>:strategies
     │ 실행
     ▼
[데이터 수집 loadSimData] ──getCandles/getIndexCandles(우선순위 2)──▶ 공급자 → 프록시
     │ SimInput (종목별 일봉 + 메타 + 거래일 축 + 비교 기준 일봉)
     ▼
[엔진 simulate()]  순수 함수, 네트워크·화면 모름
     │ SimResult
     ▼
[결과 화면] 요약 · 자산 곡선 · 비교 기준 · 거래 내역 · 거래 차트 시트
```

- **엔진은 메인 스레드에서 돈다.** 8종목 × 10년 ≈ 2만 봉이고 하루마다 종목당 상수 시간이라 수 ms 수준이다. 설계 대화에서는 Web Worker를 말했지만 계산량이 작아 뺐다(YAGNI). 엔진이 순수 함수라 느려지면 Worker로 옮기기만 하면 된다.
- 공급자 계약(`MarketDataProvider`)은 그대로 쓴다. 바꾸는 것은 `CandleQuery`·`getIndexCandles`에 **선택적 우선순위**를 더하는 것뿐이다(6.3).

## 3. 전략 모델

모든 숫자는 사용자가 바꿀 수 있다. 괄호는 기본값.

```ts
interface Strategy {
  id: string;
  name: string;                      // 30자 이내
  updatedAt: number;
  universe: { kind: 'group'; groupId: string } | { kind: 'symbols'; symbols: string[] }; // 최대 8종목
  period: { from: string; to: string };  // KST YYYY-MM-DD, 양끝 포함
  capital: { initial: number; perBuyPct: number };          // (10_000_000, 10)
  entry: {
    decline: {
      dropPct: { on: boolean; value: number };              // (켬, 10)
      days: { on: boolean; value: number };                 // (끔, 10)
    };
    triggers: {
      reboundDays: { on: boolean; value: number };          // (켬, 3)
      breakout: { on: boolean; level: 'A' | 'B' };          // (켬, 'B')
      maCross: { on: boolean; period: number };             // (끔, 20)
      goldenCross: { on: boolean; short: number; long: number }; // (끔, 5, 20)
    };
    filter: { aboveMa: { on: boolean; period: number } };   // (끔, 60)
  };
  scaleIn: { on: boolean; stepPct: number; maxAdds: number }; // (끔, 3, 2)
  exit: {
    takeProfit: { pct: number; sellPct: number }[];          // 1~3단계, 마지막 단계 sellPct = 100. 기본 [{15, 100}]
    stopLoss: { pct: number; basis: 'avgAfterScaleIn' | 'avgAlways' | 'firstBuy' }; // (5, 'avgAfterScaleIn')
    afterFirstTake: 'keep' | 'breakeven';                    // ('keep')
  };
  benchmarks: { index: 'KOSPI' | 'KOSDAQ'; symbol: string | null }; // ('KOSPI', '069500')
  costs: { feePct: number };                                 // (0.015) 매수·매도 각각
}
```

- 그룹을 고르면 실행 시점의 그룹 종목·순서를 쓴다. 그룹이 지워졌으면 편집 화면에서 다시 고르게 한다.
- `takeProfit`의 `sellPct`는 **처음 보유 수량**(그 포지션에서 산 총수량) 대비 비율이다. 마지막 단계는 항상 "나머지 전부"(100으로 저장).
- 기본 기간은 실행일 기준 최근 3년(`to` = 어제, `from` = 3년 전 같은 날).

### 3.1 규칙 점검 (편집 화면 경고. "실행을 막는다"고 적은 것만 막고 나머지는 경고만)

| 조건 | 경고 문구 |
|---|---|
| 트리거가 하나도 켜져 있지 않음 | `사는 신호가 하나도 켜져 있지 않아요. ②에서 하나 이상 켜 주세요` (실행을 막는다) |
| 골든크로스가 켜져 있고 `short ≥ long` | `짧은 이동평균 기간이 긴 이동평균보다 짧아야 해요`(편집 칸 이름 `짧은 이동평균`·`긴 이동평균`과 같은 말) |
| 종목이 0개(그룹이 비었거나 지워짐) | `종목을 하나 이상 골라 주세요` (실행을 막는다) |
| `from ≥ to` | `시작일이 종료일보다 앞이어야 해요` (실행을 막는다) |
| `avgAlways`이고 분할 매수 켬, `stepPct ≥ stopLoss.pct` | `추가 매수보다 손절이 먼저 일어나요. 추가 매수 간격을 손절폭보다 작게 해 주세요` |
| 익절 단계 % 가 오름차순이 아님 | `익절 단계는 낮은 %부터 차례로 적어 주세요` (이것도 실행을 막는다) |
| 마지막 단계를 뺀 익절 단계들의 `sellPct` 합 ≥ 100 | `마지막 단계 전에 모두 팔려서 뒤 단계가 실행되지 않아요` |
| `perBuyPct × (1 + (분할 매수 켬 ? maxAdds : 0)) × 종목 수 > 100` | `모든 종목이 한꺼번에 사면 현금이 모자라요. 신호 일부를 건너뛸 수 있어요` |
| 기간이 30거래일 미만 | `기간이 짧아 결과를 믿기 어려워요` |

### 3.2 저장

- 키 `gazua:v1:p:<profileId>:strategies` → `{ strategies: Strategy[] }`. 프로필당 최대 20개.
- 읽을 때 `sanitizeStrategies`로 검증한다. 깨진 전략 하나는 빼고 저장소 배너로 알린다(기존 `reportCorrupt` 방식). 빠진 필드는 기본값.
- 내보내기·가져오기 파일에 `strategies`를 선택 필드로 넣는다. `schemaVersion`은 1 그대로(없으면 빈 목록).
- 프로필 삭제 때 함께 지운다.

## 4. 패턴 인식

종목마다 **어제까지의 상태**와 **오늘 종가**로 신호를 판단하고, 그다음 오늘 종가로 상태를 갱신한다. 미래 봉은 쓰지 않는다.

상태(종가 기준, 인덱스는 그 종목 봉 배열의 위치):

- `A`, `aIdx`: 마지막 리셋 이후 최고 종가와 그 위치. 오늘 종가 > A면 A·aIdx를 오늘로 바꾸고 L·B를 지운다.
- `L`, `lIdx`: aIdx 뒤의 최저 종가와 그 위치(같은 값이면 나중 것).
- `B`: aIdx < i < lIdx인 i 중 `c[i] > c[i-1]` 이고 `c[i] > c[i+1]`인 마지막 i의 종가. 없으면 B = A.
- 리셋: 시작(워밍업 첫 봉)과 **전량 매도한 날**. 리셋하면 A = 그날 종가, aIdx = 그날, L·B 없음.

하락 조건(켜진 것을 모두 만족, 둘 다 꺼져 있으면 항상 만족). L이 없으면 불만족.

- `dropPct`: `(A − L) / A × 100 ≥ value`
- `days`: `t − aIdx ≥ value` (A 이후 거래일 수)

트리거(켜진 것 중 하나라도 만족, 하락 조건을 함께 만족해야 함). 오늘 = t.

- `reboundDays`: lIdx = t − k (k ≥ value)이고 lIdx+1..t의 모든 날 종가가 전일보다 높다. 즉 저점 다음 날부터 오늘까지 끊김 없이 올랐다.
- `breakout`: X = A 또는 B, `c[t-1] ≤ X < c[t]`.
- `maCross`: `c[t-1] ≤ MA(t-1)` 이고 `c[t] > MA(t)`.
- `goldenCross`: `MAs(t-1) ≤ MAl(t-1)` 이고 `MAs(t) > MAl(t)`.
- 이동평균은 종가 단순 이동평균. 값이 모자라면(봉 수 < 기간) 그 트리거·필터는 불만족.

필터: `aboveMa`가 켜져 있으면 `c[t] > MA(t)`여야 한다.

신호는 **보유하지 않은 종목**에서만 판단한다. 신호가 나면 다음 거래일 시가 매수를 예약하고, 그때의 `{A, B, L, aIdx의 날짜, lIdx의 날짜}`를 함께 남긴다(거래 차트 시트에 표시).

- 하락 조건이 꺼져 있지 않은 한, `reboundDays`는 L이 정해진 뒤에만 의미가 있다. L은 "A 이후 최저"라 반등 첫날에도 이미 정해져 있다.
- 브레이크아웃으로 A를 넘긴 날은 신호 판단 뒤 상태 갱신에서 새 A가 된다.

## 5. 엔진과 체결

### 5.1 입력과 출력

```ts
interface SimInput {
  strategy: Strategy;
  days: string[];                                   // 거래일 축(시작~끝), 오름차순
  stocks: { symbol: string; name: string; market: 'KOSPI' | 'KOSDAQ' | 'KR_ETC'; isEtf: boolean; candles: Candle[] }[]; // 그룹 순서, 워밍업 포함
  index: { id: 'KOSPI' | 'KOSDAQ'; candles: Candle[] } | null;
  benchmarkStock: { symbol: string; name: string; isEtf: boolean; market: 'KOSPI' | 'KOSDAQ' | 'KR_ETC'; candles: Candle[] } | null;
}
function simulate(input: SimInput): SimResult;
```

`days` 밖의 봉은 워밍업(패턴·이동평균 계산)에만 쓰고 거래하지 않는다.

### 5.2 하루 처리 순서

하루 가격은 **시가 → 저가 → 고가 → 종가** 순으로 움직였다고 가정한다(손실 쪽 사건을 먼저 처리하는 보수적 가정).

1. **시가**: 예약된 매수를 그룹 순서대로 시가에 체결한다. 그날 봉이 없는 종목은 예약을 취소하고 `건너뜀(거래 없음)`으로 기록한다.
2. **장중 경로**: 보유 종목마다 가격 커서를 시가에 두고, 세 구간을 차례로 지나간다.
   - ① 시가 → 저가 (내려감) ② 저가 → 고가 (올라감) ③ 고가 → 종가 (내려감)
   - 같은 날 시가에 산 종목도 이 경로에 참여한다.
3. **종가**: 보유하지 않은 종목의 신호를 판단해 다음 날 매수를 예약하고, 패턴 상태를 갱신한다. 자산 = 현금 + Σ(보유 수량 × 종가)를 기록한다. 그날 봉이 없는 종목은 마지막 종가로 평가한다.

**장중 경로 규칙.** 이벤트 가격은 손절선, 다음 추가 매수 가격, 남은 익절 단계 가격이다. 이벤트마다 포지션이 바뀌므로(평균 단가·손절선·남은 수량) 하나를 처리할 때마다 이벤트 가격을 다시 계산한다.

1. **이미 지나친 가격은 커서 가격에 체결한다.** 손절선 ≥ 커서, 추가 매수 가격 ≥ 커서, 익절 가격 ≤ 커서인 것이 있으면 그 이벤트를 **커서 가격**에 처리한다. 여럿이면 손절 → 추가 매수 → 익절(낮은 단계부터) 순서다. 손절선이 커서와 같으면 `kind`는 `stop`, 커서보다 높을 때만 `gapStop`이다.
   - 시가의 갭이 이 규칙에 해당한다. 예: 시가가 손절선 아래면 시가에 손절한다.
   - 추가 매수로 새 손절선이 커서보다 위에 생겨도 이 규칙에 해당한다. 이미 지나간 손절선 가격이 아니라 지금 가격에 판다.
2. **내려가는 구간**에서는 커서와 구간 끝 사이에 있는 손절선·추가 매수 가격 중 **가장 높은 것**까지 커서를 옮기고, 그 가격에 처리한다. 같은 가격이면 손절이 먼저다.
3. **올라가는 구간**에서는 커서와 구간 끝 사이에 있는 익절 가격 중 **가장 낮은 것**까지 커서를 옮기고, 그 가격에 처리한다.
4. 처리할 것이 없으면 커서를 구간 끝으로 옮기고 다음 구간으로 간다. 전량 매도되면 그날 그 종목의 경로는 끝난다.
5. 추가 매수가 현금 부족으로 건너뛰어지면, 그 가격은 **그날 남은 경로에서 제외**하고 계속 진행한다. 아래에 있는 손절선은 그대로 처리된다.

예시(수수료·세금 0):

| 상황 | 봉 (시가/저가/고가/종가) | 결과 |
|---|---|---|
| 10주 @100, 현금 0, 추가 간격 3%, 항상 평단 손절 5% | 100/90/105/100 | 추가 매수 97은 현금 부족으로 제외, 손절 95에 10주 매도 → 950 |
| 초기 1,000·회당 50%, 5주 @100, 추가 간격 50%·최대 1회, 분할 완료 후 손절 5% | 100/40/100/40 | 50에 10주 추가(평단 66.67), 새 손절선 63.33이 커서 50보다 위 → 50에 15주 매도 → 750 |
| 10주 @100, 손절 95, 익절 +10% 50%, 익절 뒤 본전 | 100/98/112/99 | ② 구간에서 110에 5주 익절, 손절선이 100으로 올라감 → ③ 구간에서 100에 5주 손절, 현금 1,050 |

### 5.3 수량·가격 규칙

- **1회 매수 금액** = `initial × perBuyPct / 100` (첫 매수와 추가 매수 모두 같음).
- 수량 = `floor(1회 금액 / (가격 × (1 + 수수료율)))`. 0주면 `건너뜀(1주가 1회 금액보다 비쌈)`.
- 현금 < 수량 × 가격 × (1 + 수수료율)이면 `건너뜀(현금 부족)`. 추가 매수 가격이 현금 부족으로 건너뛰면 그 가격은 살아 있고, 기록은 가격당 한 번만 남긴다.
- **추가 매수 가격** = 직전 매수가 × (1 − stepPct/100). 최대 `maxAdds`회. 한 번이라도 일부를 팔았으면 더 이상 추가 매수하지 않는다.
- **평균 단가** = 산 금액 합(수수료 제외) / 산 수량 합. 부분 매도해도 바뀌지 않는다.
- **손절선**
  - `avgAfterScaleIn`: 분할 매수가 끝난 뒤(추가 매수를 maxAdds회 했거나 분할 매수가 꺼져 있거나 일부를 팔았음)에만 `평균 단가 × (1 − pct/100)`. 그 전에는 손절 없음.
  - `avgAlways`: 항상 `평균 단가 × (1 − pct/100)`.
  - `firstBuy`: `첫 매수가 × (1 − pct/100)`.
  - 1단계 익절 뒤 `afterFirstTake = 'breakeven'`이면 손절선 = max(위 손절선, 평균 단가).
- **익절 단계 가격** = 평균 단가 × (1 + pct/100). 단계 k의 매도 수량 = `floor(처음 보유 수량 × sellPct/100)`. 남은 수량보다 많으면 남은 수량. 마지막 단계는 남은 수량 전부.
- 체결 가격은 원 단위 실수 그대로 쓴다(호가 단위 반올림 안 함).

### 5.4 비용

- 수수료: 매수·매도 금액 × `feePct`% (기본 0.015%).
- 매도 세금(증권거래세 + 농어촌특별세): **양도일 = 결제일(체결일 + 2거래일)**과 시장으로 아래 표에서 고른다(증권거래세법 시행령 제2조). 결제일이 거래일 축 끝을 넘으면 축 마지막 날에서 남은 칸만큼 평일을 더해 근사한다. 이때 토·일과 KRX가 해마다 쉬는 12-31(연말 휴장일)·01-01(신정)은 건너뛴다(그 밖의 공휴일은 모른다). 예: 축이 2025-12-29로 끝나면 그날 체결의 결제일은 2026-01-02. **ETF는 0**. `KR_ETC`(ETN 등)는 0.

| 결제일(체결일+2거래일) | KOSPI | KOSDAQ | 근거 |
|---|---|---|---|
| ~ 2019-06-02 | 0.30% | 0.30% | 2026-10-13 법령 연혁으로 확인 |
| 2019-06-03 ~ 2020-12-31 | 0.25% | 0.25% | 2026-10-13 법령 연혁으로 확인 |
| 2021-01-01 ~ 2022-12-31 | 0.23% | 0.23% | 2026-10-13 법령 연혁으로 확인 |
| 2023-01-01 ~ 2023-12-31 | 0.20% | 0.20% | 2026-10-13 법령 연혁으로 확인 |
| 2024-01-01 ~ 2024-12-31 | 0.18% | 0.18% | 2026-10-13 법령 연혁으로 확인 |
| 2025-01-01 ~ 2025-12-31 | 0.15% | 0.15% | 2026-10-13 법령 연혁으로 확인 |
| 2026-01-01 ~ | 0.20% (거래세 0.05 + 농특세 0.15) | 0.20% | 2026-10-13 법령 연혁으로 확인 |

- 세율은 체결일이 아니라 결제일(T+2)로 고른다. 예: 2025-12-29 체결은 결제일이 2026-01-02라 2026년 세율(0.20%)이다. 표의 모든 값은 2026-10-13에 증권거래세법 시행령 제5조·농어촌특별세법 제5조와 같은 법 시행령 제5조(KOSPI만) 연혁으로 확인했다(실연결 점검 ⑮). 표는 `src/lib/sim/tax.ts` 한 곳에만 둔다.
- 기간 끝까지 보유 중인 수량은 팔지 않으므로 매도 비용을 붙이지 않는다(비교 기준도 같다).

### 5.5 비교 기준

모두 첫 거래일 **시가**에 사서 마지막 거래일 **종가**로 평가한다.

- **같은 종목 균등 보유**: `initial / 종목 수`씩 나눠 수량 = floor(몫 / (시가 × (1 + 수수료율))). 첫 거래일에 봉이 없는 종목(기간 중 상장)은 그 몫을 현금으로 두었다가 첫 봉 시가에 산다.
- **시장 지수**: `initial × 지수 종가 / 첫날 지수 시가`. 비용 없음.
- **지정 종목**: 전액으로 첫날 시가에 매수(수수료 포함). 첫날 봉이 없으면 첫 봉 시가.

### 5.6 결과

```ts
interface SimResult {
  equity: { date: string; strategy: number; hold: number; index: number | null; benchmark: number | null; cash: number }[];
  summary: {
    totalReturnPct: number; cagrPct: number; mddPct: number;
    winRatePct: number | null; wins: number; losses: number;
    avgWinPct: number | null; avgLossPct: number | null;
    roundTrips: number; openPositions: number; avgHoldDays: number | null;
    avgCashPct: number; skippedSignals: number;
    vsHoldPp: number; vsIndexPp: number | null; vsBenchmarkPp: number | null;  // 총수익률 차이(%p)
  };
  benchmarks: { holdReturnPct: number; indexReturnPct: number | null; benchmarkReturnPct: number | null };
  trades: Trade[];             // 날짜 오름차순, 같은 날은 체결 순
  skipped: Skip[];
  perSymbol: { symbol: string; name: string; pnl: number; roundTrips: number; firstDate: string | null }[];
  nearMiss: { maxDropPct: number; declineDays: number } | null; // 거래가 하나도 없을 때만
}
interface Trade {
  date: string; symbol: string;
  kind: 'buy' | 'add' | 'take' | 'stop' | 'gapStop' | 'gapTake';
  stage?: number;              // 익절 단계(1부터)
  price: number; qty: number; fee: number; tax: number;
  reason: string;              // 예: 'B 돌파', '3일 연속 상승', '1단계 익절 50%', '손절'
  pnlPct?: number;             // 매도 줄: 평균 단가 대비
  pattern?: { a: number; aDate: string; b: number; l: number; lDate: string }; // 매수 줄
}
interface Skip { date: string; symbol: string; reason: '현금 부족' | '1주가 1회 금액보다 비쌈' | '거래 없음' }
```

- **한 번의 거래(round trip)** = 첫 매수부터 전량 매도까지. 손익 = 매도 대금 − 매수 대금 − 수수료 − 세금. 승 = 손익 > 0. 기간 끝에 보유 중인 포지션은 승률·평균에서 빼고 `openPositions`로 센다.
- `avgWinPct`·`avgLossPct`: round trip 손익 / 그 포지션 매수 대금 합.
- `cagrPct` = (최종/초기)^(365 / 달력 일수) − 1. `mddPct`: 일별 자산 기준.
- `avgHoldDays`: 첫 매수일부터 전량 매도일까지 거래일 수의 평균.
- `nearMiss`: 거래가 0건이면 기간 중 가장 컸던 `(A−L)/A`와 하락 조건을 만족한 날 수를 준다.

## 6. 데이터 수집

### 6.1 무엇을 받나

| 데이터 | 호출 | 범위 |
|---|---|---|
| 종목 메타 | `getStockMeta(symbols)` | 이름·시장·ETF 여부(`securityType`) |
| 종목 일봉 | `getCandles({interval:'1d', venue, from: warmFrom, to})` | 종목마다 |
| 지수 일봉 | `getIndexCandles(index, '1d', from, to)` | 거래일 축 + 비교 기준 |
| 지정 종목 일봉 | `getCandles` | 비교 기준 |

- `venue`: 공급자가 KRX를 지원하면 KRX, 아니면 `capabilities.venues[0]`(토스는 통합). 결과 머리줄에 `KRX 일봉`·`통합 일봉`으로 표시한다.
- `warmFrom` = `addDays(from, −max(400, ceil(가장 긴 이동평균 × 1.6)))`. 400 달력일 ≈ 250거래일 이상.
- **거래일 축** = `from..to` 안의 (지수 일봉 날짜 ∪ 모든 종목 일봉 날짜)를 정렬한 것. 지수가 실패하거나, 빈 배열이거나, 기간 일부만 와도 축은 종목 날짜로 채워진다. 지수는 거래정지 종목이 빠진 날을 채워 주는 역할이다.
- 축이 비면(지수·종목 모두 기간 안에 봉 없음) 엔진을 부르지 않고 `기간 안에 받은 데이터가 없어요`로 끝낸다.
- **지수 비교 기준**은 지수 봉이 축의 **첫날과 마지막 날 모두에** 있을 때만 쓴다. 아니면 `받지 못함`으로 표시한다. 요청 실패는 사유 `받지 못했어요`, 빈 배열이나 일부만 온 경우는 `기간 일부만 받았어요`다. 중간에 빠진 날은 직전 값으로 채운다.

### 6.2 순서·진행·취소

- 메타 → 지수 → 지정 종목 → 종목들 순서로 **하나씩** 받는다. 진행 표시: `일봉 받는 중 3/10`.
- 취소하면 남은 요청을 보내지 않고, 이미 나간 요청의 결과는 버린다(공급자 API에 AbortSignal이 없어서 진행 중인 요청 하나는 끝까지 간다).
- 같은 탭에서 같은 `공급자|종목|venue|warmFrom|to` 요청은 메모리 맵에서 재사용한다. 공급자가 바뀌면 비운다. IndexedDB에는 저장하지 않는다(기반 스펙 4.3의 수정주가 원칙).

### 6.3 공급자 변경

- `CandleQuery`에 `priority?: Priority`를 더하고, `getIndexCandles`에 선택적 다섯째 인자 `priority?: Priority`를 더한다. 기본은 지금 값(1). 시뮬레이션은 2(미리 받기)로 불러 비교 화면 갱신보다 뒤로 간다.
- KIS·토스·데모 공급자는 받은 우선순위를 큐에 그대로 넘긴다. 계약 테스트는 그대로 통과해야 한다.

### 6.4 결과 해석 한계 (결과 화면 아래에 항상 표시)

- `배당 제외 · 가격 수익률만이에요`
- `지금 관심종목만 넣을 수 있어서 상장폐지 종목이 빠져요(생존 편향)`
- `일봉으로 계산해서 하루 안의 순서는 시가→저가→고가→종가로 가정해요`

## 7. 화면

### 7.1 이동

- 경로: `#/simulate`(전략 목록), `#/simulate/:strategyId`(편집·결과). 새 전략은 목록에서 `＋ 새 전략`으로 만들고 바로 그 경로로 간다. 이름은 `새 전략`, 겹치면 비어 있는 가장 작은 번호(`새 전략 2`, `새 전략 3`…).
- 앱 상태의 경로 정규화(`normalize`)는 지금 비교·설정 밖의 경로를 `{ name }`으로 줄인다. `simulate`는 `strategyId`를 남겨야 한다. 그 id가 현재 프로필의 전략에 없으면 `{ name: 'simulate' }`로 바꾸고 스낵바 `전략을 찾을 수 없어요`를 띄운다. 프로필을 바꾸면 이 경우에 해당한다.
- 진입: 모바일 앱 바의 설정 아이콘 왼쪽에 시뮬레이션 아이콘(aria-label `시뮬레이션`). `#/simulate*`에서는 이 아이콘이 `aria-current="page"`와 레일 항목과 같은 배경으로 현재 위치를 알린다. PC 레일에는 그룹 목록 아래, 설정 위에 `시뮬레이션` 항목.
- 하단 탭바는 계속 두지 않는다.

### 7.2 전략 목록

- 행: 전략 이름 · 한 줄 요약(`반도체 · 2023.10.12~2026.10.11`) · 마지막 수정일. 행을 누르면 편집 화면.
- 행 메뉴: 복제, 이름 바꾸기(빈 이름은 `이름을 적어 주세요` 오류, 같은 오류를 다시 낼 때도 다시 알린다), 삭제(`--err`, 스낵바 `'{이름}'을(를) 삭제했어요 · 되돌리기`). 20개일 때 복제·되돌리기는 한도 스낵바만 띄운다.
- 빈 상태: `내 매매 규칙을 과거 데이터로 시험해 보세요` + `＋ 새 전략`.

### 7.3 전략 편집

구역을 접어 두고 접힌 구역은 요약을 보인다. 순서: 종목 / 기간·자금 / 매수 / 분할 매수 / 매도 / 비교 기준 / 비용.

- 구역 머리는 두 줄: 제목 / 요약(`--fs-sub`, 두 줄까지, 왼쪽 정렬). 셰브런은 회전하는 `▾`로 늘 오른쪽 끝 칸에 있다. 경고가 있으면 셰브런 앞에 막는 경고 `!`(`--err`) 또는 확인할 점 `△`(`--warn`)를 보이고, 머리 버튼 이름에 화면 낭독용 `· 고쳐야 실행돼요` / `· 확인할 점이 있어요`를 덧붙인다. 접혀 있으면 `aria-controls`를 두지 않는다.
- 요약 문구: 종목 `반도체 · 2종목`, 기간·자금 `2023.10.11 ~ 2026.10.11 · 1,000만 원 · 회당 10%`, 매수 `고점 대비 10% 하락 뒤 → 3일 연속 상승 또는 B 돌파`(사는 신호가 없으면 `사는 신호 없음`), 분할 매수 `3% 내릴 때마다 최대 2번 더`(끄면 `끔`), 매도 `익절 +15%에 50% → +25%에 25% → +35%에 나머지 · 손절 −5% 분할 후 평단`(단계가 하나면 `익절 +15%에 전량`, 분할 매수가 꺼져 있으면 손절 기준을 뺀다), 비교 기준 `같은 종목 사서 보유 · KOSPI · KODEX 200`, 비용 `수수료 0.015% · 팔 때 세금 포함`.
- 줄은 설정 화면 `.row`와 같은 순서: `라벨 · 숫자 칸 · 오른쪽 토글`. 라벨은 단어 중간에서 줄을 바꾸지 않고(`word-break: keep-all`), 라벨을 누르면 그 줄의 토글이 바뀐다. 토글의 접근 이름은 보이는 라벨 뒤에 ` 사용`을 붙인 것이다(`고점 대비 하락폭 사용`, `전 고점 돌파 사용`, `골든크로스 사용` 등, WCAG 2.5.3). 꺼진 조건의 숫자 칸·전 고점 A/B 세그먼트·골든크로스 칸은 흐리게 보이지만 계속 고칠 수 있다. 투명도는 글자 대비(AA)를 깨므로 쓰지 않고, 숫자 칸은 박스 배경을 빼고 테두리 `--line`·글자 `--t3`, A/B 세그먼트는 글자만 `--t3`로 보인다.
- 숫자 칸은 박스 전체가 입력과 연결된 label이라 어디를 눌러도 입력에 포커스(높이 44px 이상). 금액(처음 자금)은 포커스가 없을 때 `10,000,000`처럼 천 단위로 보이고 아래에 `= 1,000만 원`(억·조는 `= 1억 2,000만 원`처럼 끊어서)을 보인다. 만 원 단위가 아니면 힌트가 값과 같은 글이라 숨긴다. 칸은 최댓값 `10,000,000,000,000`(18자)이 보이는 폭이다. 포커스를 받으면 쉼표 없는 값으로 바꾸되, Tab으로 들어와 전체가 선택돼 있었으면 다시 전체를 선택해 바로 친 숫자가 값을 바꾼다. `10,000,000원`처럼 쉼표·띄어쓰기·`원`이 섞인 글을 붙여 넣어도 숫자로 읽는다. 숫자는 tabular-nums. 단위(`% 이상` 등)·금액 힌트·오류는 입력의 설명(`aria-describedby`)으로 읽힌다.
- 기간·자금: 시작일·종료일, `처음 자금`(원), `회당 매수 비중`(`% (처음 자금 대비)`).
- 카드 안 세그먼트는 `Segmented onSurface`로 트랙·선택 색을 테마별 토큰 `--seg-card-track`·`--seg-card-on`에서 읽는다. 라이트는 기본 세그먼트와 같은 트랙 `--surface2`·선택 `--surface`(선택·트랙 1.13:1; `--bg`·`--surface2`로 바꾸면 1.05:1로 더 흐려진다), 다크는 트랙 `--bg`·선택 `--surface2`(1.19:1, 기본 모양이면 선택이 트랙보다 어두워 꺼져 보인다).

- 종목: 관심 그룹 고르기(Segmented 또는 목록). 직접 고르기는 기존 종목 추가 시트를 재사용한다.
- 매수: 하락 조건 2줄(토글 + 숫자), 트리거 4줄, 필터 1줄. 전 고점은 `A 하락 시작 전 고점 │ B 마지막 반등 고점` 세그먼트. 도움말로 A·B·L 그림(목업과 같은 선 그림)을 접어서 둔다.
- 매도: 익절 단계(제목 줄 `N단계` 끝에 삭제 `✕`(`--err`), 목표 % · 파는 양; 칸의 접근 이름은 `1단계 목표`·`1단계 파는 양`처럼 단계를 앞에 붙이고 보이는 라벨은 그대로), `＋ 단계 추가`(최대 3), 손절 % · 기준 선택(`분할 후 평단 / 매번 평단 / 첫 매수가`, 힌트 `평단 = 평균 매수가예요. 분할 매수를 끄면 세 기준이 같아요`), `1단계 익절 뒤 손절선` 선택. 삭제 버튼은 모두 `--err`.
- 숫자 입력은 `inputmode="decimal"`, 범위를 벗어나면 그 칸 아래 오류(`1~10,000,000,000,000 사이로 적어 주세요`처럼 금액 칸은 최소·최대도 천 단위). 정수 칸에 소수를 적으면 `정수로 적어 주세요`.
- 3.1의 경고는 해당 구역 안에 Banner로 보인다. 자금 부족 경고는 기간·자금 구역에 보이고, 분할 매수가 켜져 있으면 분할 매수 구역에도 함께 보인다. 이 Banner들은 라이브 영역(alert·status)이 아니다(구역을 펼칠 때마다 다시 알리지 않는다). 막는 경고 때문에 실행하지 않으면 그 구역을 열고 첫 막는 경고 Banner로 포커스를 옮겨 읽힌다.
- 편집은 바로 저장한다(입력 멈춤 500ms 뒤, 화면을 떠나거나 `pagehide` 때는 바로). 맨 아래 고정 버튼 `시뮬레이션 실행`.
- `복제`는 이름 입력 칸 옆에 둔다(머리줄에는 좁은 화면에서 자리가 없다). 편집 화면의 머리줄 제목은 이름과 관계없이 `시뮬레이션`이고, 이름은 이름 입력 칸에서 본다. 이름을 비우면 칸 아래에 `이름을 적어 주세요`(`--err`, alert)를 보이고 저장된 이름은 맞는 이름을 적을 때까지 그대로 둔다(칸을 떠나도 조용히 되돌리지 않는다).

### 7.4 결과

실행하면 같은 경로에서 결과 보기로 바뀌고 머리줄에 `규칙`(편집으로 돌아가기) 버튼이 생긴다. 좁은 화면에서 `규칙`으로 편집에 가 있을 때 실행 상태가 대기(idle)가 아니면(로딩·일부 실패 확인·완료·오류·데이터 없음) 머리줄에 `결과` 버튼이 있어 결과 보기로 돌아간다. `규칙`과 `결과`는 이름과 동작만 바뀌는 같은 버튼이라 눌러도 포커스가 그 버튼에 남는다. PC(≥1024)에서는 편집과 결과를 좌우로 놓으므로 이 버튼이 없다.

포커스: 좁은 화면에서 `시뮬레이션 실행`을 누르면 편집기가 내려가므로 포커스를 결과 자리로 옮기고, 받는 중에 `취소`하면 편집기의 `시뮬레이션 실행`으로 옮긴다. `다시 시도`·`다시 실행`·`빼고 계속`·`취소`처럼 상태가 바뀌어 누른 버튼이 사라지면(포커스가 결과 자리 안에 있었거나 잃었을 때) 결과 자리로 옮긴다. 결과의 `규칙 고치기`가 편집의 구역을 열면 그 구역 머리로 옮긴다.

폰 폭(<600)에서는 시뮬레이션 머리줄에 상태 칩을 그리지 않는다(`back` · 제목 · `규칙`/`결과` · 아이콘 2개가 375px에 들어가야 한다). 비교·설정의 머리줄은 그대로 칩을 둔다.

1. 머리줄 아래 한 줄: `2023.10.12 ~ 2026.10.11 · KRX 일봉 · 10/12 14:05 받음`. 기간은 실제로 받은 거래일 축의 첫날~마지막 날이다. 축이 요청 시작일보다 **7일 넘게** 늦게 시작하면(주말·명절 연휴로 늦은 것은 표시하지 않는다) `2025.01.02 ~ 2026.10.12 (요청 2023.10.12부터) · KRX 일봉 · …`처럼 요청 시작일을 덧붙인다.
2. 요약 카드 2×2: 총수익률(`그냥 보유보다 +16.1%p`를 작게), 최대 낙폭, 승률(`24승 17패`), 거래 횟수(값은 보유 중 포함 `roundTrips`, 부가 줄 `끝난 6번 · 아직 보유 3종목 · 평균 149일`의 끝난 거래는 `roundTrips − openPositions`(= 승 + 패); 보유 중이 없으면 `끝난 6번 · 평균 149일`). 카드는 앱 카드와 같은 모서리(`--r-card`)·무테이고, 총수익률 값만 `--fs-headline`, 나머지 셋은 `--fs-title`이다. 총수익률 값은 줄바꿈하지 않고, `▲ +125.3%`처럼 길어 반 카드에 들어가지 않으면 카드 폭에 맞춰 글자를 줄인다(넓은 카드는 그대로).
3. 자산 곡선: lightweight-charts 선 4개. 전략 `--accent`(굵기 2, 실선; 파랑 슬롯 7은 하락색으로 읽혀 쓰지 않는다), 같은 종목 사서 보유 `--t3`(1, 실선), 지정 종목 `--line-bench`(2, 점선; 라이트·다크 `#d95926`, `--bg` 위 3.62:1·4.94:1. 비교 화면 슬롯 1 `--s1`은 라이트 `--bg` 위 2.99:1이라 쓰지 않고 그대로 둔다), 지수 `--t2`(1.5, 점선). 범례 견본도 실선/점선을 구분한다. 가격 축 위 여백 0.1(맨 위 라벨이 잘리지 않게). 크로스헤어로 그날 네 값. 앱 테마가 바뀌면 색을 다시 읽어 넣는다.
4. 비교 기준 목록: `내 전략 / 같은 종목 사서 보유 / <지정 종목명> / <지수명>`과 총수익률, 행 앞에 자산 곡선과 같은 선 견본. 받지 못한 기준은 `받지 못했어요`.
5. 세그먼트 `거래 내역 │ 종목별 │ 건너뛴 신호 N`
   - 거래 내역 행(리더보드 행 구조): 1줄 종목명 + 오른쪽 정렬 값(매수·추가 `12주 · 132,400원`, 매도 `▲ +15.0%`처럼 ▲▼와 색), 2줄 `03.14 · B 돌파 매수`(`--t3`), 행 끝 `›`. 익절 사유는 `1단계 익절(80% 매도)`로 보인다. 해마다 설정 화면 구역 제목 모양의 연도 제목(`h2` `2024년`)을 두고 그해 거래를 따로 목록으로 묶는다(제목이 목록 항목 수에 섞이지 않게). 전체는 `거래 내역` 그룹.
   - 행을 누르면 **거래 차트 시트**(제목 `SK하이닉스 · 24.03.14 매수`, 포지션의 첫 매수일): 그 종목의 일봉 종가 선, 그 포지션의 매수·추가·매도 마커(같은 방향 마커가 3봉 안이면 하나로 합쳐 `매수·추가`·`익절·손절`; 익절과 손절이 합쳐진 마커는 색이 섞이므로 중립색 `--t2`), 매수 시점의 A·B·L 가격선(라벨 `A`·`B`·`L`; 전략이 고른 돌파 기준선만 `--accent`, 다른 하나는 `--t3` 점선(전 고점 돌파 트리거가 꺼져 있으면 A·B 둘 다 `--t3`), L은 성긴 점선에 축 라벨 없음), 가격 축 여백 위 0.12·아래 0.22, 표시 구간은 aDate 20거래일 전 ~ 전량 매도 20거래일 뒤이고, 첫 x 라벨(`'25년` 등)이 왼쪽 끝에서 잘리지 않게 앞에 표시 봉 수의 7%(최소 3봉)만큼 빈칸을 둔다. 아래 요약은 `매수 03.14 132,400원 → 손절 04.02 125,000원 · ▼ −5.6%`(단계마다 줄바꿈 없음, 끝은 포지션 결과 또는 `보유 중`). 첫 매수와 해가 다른 단계는 `25.01.10`처럼 연도를 붙인다.
6. 한계 안내 3줄(6.4).

거래가 0건이면 2~5 대신 `기간 동안 매수 신호가 한 번도 나지 않았어요` + nearMiss 문구와 `규칙 고치기` 버튼. nearMiss는 ① 하락 폭이 모자랐으면 `고점 대비 가장 크게 빠진 때도 27.0%라, 하락 조건(85% 이상)에 닿지 않았어요`, ② 하락 조건을 채운 날이 있었으면 `충분히 떨어진 날은 N일 있었지만, 그 뒤 ②의 사는 신호(연속 상승·돌파 등)가 한 번도 나오지 않았어요`, ③ 일수 조건 때문이면 `고점 뒤 하락이 N거래일 이상 이어진 적이 없었어요`(N은 조건의 일수).

신호는 났지만 모두 건너뛰었으면(`skipped`만 있음) 제목 `매수 신호가 N번 났지만 한 번도 사지 못했어요` + 사유별 개수 목록(표시 문구: `현금 부족`→`현금이 모자랐어요`, `1주가 1회 금액보다 비쌈`→`1주가 회당 금액보다 비싸요`, `거래 없음`→`그날 거래가 없었어요`; 5.6의 enum 값은 그대로)을 보이고 건너뛴 신호 목록을 펼친다. 가장 많은 사유가 현금·금액이면 `기간·자금에서 회당 비중이나 처음 자금을 늘려 보세요`를 안내하고 `규칙 고치기`가 편집의 기간·자금 구역을 연다. 건너뛴 신호 탭이 비면 `건너뛴 신호가 없어요`.

`to`가 오늘 이후면 **어제**로 줄여서 실행한다(장중의 미완성 봉으로 신호를 판단하지 않도록). 결과 머리줄 기간은 줄인 날짜 안의 실제 마지막 거래일로 끝난다. 줄인 뒤에도 `from`이 `to`보다 뒤(시작일이 오늘 이후)면 공급자를 부르지 않고 데이터 없음으로 처리한다.

| 429로 기다리는 중 | 진행 문구 뒤에 `· 잠시 대기 중` (요청 큐가 재시도하는 동안) |
| 키·프록시 오류(첫 요청부터 실패) | 기존 오류 배너 문구와 `진단 열기` + `다시 시도`(편집기의 현재 작업본으로 다시 받는다) |
| 모든 종목을 받지 못함(남은 종목 0, 실패 사유가 모두 `받지 못했어요` 또는 `종목 정보를 받지 못했어요`) | 데이터가 없는 것이 아니라 연결 문제로 보고 위 행과 같은 배너·`다시 시도`. 문구와 해결 행동은 종목들이 던진 오류 중 먼저 고칠 수 있는 것(연결 → 키·권한 → …)의 것이고, ApiError가 아니면 `종목 일봉을 받지 못했어요`(모두 종목 정보를 못 받았으면 `종목 정보를 받지 못했어요`) + `진단 열기`. 기간 안 데이터 없음이 하나라도 섞이면 `기간 안에 받은 데이터가 없어요` + 실패 목록 |
| 일부 종목만 실패 | 사유별로 한 줄씩 말한다. 일봉을 받지 못함: `○○, △△ 일봉을 받지 못했어요`, 종목 정보(메타)를 받지 못함: `○○ 종목 정보를 받지 못했어요`(이름을 모르면 종목 코드), 기간 안 데이터 없음: `○○은(는) 이 기간에 데이터가 없어요`. 마지막 줄 끝에만 `. 빼고 계속할까요?`를 붙인다. + `빼고 계속`·`취소`. 결과의 종목별 탭에 `제외: ○○ (사유)` |
| 규칙이 바뀐 뒤 | 결과의 `meta.strategy`와 편집기의 현재 작업본이 `id`·`name`·`updatedAt`을 뺀 깊이 비교로 다르면 결과 위에 안내 배너 `규칙이 바뀌었어요. 다시 실행하면 결과에 반영돼요` + `다시 실행`(현재 작업본으로). 결과는 흐리게 하지 않고(투명도는 글자 대비를 AA 밑으로 떨어뜨리고 안의 거래 차트 시트까지 흐린다) 결과 머리줄 앞에 `이전 결과` 배지(`--accent` / `--accent-soft`)와 결과 영역 왼쪽 3px `--accent` 선으로 표시한다. 좁은 화면도 같다(`규칙`에서 고친 뒤 `결과`로 돌아오면 배너) |
| 지수·지정 종목 실패 | 그 기준만 `받지 못했어요`, 나머지는 정상 |
| 종목 데이터가 기간보다 짧음 | 종목별 탭에 `2024.03.02부터 참여` (종목 첫 거래일이 **실제 데이터 축의 시작일**보다 7일 넘게 늦을 때. 축 전체가 늦게 시작한 것은 머리줄이 알린다) |
| `다시 실행`·`다시 시도` 때 작업본에 막는 경고가 있음 | 버튼은 그대로 두고, 누르면 실행하지 않고 첫 막는 경고의 구역을 편집에서 연다(좁은 화면은 편집으로 전환) |
| 엔진 예외 | `계산 중 문제가 생겼어요` + `다시 실행`(편집기의 현재 작업본으로). 콘솔에 원인 |
| 데모 공급자 | 결과 머리줄에 `데모 데이터` 배지 |

화면 낭독기 알림은 결과 자리에 늘 있는 라이브 영역(polite) 하나가 맡는다: 받는 중 시작·대기, `결과가 나왔어요`, 일부 실패의 질문 글, `기간 안에 받은 데이터가 없어요`, `계산 중 문제가 생겼어요`. 연결 오류는 그 Banner(alert)만 알린다(겹쳐 알리지 않는다).

## 9. 테스트

- **엔진(가장 두껍게)**: 손으로 만든 짧은 일봉 시나리오마다 기대 거래를 검증한다.
  - 패턴: A 갱신·리셋, B 없음 → B=A, L 갱신, 하락 조건 각각·둘 다·둘 다 끔, reboundDays가 저점 다음 날부터일 때만, 돌파의 어제·오늘 조건, 이동평균 값 부족.
  - 체결: 다음 날 시가 매수, 갭 손절·갭 익절, 같은 날 손절·익절이면 손절, 하루에 익절 두 단계, 같은 날 산 종목의 장중 손절.
  - 분할: 손절 기준 3종, 부분 매도 뒤 추가 매수 중단, 본전 손절선, 추가 매수 연쇄(하루에 두 번).
  - 자금: 현금 부족 건너뜀(가격당 기록 1회), 같은 날 신호의 그룹 순서, 0주, 수수료·세금(연도별·ETF).
  - **미래 데이터 미사용**: t일 뒤 봉을 임의로 바꿔도 t일까지의 거래·자산이 같다(속성 테스트, 무작위 시드 고정).
  - 비교 기준·요약: 균등 보유, 기간 중 상장, 지수 정규화, MDD·CAGR·승률 손계산.
- **데이터 수집**: 데모 공급자와 가짜 공급자로 워밍업 범위, 거래일 축(지수 실패 시 합집합), 부분 실패, 취소, 메모 재사용, 우선순위 2 전달.
- **저장**: 깨진 전략 하나만 빠지고 배너, 내보내기·가져오기 왕복, 프로필 삭제 시 함께 삭제.
- **화면(컴포넌트 테스트)**: 접힌 구역 요약 문구, 경고 표시, 실행 버튼 막힘(트리거 없음), 결과 카드·비교 목록, 0건 nearMiss 문구, 거래 행 → 시트.
- **e2e(Playwright, 데모 공급자)**: 새 전략 → 실행 → 결과 → 거래 차트 시트, axe 접근성 검사.
- **실연결 점검** `docs/live-check.md`에 추가:
  - ⑭ KIS·토스 일봉을 몇 년 전까지 주는가, 지수 일봉 기간 한도
  - ⑮ 매도 세율표(5.4)의 값과 적용 시작일을 법령 원문으로 확인(2026-10-13 완료)

## 10. 결정 기록

| 결정 | 이유 |
|---|---|
| 브라우저 안에서 받고 계산 | 정적 사이트·서버 없음 원칙 유지. 8종목 일봉은 호출 몇 번이면 충분 |
| 종목 스크리닝은 별도 프로젝트 | 전 종목 데이터 수집(CI·키·용량)이 필요해 규모가 다름 |
| Web Worker 없이 메인 스레드 | 계산량이 작음. 엔진이 순수 함수라 나중에 옮기기 쉬움 |
| 종가 기준 패턴 | 사용자 확정. 신호가 덜 잦고 일봉 체결 가정과 어긋나지 않음 |
| 시가→저가→고가→종가 경로 | 순서를 모를 때 불리한 쪽으로 가정해 과대평가를 막음 |
| 결과 미저장 | 수정주가가 바뀔 수 있어 재실행이 맞음 |
| 세율을 결제일(체결일+2거래일)로 고름 | 2019~2026년에 여러 번 바뀜. 고정값이면 과거 구간 결과가 틀림 |
