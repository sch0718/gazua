# 선정 기준 3단계 설계: 투자자 매매동향

작성 2026-10-16. 기반 스펙은 [선정 기준 검증 1단계](2026-10-16-selection-criteria-validation-design.md)와 [4단계 환율·유가와 테마](2026-10-16-macro-theme-criteria-design.md)다. 두 스펙의 원칙은 그대로 이어받는다.

- 과거 시점에서 선별한다.
- 재선정일의 전 거래일 p까지의 데이터만 쓴다.
- ①·②를 나란히 계산한다.
- 사용자가 직접 수집한 파일을 쓴다.
- 데이터가 없는 파일에서는 새 조건을 끈 채 안내한다.

## 1. 목표와 범위

### 1.1 목적
선정 기준에 외국인·기관·개인의 매매동향 조건을 더한다. 아래와 같은 기준을 만들어 1단계와 똑같이 검증하고 결과를 읽을 수 있으면 성공이다.

- "최근 20일 외국인 순매수가 거래대금의 3% 이상인 종목"
- "기관이 5일 이상 연속 순매수 중인 종목"
- "외국인과 기관이 함께 사는(쌍끌이) 종목 중 수급이 강한 순으로 10개"

### 1.2 대화에서 확정한 것 (2026-10-16)

| 항목 | 결정 |
|---|---|
| 단계 순서 | 3단계(투자자 매매동향)를 2단계(재무·가치)보다 먼저 한다 |
| 쓰임새 | 최근 N일 순매수 규모, 연속 순매수 일수, 수급 순 정렬, 함께 사는 주체(쌍끌이). 네 가지 모두 |
| 투자 주체 | 외국인·기관(기관계)·개인 세 주체만 둔다. 쌍끌이는 외국인+기관이다 |
| 수집 범위 | 전 종목을 받는다. 기간은 기본으로 일봉과 같고, 옵션으로 줄일 수 있다 |
| 비율의 분모 | 같은 기간 거래대금을 쓴다. 시가총액은 쓰지 않는다(상장주식수가 수집일 기준값 하나뿐이다) |
| 반영 시점 | 하루 늦춘다 |

### 1.3 범위 밖
- 기관 세부(연기금·투신·사모 등)와 수량(주) 기준 조건은 넣지 않는다.
- 시가총액 대비 비율은 넣지 않는다.
- 매매동향을 매매 규칙(②)의 진입·청산 신호로 쓰는 것은 넣지 않는다.
- 장중 잠정치는 쓰지 않는다.

## 2. 데이터

### 2.1 출처
- KIS 국내주식 "종목별 투자자매매동향(일별)", TR `FHPTJ04160001`.
  - 기준일 하나를 주면 그날부터 과거로 여러 날의 행을 돌려준다.
  - 행마다 영업일과 주체별 순매수 수량·거래대금이 있다.
- 쓰는 필드는 영업일, 외국인 순매수 거래대금, 기관계 순매수 거래대금, 개인 순매수 거래대금이다.
- 아래 세 가지는 실연결 점검 ㉓에서 확인한다. 코드는 아래의 가정 값을 상수 한 곳에 두고, 점검 결과에 맞춰 바꾼다.
  - 정확한 경로와 필드 이름
  - 금액 단위. 백만 원으로 가정한다.
  - 한 번 호출에 오는 행 수와 최대 과거 깊이
- 수집은 기존 KIS 클라이언트(초당 호출 제한·재시도·비밀값 가리기)를 그대로 쓴다. 앱은 수집 파일만 읽으므로 **프록시 허용 목록은 바꾸지 않는다.**

### 2.2 파일 형식 v3
v2에 종목별 `flow`를 더한다.

```ts
interface FlowSeries {
  from: string;    // 수급 시작일(YYYYMMDD). 그 종목 d에 있는 날짜
  f: number[];     // 외국인 순매수 금액(백만 원, 정수)
  i: number[];     // 기관계
  p: number[];     // 개인
}
// stocks[k].flow?: FlowSeries
// 세 배열의 길이 L(≥ 1)은 같고, d[from 위치 + j](j < L)와 한 칸씩 맞는다.
// 수급 끝 = d[from 위치 + L − 1]. 마지막 일봉까지 닿지 않아도 된다(아래 '수급 끝')
interface MarketDataFileV3 extends Omit<MarketDataFileV2, 'version'> { version: 3 }
```

- **빈 날의 처리.** 일봉에는 있는데 수급 행이 없는 날이 있으면, 0으로 채우지 않는다. `from`을 그 빈 날 다음으로 옮긴다(수급 구간은 언제나 이어져 있다).
- **수급 끝.** 마지막 수급 행 뒤에 일봉만 있는 날은 0으로 채우지 않고 구간을 거기서 끝낸다. `--update`에서 일봉은 늘었는데 수급 받기만 실패한 종목이 이 경우다. 이런 파일도 형식상 유효하다(리뷰 반영, 결정 F8).
- 수급을 받지 못한 종목은 `flow`가 없다.
- **검증.** 아래 중 하나라도 어기면 `corrupt`다.
  - `from`이 `d` 안에 있다.
  - 세 배열의 길이가 같고 1 이상이며, `from` 위치 + 길이 ≤ `d`의 길이다.
  - 값이 모두 유한한 정수다.
- **호환.** v1·v2를 그대로 받는다. 4 이상은 `version-newer`다.
- **저장소 정보.** `info()`에 `hasFlow`(수급이 있는 종목이 하나라도 있는가)와 `flowStocks`(그 종목 수)를 더한다.
- **데이터 요약 문구.** 수급이 있으면 기존 요약 뒤에 ` · 매매동향 포함`을 붙인다.

### 2.3 미래 정보 차단: 반영 시점 규칙
- 날짜 t의 수급은 **t < p** 일 때만 쓴다. p는 재선정일 d의 전 거래일이다. 즉 마지막으로 쓰는 수급은 p의 전 거래일(재선정일의 이틀 전 거래일) 것이다.
  - 이유: 투자자별 수치는 장 마감 뒤 확정·정정될 수 있다. 하루를 늦춰 보수적으로 잡는다.
- 구현에서는 종목의 일봉 위치 `idx(p)`를 찾고, 수급은 `idx(p) − 1`까지 쓴다.
- 계산에 필요한 N일 창이 `from`보다 앞으로 나가면 그 종목은 **계산 불가**다. 수급 조건에서는 탈락이다.
- e가 수급 끝보다 뒤여도(최근 수급을 받지 못한 종목) **계산 불가**다. 끝 이후를 0으로 보지 않는다.

## 3. 조건과 정렬

### 3.1 주체
`FlowWho = 'foreign' | 'inst' | 'indiv' | 'both'`. `both`는 외국인과 기관이 **각각** 조건을 만족해야 한다.

### 3.2 순매수 비율
마지막으로 쓸 수 있는 봉을 e(= `idx(p) − 1`)라 할 때 다음과 같이 계산한다.

```
ratio(who, days) = Σ_{j=e−days+1..e} net_who[j] × 1e6 / Σ_{j=e−days+1..e} tv[j] × 100   (%)
```

- 분모가 0 이하이면 계산 불가다.
- 백만 원 단위 가정은 2.1과 같다.

### 3.3 조건 모델 (`SelectionCriteria.conditions.flow`)

```ts
flow: {
  amount: { on: boolean; who: FlowWho; days: number; minPct: number; maxPct: number };
  streak: { on: boolean; who: FlowWho; minDays: number };
}
rank: { by: RankBy | 'flow'; take: number; series?: MacroSeriesKey; flow?: { who: FlowWho; days: number } }
```

| 항목 | 기본값 | 범위 |
|---|---|---|
| `amount` | 끔, `who` `'foreign'`, `days` 20, `minPct` 1, `maxPct` 100 | `days` 5~120, `minPct`·`maxPct` −100~100 |
| `streak` | 끔, `who` `'inst'`, `minDays` 5 | `minDays` 1~60 |
| `rank.flow` | `who` `'foreign'`, `days` 20 | `days` 5~120 |

- **순매수 규모.** `minPct ≤ ratio ≤ maxPct`이면 통과한다. 음수 범위로 순매도 종목을 고를 수 있다. `both`이면 외국인 비율과 기관 비율이 둘 다 범위 안이어야 한다.
- **연속 순매수.** e부터 거꾸로 세어 `net > 0`인 날이 이어진 수가 `minDays` 이상이면 통과한다. `both`이면 외국인과 기관이 같은 날 함께 `> 0`인 날만 센다.
  - 세다가 `from`에 닿았는데도 끊기지 않았으면, 센 일수가 `minDays` 이상일 때만 통과한다(모르는 앞날을 순매수로 치지 않는다).
- **수급 순 정렬.** `rank.by === 'flow'`이면 `ratio(rank.flow.who, rank.flow.days)`가 큰 순서로 고른다.
  - `both`이면 두 비율 중 작은 값으로 정렬한다.
  - 계산 불가인 종목은 정렬에서 뺀다.
- **기존 프로필.** `flow`나 `rank.flow`가 없는 기존 프로필은 기본값으로 조용히 채운다(`repaired=false`). 4단계의 `macro`와 같다.

### 3.4 막는 경고 (`criteriaIssues`)
- `amount.minPct > amount.maxPct`이면 실행을 막는다. 문구: `순매수 비율의 최소가 최대보다 커요`
- 수급이 없는 데이터(`hasFlow`가 false)에서 다음 중 하나라도 해당하면 실행을 막는다. 문구: `이 데이터에는 투자자 매매동향이 없어요`
  - 수급 조건이 켜져 있다.
  - `rank.by === 'flow'`이다.
- 수급 조건과 `rank.by === 'flow'`가 함께 켜져 있고 수급이 없는 데이터이면 막는 문구는 조건 구역에 한 번만 보인다(정렬 구역에는 따로 더하지 않는다). 4단계의 선례를 따른다(ruling P7).
- 숫자가 범위를 벗어나면 기존 규칙대로 막는다.

### 3.5 미리 계산
- 쓰는 주체만 종목별 누적합 배열을 `Float64Array`로 만든다. `both`는 외국인과 기관 두 배열을 만든다.
- 연속 순매수를 쓸 때만 종목별 "그날까지 이어진 순매수 일수" 배열을 `Int32Array`로 만든다.
- 그러면 한 종목·한 날짜의 계산이 O(1)이다.
- 수급 조건과 정렬을 모두 쓰지 않으면 아무 배열도 만들지 않는다. 4단계 β와 같다(ruling M3).
- 메모리: 비율을 쓰면 봉당 주체 누적합 8B + 거래대금 누적합(tv prefix) 8B이고, 연속 일수를 쓰면 4B를 더한다. 449만 봉이면 주체 하나에 비율만 약 72MB, 연속 일수까지 약 90MB다. `both`는 주체 누적합이 둘이라 거래대금 누적합을 더해 24B(약 108MB), 연속 일수까지 28B(약 126MB)다. 실측은 ㉔에서 한다.

## 4. 화면

### 4.1 조건 구역: `투자자 매매동향` 소구역
- 위치는 환율·유가 소구역 아래이고, 접는 구역이다. 구조는 `MacroConditions`와 같다.
- **줄 1 `순매수 규모`**: 토글, 주체 고르기, 기간(일), 최소·최대(%).
  - 설명: `최근 기간 순매수 금액이 같은 기간 거래대금에서 차지하는 비율이에요. 음수면 순매도예요`
- **줄 2 `연속 순매수`**: 토글, 주체 고르기, 최소 일수.
  - 설명: `이 주체가 하루도 빠짐없이 순매수한 날이 이어진 수예요`
- **주체 이름**: `외국인`, `기관`, `개인`, `외국인+기관`.
- **공통 안내**: `매매동향은 하루 늦게 반영해요(장 마감 뒤 수치가 바뀔 수 있어서)`
- **수급이 없는 데이터**
  - 토글은 `aria-disabled`로 막고, `다시 수집하면 쓸 수 있어요`를 `aria-describedby`로 잇는다.
  - 이미 켜져 있던 조건은 끌 수 있고, 끈 뒤에도 포커스가 그 토글에 남는다(4단계 Minor 3 수정과 같다).
- 접힌 구역에 범위를 벗어난 값이 있으면 실행을 막고, 구역을 펼쳐 그 칸으로 포커스한다.

### 4.2 정렬
정렬 고르기에 `수급 순`을 더한다. 고르면 주체와 기간 칸이 나온다. 수급이 없는 데이터에서는 3.4의 막는 경고를 정렬 구역에 보인다.

### 4.3 결과
- **선정 이력** (행을 펼쳤을 때): 켠 조건이나 정렬에 쓴 값을 보인다.
  - 예: `외국인 순매수 20일 3.2% · 연속 5일`
  - `both`의 예: `외국인 2.1% · 기관 1.4% (20일) · 함께 연속 3일`
  - 소수점 한 자리이고, 음수는 `−` 부호로 쓴다.
- **결과 도움말 메모**
  - `flowLag` (수급 조건이나 정렬을 쓸 때 늘): `매매동향은 재선정일 이틀 전 거래일까지 써요`
  - `flowGap` (어떤 재선정일에 수급 때문에 후보 전체가 계산 불가였을 때): `수급 데이터가 없는 구간이 있어 그 재선정일에는 고른 종목이 없거나 적어요`
- **실행 오류** `no-flow`: 수급 없는 데이터로 수급 기준을 실행하려 할 때(화면에서 막히지만 Worker도 거절한다). 문구는 3.4와 같다.

## 5. 수집 스크립트 변경
- `scripts/fetch-investor-flow.mjs`(새 파일): 한 종목의 수급을 기준일부터 과거로 받는다.
  - 받은 가장 오래된 날짜의 전날을 다음 기준일로 삼는다.
  - 기간 시작에 닿거나, 빈 응답이 오거나, 이전과 같은 날짜가 반복되면 멈춘다.
  - 행 → `{ d, f, i, p }`로 바꾼다. 금액은 정수로 반올림한다.
- `collect-market-data.mjs`
  - 일봉 다음에 종목마다 수급을 받아 2.2 규칙대로 `flow`를 만들고, v3로 쓴다.
  - **실패 처리**
    - 종목 하나가 실패하면 그 종목만 `flow`를 비우고 계속한다.
    - 끝에 `수급 받기 실패 N종목` 경고를 남긴다.
    - 실패가 전체의 절반을 넘으면 경고를 더 크게 띄운다. 그래도 파일은 쓴다.
  - **새 옵션** `--flows-years N`: 수급 기간을 최근 N년으로 줄인다. 기본은 일봉 기간이다. `--no-flows`를 주면 수급을 받지 않는다(v3로 쓰되 `flow`가 없다).
  - **`--update`**
    - 이전 파일에 있던 `flow`는 이어 붙이고, 그 뒤 날짜만 받는다.
    - 이어 붙이는 자리에 빈 날이 생기면 2.2 규칙대로 `from`을 옮긴다.
    - 받기 시작일은 이전 `flow`의 수급 끝에서 5번째 날이다(이전 파일의 마지막 일봉 기준이 아니다). 이전 `flow`가 5일보다 짧으면 `flow`의 `from`부터 받는다. 일봉처럼 마지막 5일을 다시 받아 잠정값의 정정을 반영하고, 겹친 날은 새로 받은 행이 이전 행을 덮어쓴다(ruling P8). 한 번 실패한 종목도 다음 `--update`에서 메워진다.
    - 이번에 받기가 실패하면 그 종목의 이전 `flow`를 그대로 둔다.
  - **요약 줄**에 `매매동향 N종목 · 최초 YYYY-MM-DD`를 더한다.
- `make-demo-market-data.mjs`: v3를 만들고, 아래처럼 설계한 수급 종목을 넣는다(테스트와 e2e가 쓴다).
  - 외국인이 꾸준히 순매수하는 종목 3개(비율 약 +5%)
  - 기관이 최근 연속 순매수하는 종목 2개(최근 8일 연속)
  - 외국인과 기관이 함께 사는 종목 1개
  - 수급 시작일이 데모 기간 중간인 종목 1개(`flowGap`·계산 불가 확인용)
  - 나머지 종목은 순매수 비율이 0 주변이다.
- 키는 `KIS_APP_KEY`·`KIS_APP_SECRET` 환경변수에서만 읽는다. 로그·오류·파일·URL 어디에도 키를 넣지 않는다.

## 6. 오류·예외

| 상황 | 동작 |
|---|---|
| v1·v2 파일 | 열린다. 수급 조건은 끈 채 `다시 수집하면 쓸 수 있어요`를 보인다 |
| 수급 없는 데이터 + 수급 기준 실행 | 화면에서 막는다. Worker는 `no-flow`로 거절한다 |
| 종목의 수급 시작일 이전이 걸리는 재선정일 | 그 종목은 수급 조건에서 탈락하고 정렬에서 빠진다. 후보 전체가 그렇게 비면 `flowGap` 메모를 붙인다 |
| 분모(거래대금 합)가 0 | 계산 불가로 탈락한다 |
| 파일의 `flow` 형식 오류 | `corrupt`다. 기존 가져오기 오류 흐름을 따른다 |
| 수집 중 한 종목 실패 | 그 종목만 비우고 계속한다. 끝에 경고를 남긴다 |

## 8. 테스트
- **형식**: v3 검증(`from` 위치, 길이, 정수), 수급 끝이 마지막 일봉보다 앞선 `flow`도 유효, v1·v2 호환, 4 이상 거절.
- **수집**: 아래는 주입한 가짜 클라이언트로 확인한다.
  - `fetch-investor-flow` 페이지 넘김과 멈춤 조건
  - 빈 날이 있을 때 `from` 이동
  - 종목 실패 시 계속하기
  - `--update`의 이어 붙이기와, 실패 시 이전 값 유지(일봉만 늘고 수급만 실패한 결과 파일이 v3 검증을 통과)
  - 다음 `--update`가 수급 끝의 마지막 5일을 겹쳐 받아 메우고, 겹친 날은 새 값으로 덮어씀(P8)
  - `--flows-years`, `--no-flows`
  - 키가 요청 URL·로그·오류·출력 파일에 들어가지 않음(인증 헤더는 기존 KIS 클라이언트가 넣는 그대로다)
- **계산**
  - 비율·연속 일수를 직접 계산한 값과 비교한다. `from` 경계, 분모 0, `both`를 포함한다.
  - **미래 정보 누출 검사**: 날짜가 p 이상인 수급 값을 바꾸거나 잘라내도 모든 재선정일의 선정 결과가 같아야 한다.
  - 수급을 쓰지 않는 기존 기준의 결과는 기준선 파일과 같아야 한다.
- **기준 모델**: 기본값, 범위, 막는 경고 두 가지, 기존 프로필 채우기, 내보내기·가져오기 왕복.
- **화면**: 소구역 토글과 칸, v1·v2에서 비활성과 포커스 유지, 접힌 구역 차단, 정렬 `수급 순`, 이력 값 형식, 메모 두 가지.
- **e2e** (4개 프로젝트)
  - v3 데모를 가져와 외국인 순매수 ≥ 3%(1%는 안 된다: 데모 잡음으로 설계 외 종목 107777이 한 재선정일에 1.02%까지 올라간다. 설계 종목은 3.8~6.0%다)로 미리 보기와 실행을 한다.
  - 이력 값 `외국인 순매수 20일` 형식을 확인한다.
  - 고른 종목이 모두 설계한 외국인 순매수 종목(`FLOW_FOREIGN_CODES`와 함께 사는 `FLOW_BOTH_CODE`)인지 확인한다.
  - axe 검사를 한다(serious·critical 0).

## 9. 결정 기록 (사용자 리뷰 대상)

| # | 결정 | 이유 | 바꾸면 |
|---|---|---|---|
| F1 | 분모는 같은 기간 거래대금 | 과거 시점 값으로 계산할 수 있고, 종목 크기가 달라도 비교된다 | 시가총액으로 하려면 과거 상장주식수가 필요하다 |
| F2 | 수급은 t < p만 쓴다(하루 늦춤) | 장 마감 뒤 정정 가능성에 대비해 보수적으로 잡는다 | ㉓에서 정정이 없다고 확인되면 t ≤ p로 바꿀 수 있다 |
| F3 | 빈 날은 0으로 채우지 않고 `from`을 옮긴다 | 0을 넣으면 "순매수 없음"으로 잘못 읽힌다 | 빈 날이 잦으면 수급 구간이 짧아진다. ㉔에서 본다 |
| F4 | `both`는 각각 만족, 정렬은 두 비율의 최솟값 | "둘 다 산다"의 가장 엄격한 해석이다 | 합계로 바꾸면 한쪽이 강한 종목도 올라온다 |
| F5 | 연속 일수가 `from`에 닿으면 센 만큼만 인정 | 모르는 과거를 순매수로 치지 않는다 | — |
| F6 | 금액만 저장(백만 원 정수), 수량은 버림 | 파일 크기. 조건이 금액 비율만 쓴다 | 수량 조건이 필요하면 v4 |
| F7 | 수급 종목 실패는 경고 후 계속 | 4단계 FRED·테마와 같은 방식 | — |
| F8 | 수급 구간은 마지막 일봉까지 닿지 않아도 된다(수급 끝). 끝 이후는 계산 불가 | `--update`에서 수급만 실패해도 파일이 유효하고, 0을 채우지 않는다(PR #14 리뷰) | 끝 이후가 길면 최근 재선정일이 `flowGap`이 된다 |
