# 선정 기준 4단계 설계: 환율·유가 영향도와 테마

작성 2026-10-16. 기반 스펙: [선정 기준 검증 1단계](2026-10-16-selection-criteria-validation-design.md). 1단계 스펙의 원칙은 그대로 이어받는다. 과거 시점 선별, 재선정일 전 거래일 p까지의 데이터만 쓰기, ①·② 나란히 계산, 사용자가 직접 수집한 파일 사용이 그것이다.

## 1. 목표와 범위

### 1.1 목적
1단계 선정 기준에 사용자가 평소 보는 기준 두 가지를 더한다.

- **환율·유가 영향도**
  - (a) 과거에 원/달러 환율·유가와 함께 움직인 정도(민감도)로 종목을 고른다.
  - (b) 그 시점의 환율·유가 흐름(올랐는지, 내렸는지)에 맞는 쪽, 즉 수혜주나 피해주를 고른다.
- **테마**
  - 후보 범위를 KIS 테마(예: HBM, 2차전지) 또는 사용자가 직접 만든 종목 묶음으로 좁힌다.

**성공 기준.** 다음 같은 기준을 만들어 1단계와 똑같이 검증하고 결과를 읽을 수 있다.

- "환율에 민감한 수출주 중 거래대금 상위"
- "최근 한 달 환율이 3% 넘게 오르면 환율 수혜주"
- "2차전지 테마 안에서 반등 신호"

### 1.2 대화에서 확정한 것 (2026-10-16)

| 항목 | 결정 |
|---|---|
| 환율·유가 쓰임새 | 민감한 종목 고르기 + 그 시점 흐름에 맞춰 고르기(둘 다) |
| 테마 | KIS 테마 + 직접 만든 묶음(둘 다) |
| 진행 | 남은 세부는 설계자가 정하고 결정 기록(10장)에 기본값과 함께 남긴다. 사용자는 PR 리뷰로 확인한다. |

### 1.3 범위 밖
- 재무·가치(2단계), 투자자 매매동향(3단계).
- 브렌트·두바이 유가, 원/엔 등 다른 계열. 구조는 계열 추가를 허용하지만 이번에는 원/달러와 WTI만 다룬다.
- 테마 편입 이력. KIS가 현재 구성만 준다.

## 2. 데이터

### 2.1 출처

| 데이터 | 출처 | 비고 |
|---|---|---|
| 원/달러 환율(일별) | FRED `DEXKOUS` CSV (`https://fred.stlouisfed.org/graph/fredgraph.csv?id=DEXKOUS`) | 키 필요 없음. 1981년부터. 값 없는 날은 `.` |
| WTI 유가(일별) | FRED `DCOILWTICO` CSV | 1986년부터. 음수 값(2020-04-20)이 있으니 그대로 둔다 |
| KIS 테마 | `theme_code.mst.zip` (`https://new.real.download.dws.co.kr/common/master/`) | 테마 약 300개. **현재 구성만** 있다 |

- 수집은 기존 `pnpm collect`가 함께 한다. Node에서 받으니 CORS와 프록시는 상관없다. 프록시 허용 목록은 바꾸지 않는다.
- FRED와 마스터 파일 요청에는 키를 붙이지 않는다.
- FRED 요청이 실패하면 macro를 빈 계열로 두고 요약에 `환율·유가를 받지 못했어요`를 적는다. 수집은 계속한다.
- `theme_code.mst`의 행 형식(테마코드·테마명·종목코드의 폭)은 실제 파일로 확인해 fixture로 고정한다. 조사 메모(2026-10-16): 앞 3자리가 테마코드, 40자가 테마명, 뒤 7자가 종목코드이고, KIS 예제의 주석은 둘을 뒤바꿔 적었다.

### 2.2 파일 형식 v2

1단계 `MarketDataFile`(v1)에 두 필드를 더한다.

```ts
interface MarketDataFileV2 extends Omit<MarketDataFileV1, 'version'> {
  version: 2;
  macro: {
    usdkrw: { d: string[]; v: number[] };   // FRED 날짜(YYYYMMDD, 미국 날짜) 오름차순, 값 있는 날만
    wti: { d: string[]; v: number[] };
  };
  themes: { code: string; name: string; symbols: string[] }[]; // symbols는 파일에 있는 종목만
}
```

- 검증기(`validateMarketData`)는 version 1과 2를 모두 받는다.
  - 2라면 macro의 `d`와 `v` 길이가 같은지, 날짜가 오름차순인지, 값이 유한한지(WTI는 음수 허용, 환율은 > 0)를 확인한다.
  - themes의 모양도 확인한다.
  - 3 이상이면 `version-newer`다.
- 앱에서 v1 파일은 `macro`와 `themes`가 없는 파일로 다룬다. 이때 환율·유가 조건과 테마 선택은 비활성이고, 그 자리에 `다시 수집하면 쓸 수 있어요`를 보인다.
- `--update`에 v1 파일을 주면 결과는 v2다. macro와 themes는 매번 전체를 새로 받는다. 크기가 작아서다(합쳐서 100KB 안팎).
- 저장소(`store.ts`)에는 작은 보조 키 `current-themes`를 둔다. 테마 목록(code, name, 종목 수)만 담아 화면이 전체 파일을 읽지 않게 한다. 1단계 `current-sectors`와 같은 방식이고, 같은 트랜잭션에서 쓴다.

### 2.3 미래 정보 차단
- FRED 값은 미국 날짜 기준이다. 미국 d일 값은 한국 d+1일 아침에야 알려진다.
- 그래서 재선정일 d의 전 거래일 p에서 계산할 때는 **날짜가 p보다 앞선(< p) FRED 값만** 쓴다.
- 종목의 i번째 봉(날짜 t_i)에 대응하는 계열 값 `m(t_i)`는 "날짜가 t_i보다 앞선 마지막 FRED 값"이다.
- 미국 휴일처럼 값이 없는 날은 직전 값을 그대로 쓴다.

## 3. 환율·유가 조건

### 3.1 민감도(β)
- 종목의 일간 수익률 `r_i = c_i / c_{i-1} − 1`과 같은 날의 계열 변화율 `x_i = m(t_i) / m(t_{i-1}) − 1`로 최근 `betaDays`개 쌍의 회귀 기울기를 구한다(단순 OLS, `β = cov(r, x) / var(x)`).
- **뜻.** 환율(유가)이 1% 오를 때 그 종목이 평균 β% 움직였다는 뜻이다.
- **창.** 종목의 봉을 기준으로 p까지 `betaDays`개를 쓴다.
- **계산하지 않는 경우.** 아래 셋 중 하나면 그 종목의 β가 없고, 조건을 켠 경우 탈락한다.
  - 계열 변화가 0인 날만 있어서 분산이 0인 경우
  - 쌍이 `betaDays × 0.8`개보다 적은 경우
  - macro가 없는 경우
- 계열마다 따로 계산한다. 원/달러와 WTI가 각각 있다.

### 3.2 계열 흐름
- 계열의 최근 흐름은 `trend = m(p) / m(p − lookback 영업일) − 1`이다.
- 영업일은 FRED 날짜 기준이고, p보다 앞선 값만 쓴다.

### 3.3 조건 모델 (`SelectionCriteria.conditions.macro`)

```ts
macro: {
  betaDays: number;                       // (120) 30~250, 두 계열 공통
  usdkrw: MacroSeriesCond;
  wti: MacroSeriesCond;
}
interface MacroSeriesCond {
  beta:  { on: boolean; min: number; max: number };            // (끔, 0.3, 5) 민감도 범위(양 끝 포함)
  trend: { on: boolean; lookback: number; thresholdPct: number; minAbsBeta: number; whenFlat: 'pass' | 'none' };
                                                               // (끔, 20, 3, 0.3, 'pass')
}
```

**민감도 범위(`beta`).**
- β가 [min, max] 안이면 통과한다.
- 쓰임새 예:
  - 수혜주만: min 0.3, max 5
  - 피해주만: min −5, max −0.3
  - 둔감한 종목: min −0.2, max 0.2

**흐름 따라가기(`trend`).**
- `trend ≥ +thresholdPct%`이면 `β ≥ +minAbsBeta`인 종목만 통과한다. 오르는 흐름의 수혜주다.
- `trend ≤ −thresholdPct%`이면 `β ≤ −minAbsBeta`인 종목만 통과한다. 내리는 흐름에서 이득을 보는 쪽이다.
- 그 사이(흐름이 약함)이면 `whenFlat`을 따른다.
  - `'pass'`: 이 조건을 건너뛴다. 다른 조건만으로 고른다.
  - `'none'`: 아무도 통과하지 못해 그 구간은 현금이다.

**함께 켤 때.** `beta`와 `trend`를 같은 계열에서 함께 켜면 둘 다 만족해야 한다. 다른 조건과는 그대로 AND다.

**`values`에 남기는 값.** 선정 이력에서 근거를 보이려고 다음을 남긴다.
- `usdkrwBeta`, `usdkrwTrend`, `wtiBeta`, `wtiTrend`

**정렬.**
- 정렬 기준에 `macroBeta`를 더한다. 계열을 함께 고른다(`rank.series: 'usdkrw' | 'wti'`).
- β가 큰 순서다. 피해주 기준이면 사용자가 `beta` 범위로 거른 뒤 정렬한다.
- 기본 정렬은 그대로 시가총액이다.

### 3.4 미리 계산
- `precompute`에 계열별 정렬 배열(날짜, 값)과 종목별 롤링 β 배열(i번 = i번 봉까지의 창)을 더한다.
- 롤링은 누적합(Σx, Σr, Σxr, Σx²)을 빼고 더하는 방식으로 O(n)에 계산한다.
- `Precomputed.params`에 `betaDays`를 더해, 기준이 다르면 `PrecomputeMismatchError`를 낸다(1단계 규칙과 같음).
- 메모리 영향은 종목당 β 배열 2개다. Float64Array에 NaN을 센티널로 써서 null 박싱을 피한다. 449만 봉 × 2 × 8B ≈ 72MB다.

## 4. 테마와 내 묶음

### 4.1 후보 범위 모델

```ts
pool: {
  markets; types; excludeManaged;
  sectors: string[];   // 1단계
  themes: string[];    // KIS 테마 코드. 빈 배열 = 사용 안 함
  baskets: string[];   // 내 묶음 id. 빈 배열 = 사용 안 함
}
```

- **합집합.** 업종·테마·묶음 가운데 하나라도 고르면, 고른 업종 ∪ 고른 테마의 종목 ∪ 고른 묶음의 종목에 속한 종목만 후보다. 시장·종류·관리종목 필터는 그 위에 AND로 적용한다.
- **아무것도 고르지 않으면** 1단계처럼 전체가 후보다.
- 업종만 고른 기존 기준은 결과가 그대로다.
- **대장주 조건은 업종 기준을 유지한다.** 테마 안 대장주는 이번 범위가 아니다. 테마는 종목이 여러 테마에 겹치기 때문이다.

### 4.2 내 묶음 (새 엔티티, 프로필별)

```ts
interface Basket { id: string; name: string; updatedAt: number; symbols: string[] } // 이름 30자, 종목 1~300
```

- 저장 키는 `p:<id>:baskets`이고, 최대 30개다. 전략·기준과 같은 손상 처리(`repaired`)를 따르고, 내보내기·가져오기에 포함한다.
- 관심 그룹(최대 8종목, 비교 화면용)과는 별개다.
- 편의 기능:
  - "관심 그룹에서 가져오기": 그룹의 종목을 묶음에 복사한다.
  - "테마에서 가져오기": 테마 구성을 복사해 내 묶음으로 고친다.
- 기준이 지워진 묶음을 가리키면 그 묶음은 비어 있는 것으로 보고 경고를 보인다(막지 않음). 편집 화면에서 다시 고를 수 있다.

### 4.3 시점 한계
- KIS 테마와 내 묶음은 **지금 구성**을 과거에도 쓴다.
- 테마나 묶음을 쓴 결과에는 다음 해석 메모를 더한다(`ValidationNote` `'themeSnapshot'`): `테마·내 묶음은 지금 구성을 과거에도 써요. 그때는 없던 종목이 들어 있어 결과가 실제보다 좋게 나올 수 있어요`.

## 5. 화면

### 5.1 후보 범위 구역
- 업종 고르기 아래에 `테마`와 `내 묶음`을 둔다.
- **테마**
  - 검색할 수 있는 목록이다. 행에 이름과 종목 수(파일에 있는 종목 기준)를 보인다.
  - 고른 테마는 칩으로 보이고, 칩마다 지우기 버튼이 있다.
  - 데이터가 v1이면 `다시 수집하면 쓸 수 있어요`를 보이고 선택은 끈다.
- **내 묶음**
  - 내 묶음 목록에서 체크로 고른다. `묶음 관리` 시트에서 만들기·이름 바꾸기·삭제(되돌리기 있음)·종목 추가와 빼기를 한다.
  - 종목 추가는 기존 `AddStockSheet`를 여러 개 추가 모드로 쓴다.
  - "관심 그룹에서 가져오기"와 "테마에서 가져오기"가 있다.
- **요약 줄**: `테마 2·묶음 1`을 기존 `업종 n개` 옆에 붙인다.

### 5.2 조건 구역: `환율·유가` 소구역
- 계열마다(원/달러, WTI) 두 줄을 둔다. 토글, 숫자 칸, 한 줄 설명을 기존 `ConditionRow` 패턴으로 만든다.
  - **민감도**: `환율이 1% 오를 때 주가가 평균 몇 % 움직였는지예요. +면 같이 오르고, −면 반대로 움직여요.` 숫자 칸은 최소·최대다.
  - **흐름 따라가기**: `최근 며칠 동안 환율이 크게 오르면 같이 오르는 종목을, 크게 내리면 반대로 움직이는 종목을 골라요.` 숫자 칸은 기간, 기준 %, 최소 민감도이고, 흐름이 약할 때의 처리는 `이 조건 건너뛰기` / `현금으로 두기` 중에서 고른다.
  - WTI 문구는 `환율`을 `유가`로 바꾼다.
- 공통 `민감도 계산 기간`(betaDays) 칸을 하나 둔다.
- 데이터가 v1이면 소구역 전체를 비활성으로 두고 `다시 수집하면 쓸 수 있어요`를 보인다.

### 5.3 결과
- 선정 이력을 펼쳤을 때 조건값에 β와 흐름을 보인다. 형식은 `원/달러 민감도 0.82 · 최근 20일 +3.4%`다.
- 도움말에 `'themeSnapshot'` 메모를 보인다. 환율·유가 조건을 썼다면 `환율·유가는 미국 날짜 값이라 하루 늦게 반영해요`도 보인다.
- 오늘 기준 선별은 1단계 그대로다.

## 6. 수집 스크립트 변경
- `scripts/fetch-fred.mjs`(새로 만듦): `fetchFredSeries(id, { fetchImpl, from, to })`를 둔다. CSV를 파싱하고 `.` 값은 버린다. 20초 시간 제한과 최대 3번 재시도가 있다.
- `scripts/parse-theme.mjs`(새로 만듦): `parseThemes(bytes) → { code, name, symbols }[]`. 실제 파일 2~3행으로 만든 fixture를 쓴다.
- `collect-market-data.mjs`: 종목 수집 뒤에 macro와 themes를 받아 v2로 쓴다. 테마 종목은 파일에 있는 종목만 남기고, 비어 있는 테마는 버린다.
- 요약 출력에 `환율 n일 · 유가 n일 · 테마 n개`를 더한다.
- 데모 fixture 생성기(`make-demo-market-data.mjs`)는 v2로 만든다.
  - 합성 macro를 넣는다. 일부 종목 수익률이 환율과 상관되게 만들어 β 조건을 테스트할 수 있게 한다.
  - 테마 3개를 넣는다.

| 계열 일부 구간 없음 | 그 구간은 β·흐름을 계산할 수 없어 조건을 켠 경우 탈락한다. 결과 메모 `macroGap`: `일부 기간은 환율·유가 값이 없어 그 조건을 통과한 종목이 없어요` |
| 기준이 가리키는 테마가 새 데이터에 없음 | 빈 테마로 보고 편집 화면에 경고(막지 않음) |
| 지워진 묶음 | 4.2와 같이 처리 |
| 테마·업종·묶음 합집합이 0 | 1단계의 "통과 0개" 규칙대로 그 구간은 현금이다 |

## 9. 테스트
- **β 손계산:** 합성 계열(환율 +1%일 때 종목 +2% → β = 2)로 확인한다. 롤링 창 경계(`betaDays`), 쌍 부족, 분산 0인 경우도 다룬다.
- **미래 정보 차단:**
  - 날짜가 p 이상인 FRED 값을 극단값으로 바꿔도 `selectAt(d)` 결과가 같아야 한다.
  - p 이후 데이터를 잘라도 같아야 한다(1단계 절단 프로브와 같은 방식).
- **흐름 따라가기:** 오름, 내림, 약함 × `whenFlat` 두 값.
- **합집합 후보 범위:**
  - 업종만, 테마만, 묶음만, 셋을 섞은 경우
  - 업종만 고른 기존 기준의 결과가 그대로인지(회귀)
- **형식:**
  - v1·v2 검증, v3는 `version-newer`
  - v1 데이터에서 UI 비활성
  - v1 파일을 `--update`하면 v2
- **수집:** FRED CSV의 `.` 값, 실패 시 빈 계열과 요약 문구, 테마 파싱 fixture, 파일에 없는 종목 제거
- **내 묶음:** 저장, 손상 복구, 한도, 내보내기·가져오기, 관심 그룹·테마에서 가져오기, 지워진 묶음 경고
- **e2e:** v2 데모 파일로 "원/달러 민감도 ≥ 0.3 + 테마 1개"인 기준을 실행하고, 이력에 β 값이 보이는지와 axe 검사를 확인한다.

## 10. 결정 기록 (사용자 리뷰 대상)

| # | 결정 | 이유 | 바꾸려면 |
|---|---|---|---|
| 1 | 환율·유가 출처는 FRED(원/달러 `DEXKOUS`, WTI `DCOILWTICO`) | 키가 필요 없고 이력이 길다. KIS 해외 TR은 실연결 확인이 필요하고 유가 제공 여부도 불확실하다 | 수집기의 `fetch-fred.mjs`만 갈아 끼운다 |
| 2 | 미국 날짜 값은 한국 p보다 **앞선** 날짜만 쓴다(하루 늦게 반영) | 미국 d일 종가는 한국 d+1일 아침에 알려진다 | 없음(미래 정보 차단 원칙) |
| 3 | 영향도 지표는 회귀 기울기 β(기본 120거래일) | "환율 1% → 주가 β%"로 읽기 쉽다. 상관계수는 크기를 말해 주지 않는다 | 상관계수를 추가 조건으로 둘 수 있다 |
| 4 | 흐름이 약할 때 기본은 `이 조건 건너뛰기` | 흐름이 없을 때 전부 현금이 되면 검증 구간이 비어 결과를 읽기 어렵다 | 기준마다 `현금으로 두기`를 고를 수 있다 |
| 5 | 업종·테마·묶음은 합집합(OR), 시장 등 필터는 AND | "반도체 업종 또는 HBM 테마"처럼 넓히는 쓰임새가 자연스럽다. 교집합이 필요하면 내 묶음으로 만든다 | `pool.combine: 'or' | 'and'` 추가 |
| 6 | 대장주는 업종 기준만 | 테마는 종목이 여러 테마에 겹쳐 순위가 모호하다 | 3단계 이후 재검토 |
| 7 | 내 묶음은 관심 그룹과 별개(최대 30개 × 300종목) | 관심 그룹은 비교 화면용이라 8종목 제한이 있다 | — |
| 8 | 계열은 원/달러·WTI 두 개만 | 사용자가 말한 환율·유가에 해당한다. 구조는 계열 추가를 허용한다 | `macro`에 키를 더한다 |
| 9 | v1 데이터도 계속 쓴다(새 기능만 비활성) | 다시 수집하기 전까지 기존 검증을 막지 않는다 | — |
