# 선정 기준 4단계 설계: 환율·유가 영향도와 테마

작성 2026-10-16. 기반 스펙: [선정 기준 검증 1단계](2026-10-16-selection-criteria-validation-design.md). 1단계 스펙의 원칙은 그대로 이어받는다. 과거 시점 선별, 재선정일 전 거래일 p까지의 데이터만 쓰기, ①·② 나란히 계산, 사용자가 직접 수집한 파일 사용이 그것이다.

## 1. 목표와 범위

### 1.1 목적
1단계 선정 기준에 사용자가 평소 보는 기준 두 가지를 더한다.

- **환율·유가 영향도**
  - (a) 과거에 원/달러 환율·유가와 함께 움직인 정도(민감도)로 종목을 고른다.
  - (b) 그 시점의 환율·유가 흐름(올랐는지, 내렸는지)에 맞는 쪽, 즉 수혜주나 피해주를 고른다.
- **테마**
  - 후보 범위를 KIS 테마(예: HBM, 2차전지) 또는 사용자가 직접 만든 종목 묶음으로 좁힌다.

**성공 기준.** 다음 같은 기준을 만들어 1단계와 똑같이 검증하고 결과를 읽을 수 있다.

- "환율에 민감한 수출주 중 거래대금 상위"
- "최근 한 달 환율이 3% 넘게 오르면 환율 수혜주"
- "2차전지 테마 안에서 반등 신호"

### 1.2 대화에서 확정한 것 (2026-10-16)

| 항목 | 결정 |
|---|---|
| 환율·유가 쓰임새 | 민감한 종목 고르기 + 그 시점 흐름에 맞춰 고르기(둘 다) |
| 테마 | KIS 테마 + 직접 만든 묶음(둘 다) |
| 진행 | 남은 세부는 설계자가 정하고 결정 기록(10장)에 기본값과 함께 남긴다. 사용자는 PR 리뷰로 확인한다. |

### 1.3 범위 밖
- 재무·가치(2단계), 투자자 매매동향(3단계).
- 브렌트·두바이 유가, 원/엔 등 다른 계열. 구조는 계열 추가를 허용하지만 이번에는 원/달러와 WTI만 다룬다.
- 테마 편입 이력. KIS가 현재 구성만 준다.

### 2.2 파일 형식 v2

1단계 `MarketDataFile`(v1)에 두 필드를 더한다.

```ts
interface MarketDataFileV2 extends Omit<MarketDataFileV1, 'version'> {
  version: 2;
  macro: {
    usdkrw: { d: string[]; v: number[] };   // FRED 날짜(YYYYMMDD, 미국 날짜) 오름차순, 값 있는 날만
    wti: { d: string[]; v: number[] };
  };
  themes: { code: string; name: string; symbols: string[] }[]; // symbols는 파일에 있는 종목만
}
```

- 검증기(`validateMarketData`)는 version 1과 2를 모두 받는다.
  - 2라면 macro의 `d`와 `v` 길이가 같은지, 날짜가 오름차순인지, 값이 유한한지(WTI는 음수 허용, 환율은 > 0)를 확인한다.
  - themes의 모양도 확인한다.
  - 3 이상이면 `version-newer`다.
- 앱에서 v1 파일은 `macro`와 `themes`가 없는 파일로 다룬다. 이때 환율·유가 조건과 테마 선택은 비활성이고, 그 자리에 `다시 수집하면 쓸 수 있어요`를 보인다.
- `--update`에 v1 파일을 주면 결과는 v2다. macro와 themes는 매번 전체를 새로 받는다. 크기가 작아서다(합쳐서 100KB 안팎). 다만 이때 FRED 요청이 실패하고 이전 파일에 값이 있는 계열이면, 빈 계열로 덮어쓰지 않고 이전 계열을 그대로 두며 경고를 적는다.
- 설정의 시장 데이터 요약 줄은 파일에 실제로 있는 것만 적는다(환율·유가는 `hasMacro`, 테마는 `themeCount > 0` 기준).
  - 둘 다: ` · 환율·유가·테마 포함`
  - 환율·유가만: ` · 환율·유가 포함 · 테마는 다시 수집하면 쓸 수 있어요`
  - 테마만: ` · 테마 포함 · 환율·유가는 다시 수집하면 쓸 수 있어요`
  - 둘 다 없음(v1이거나 비어 있는 v2): ` · 다시 수집하면 환율·유가·테마도 쓸 수 있어요`
- 저장소(`store.ts`)에는 작은 보조 키 `current-themes`를 둔다. 테마 목록(code, name, 종목 수)만 담아 화면이 전체 파일을 읽지 않게 한다. 1단계 `current-sectors`와 같은 방식이고, 같은 트랜잭션에서 쓴다.

### 2.3 미래 정보 차단: 공개 시점 규칙
FRED 값은 관측 날짜와 **실제 공개 시점**이 다르다. 두 계열 모두 일별 관측값을 주 단위로 묶어 공개한다(확인 2026-10-16).
- 원/달러 `DEXKOUS`: 연준 H.10이 출처다. 국가별 데이터는 매주 월요일 오후 4시 15분(미국 동부)에 갱신되고, 지난주의 일별 값을 담는다([H.10 안내](https://www.federalreserve.gov/releases/h10/about.htm)). FRED 페이지에는 관측일 2026-10-09가 갱신일 2026-10-13으로 표시됐다.
- WTI `DCOILWTICO`: EIA Spot Prices가 출처다. 관측일 2026-10-14가 10-15에 갱신됐고, 다음 공개 예정일은 10-21이었다([FRED](https://fred.stlouisfed.org/series/DCOILWTICO)).

그래서 관측값마다 **한국 날짜로 언제부터 알 수 있었는지(`knownFrom`)**를 보수적인 규칙으로 정하고, 재선정일 d의 전 거래일 p에서는 `knownFrom ≤ p`인 값만 쓴다. 규칙은 실제 공개보다 늦게 잡아 미래 정보가 섞이지 않게 한다. 실제보다 며칠 늦게 반영될 뿐이다.

| 계열 | 관측일 t → 한국에서 쓸 수 있는 첫날 `knownFrom(t)` | 근거 |
|---|---|---|
| usdkrw | t가 속한 주(월~일)의 월요일 M에 대해 **M + 9일**(그다음 주 수요일, 한국 날짜) | 다음 주 월요일 16:15 ET는 한국 화요일 05:15다. 미국 월요일 휴일로 공개가 하루 밀리는 경우까지 하루를 더 둔다 |
| wti | t 다음 날 이후 첫 수요일 W에 대해 **W + 2일**(그 주 금요일, 한국 날짜) | EIA 주간 공개가 수요일·목요일에 나간다. 목요일 공개분도 한국 금요일 아침에는 알려진다 |

- 규칙은 앱의 `macroKnownFrom(series, t)` 한 곳에 둔다. 공개 일정이 바뀌면 이 함수만 고친다.
- 데이터 파일에는 관측일만 둔다. 다시 수집하지 않아도 규칙을 바꿀 수 있게 하기 위해서다.
- **두 규칙을 나눈다.** 공개 시점은 "p에서 그 값을 **쓸 수 있는가**"만 정한다. 회귀에서 주가와 짝지을 **기간**은 관측일로 정한다. 공개일로 값을 옮겨 짝지으면 환율이 실제로 움직인 기간과 주가가 움직인 기간이 어긋난다. 그러면 β의 크기는 물론 부호까지 뒤집힐 수 있다(2026-10-16 리뷰 재현: 실제 β +2.0이 −0.40으로 나왔다).
- **기간 맞추기(관측일 기준).** 종목의 i번째 봉(한국 날짜 t_i)에 짝짓는 계열 값 `a(t_i)`는 **관측일이 t_i보다 앞선 마지막 관측값**이다. 미국 정오 매입률(H.10)과 미국 장중 유가는 한국 날짜 t_i의 장 마감(15:30 KST)보다 먼저 정해진 값이기 때문이다. 관측값이 없는 날(미국 휴일)은 직전 관측값을 쓴다.
- **쓸 수 있는가(공개 시점 기준).** `a(t_i)`는 "t_i보다 앞선 **마지막** 관측값"이라, 그 값이 공개됐다는 것만으로는 그 사이에 아직 공개되지 않은 관측값이 없다는 것을 알 수 없다. 그래서 봉 i의 쌍은 **그다음 관측값**(`a(t_i)` 바로 뒤 관측값)의 `knownFrom`이 p 이하일 때만 p에서 쓸 수 있다. 그 관측값의 관측일은 t_i 이후이므로 `a(t_i)`가 확정된다. 다음 관측값이 아직 없으면(계열이 봉보다 일찍 끝남) 그 봉은 쓰지 않는다. `knownFrom`은 관측일이 늦을수록 늦어지므로, p에서 쓸 수 있는 쌍은 앞에서부터 이어진 구간 `i ≤ i*(p)`다. 검증: 계열을 `knownFrom ≤ p`인 관측값만 남겨 잘라도 선별이 같아야 한다.
- 실연결 점검 ㉒에서 FRED 페이지의 갱신일로 규칙을 다시 확인한다(8장).

## 3. 환율·유가 조건

### 3.1 민감도(β)
- 종목의 일간 수익률 `r_i = c_i / c_{i-1} − 1`과 같은 기간의 계열 변화율 `x_i = a(t_i) / a(t_{i-1}) − 1`(2.3의 관측일 기준 짝짓기)로 최근 `betaDays`개 쌍의 회귀 기울기를 구한다(단순 OLS, `β = cov(r, x) / var(x)`).
- **뜻.** 환율(유가)이 1% 오를 때 그 종목이 평균 β% 움직였다는 뜻이다.
- **창.** 2.3의 `i*(p)`까지, 즉 p에서 공개된 관측값으로 만들 수 있는 마지막 쌍까지 `betaDays`개 봉을 쓴다. 롤링 β 배열은 관측일 기준으로 짝지은 쌍으로 한 번 계산하고, p에서는 `i*(p)` 위치의 값을 읽는다. 최근 1~2주는 아직 공개되지 않아 창에 들어가지 않으므로, β는 그만큼 과거에서 끝난다.
- **계산하지 않는 경우.** 아래 셋 중 하나면 그 종목의 β가 없고, 조건을 켠 경우 탈락한다.
  - 계열 변화가 0인 날만 있어서 분산이 0인 경우
  - 쌍이 `betaDays × 0.8`개보다 적은 경우
  - macro가 없는 경우
- 계열마다 따로 계산한다. 원/달러와 WTI가 각각 있다.
- 창 안에서 x ≠ 0인 쌍이 2개보다 적으면 계산하지 않는다(움직임이 멈춘 창에서 누적합 뺄셈 찌꺼기로 β가 생기지 않게).

- **0 이하 값.** 변화율은 두 값이 모두 0보다 클 때만 뜻이 있다. 이전값이 음수면 오른 것도 음의 변화율이 되고(−36.98 → 8.91이면 약 −124%), 0이면 무한대가 된다.
  - `a(t_{i-1}) ≤ 0` 또는 `a(t_i) ≤ 0`인 쌍은 **쌍에서 뺀다**(없는 날과 같게).
  - 변화율이 유한하지 않은 쌍도 뺀다.
  - 롤링 누적합에는 유한한 값만 들어가므로 창에서 빠진 뒤 NaN이 남지 않는다.
  - 실제로 해당하는 날은 WTI 2020-04-20~21뿐이다.
  - `계산하지 않는 경우`의 "쌍이 `betaDays × 0.8`개보다 적은 경우"는 이렇게 뺀 뒤의 쌍 수로 센다.
- **공개 지연의 영향.** 공개가 주 단위라 p에서 쓸 수 있는 마지막 쌍은 p보다 최대 1~2주 앞선다. β는 관측 기간이 맞는 쌍만 쓰므로 부호와 크기는 왜곡되지 않고, 창이 그만큼 과거로 밀릴 뿐이다. 이 한계는 결과 도움말에 적는다(5.3).

### 3.2 계열 흐름
- 계열의 최근 흐름은 **p에서 공개된 관측값끼리** 계산한다: `knownFrom ≤ p`인 마지막 관측값 `o_k`와 그보다 `lookback`개 앞선 관측값 `o_{k−lookback}`으로 `trend = o_k / o_{k−lookback} − 1`. 관측값 순서(미국 영업일) 기준이라, 두 끝이 같은 계열 안에서 실제로 그 기간만큼 떨어져 있다.
- 두 끝 값 중 하나라도 0 이하이면 흐름을 계산하지 않는다. 이때 흐름 따라가기 조건은 통과한 종목이 없고 `macroGap` 메모가 붙는다.

### 3.3 조건 모델 (`SelectionCriteria.conditions.macro`)

```ts
macro: {
  betaDays: number;                       // (120) 30~250, 두 계열 공통
  usdkrw: MacroSeriesCond;
  wti: MacroSeriesCond;
}
interface MacroSeriesCond {
  beta:  { on: boolean; min: number; max: number };            // (끔, 0.3, 5) 민감도 범위(양 끝 포함)
  trend: { on: boolean; lookback: number; thresholdPct: number; minAbsBeta: number; whenFlat: 'pass' | 'none' };
                                                               // (끔, 20, 3, 0.3, 'pass')
}
```

**민감도 범위(`beta`).**
- β가 [min, max] 안이면 통과한다.
- 쓰임새 예:
  - 수혜주만: min 0.3, max 5
  - 피해주만: min −5, max −0.3
  - 둔감한 종목: min −0.2, max 0.2

**흐름 따라가기(`trend`).**
- `trend ≥ +thresholdPct%`이면 `β ≥ +minAbsBeta`인 종목만 통과한다. 오르는 흐름의 수혜주다.
- `trend ≤ −thresholdPct%`이면 `β ≤ −minAbsBeta`인 종목만 통과한다. 내리는 흐름에서 이득을 보는 쪽이다.
- 그 사이(흐름이 약함)이면 `whenFlat`을 따른다.
  - `'pass'`: 이 조건을 건너뛴다. 다른 조건만으로 고른다.
  - `'none'`: 아무도 통과하지 못해 그 구간은 현금이다.

**막는 입력.**
- `beta`를 켠 계열에서 `min > max`이면 막는다(`원/달러 민감도 범위의 최소가 최대보다 커요`, `유가 민감도 범위의 최소가 최대보다 커요`). `min == max`는 통과한다.
- 데이터에 macro가 없는데 정렬이 `macroBeta`이면 정렬 구역에서 `이 데이터에는 환율·유가가 없어요`로 막는다. 조건 구역에 같은 문구가 이미 있으면 한 번만 보인다.

**함께 켤 때.** `beta`와 `trend`를 같은 계열에서 함께 켜면 둘 다 만족해야 한다. 다른 조건과는 그대로 AND다.

**`values`에 남기는 값.** 선정 이력에서 근거를 보이려고 다음을 남긴다.
- `usdkrwBeta`, `usdkrwTrend`, `wtiBeta`, `wtiTrend`

**정렬.**
- 정렬 기준에 `macroBeta`를 더한다. 계열을 함께 고른다(`rank.series: 'usdkrw' | 'wti'`).
- β가 큰 순서다. 피해주 기준이면 사용자가 `beta` 범위로 거른 뒤 정렬한다.
- 기본 정렬은 그대로 시가총액이다.

### 3.4 미리 계산
- `precompute`에 계열별 정렬 배열(날짜, 값)과 종목별 롤링 β 배열(i번 = i번 봉까지의 창)을 더한다.
- 롤링은 누적합(Σx, Σr, Σxr, Σx²)을 빼고 더하는 방식으로 O(n)에 계산한다.
- `Precomputed.params`에 `betaDays`를 더해, 기준이 다르면 `PrecomputeMismatchError`를 낸다(1단계 규칙과 같음).
- β는 환율·유가 조건을 켰거나 정렬이 `macroBeta`일 때만 계산한다. 쓰지 않으면 `params.betaDays`는 `null`이다(1단계 `maPeriod`와 같은 방식).
- 봉마다 쌍에 쓴 관측값의 인덱스(`Int32Array`, 없으면 −1)를 두고, 그 `knownFrom`은 계열의 정렬 배열에서 읽는다. `selectAt`은 이 둘로 `i*(p)`를 이분 탐색한다.
- 메모리 영향은 종목당 β 배열 2개다. Float64Array에 NaN을 센티널로 써서 null 박싱을 피한다. 449만 봉 × 2 × 8B ≈ 72MB다.

## 4. 테마와 내 묶음

### 4.1 후보 범위 모델

```ts
pool: {
  markets; types; excludeManaged;
  sectors: string[];   // 1단계
  themes: string[];    // KIS 테마 코드. 빈 배열 = 사용 안 함
  baskets: string[];   // 내 묶음 id. 빈 배열 = 사용 안 함
}
```

- **합집합.** 업종·테마·묶음 가운데 하나라도 고르면, 고른 업종 ∪ 고른 테마의 종목 ∪ 고른 묶음의 종목에 속한 종목만 후보다. 시장·종류·관리종목 필터는 그 위에 AND로 적용한다.
- **아무것도 고르지 않으면** 1단계처럼 전체가 후보다.
- 업종만 고른 기존 기준은 결과가 그대로다.
- **대장주 조건은 업종 기준을 유지한다.** 테마 안 대장주는 이번 범위가 아니다. 테마는 종목이 여러 테마에 겹치기 때문이다.

### 4.2 내 묶음 (새 엔티티, 프로필별)

```ts
interface Basket { id: string; name: string; updatedAt: number; symbols: string[] } // 이름 30자, 종목 1~300
```

- 저장 키는 `p:<id>:baskets`이고, 최대 30개다. 쓸 때 종목 0개·300개 초과·이름 30자 초과는 거절한다(읽을 때 조용히 사라지지 않게). 전략·기준과 같은 손상 처리(`repaired`)를 따르고, 내보내기·가져오기에 포함한다.
- 관심 그룹(최대 8종목, 비교 화면용)과는 별개다.
- 편의 기능:
  - "관심 그룹에서 가져오기": 그룹의 종목을 묶음에 복사한다.
  - "테마에서 가져오기": 테마 구성을 복사해 내 묶음으로 고친다.
- 기준이 지워진 묶음을 가리키면 그 묶음은 비어 있는 것으로 보고 경고를 보인다(막지 않음). 편집 화면에서 다시 고를 수 있다.

### 4.3 시점 한계
- KIS 테마와 내 묶음은 **지금 구성**을 과거에도 쓴다.
- 테마나 묶음을 쓴 결과에는 다음 해석 메모를 더한다(`ValidationNote` `'themeSnapshot'`): `테마·내 묶음은 지금 구성을 과거에도 써요. 그때는 없던 종목이 들어 있어 결과가 실제보다 좋게 나올 수 있어요`.

## 5. 화면

### 5.1 후보 범위 구역
- 업종 고르기 아래에 `테마`와 `내 묶음`을 둔다.
- **테마**
  - 검색할 수 있는 목록이다. 행에 이름과 종목 수(파일에 있는 종목 기준)를 보인다.

  - 데이터가 v1이면 `다시 수집하면 쓸 수 있어요`를 보이고 선택은 끈다.
- **내 묶음**
  - 내 묶음 목록에서 체크로 고른다. `묶음 관리` 시트에서 만들기·이름 바꾸기·삭제(되돌리기 있음)·종목 추가와 빼기를 한다.
  - 종목 추가는 기존 `AddStockSheet`를 여러 개 추가 모드로 쓴다.
  - "관심 그룹에서 가져오기"와 "테마에서 가져오기"가 있다.
- **요약 줄**: `테마 2·묶음 1`을 기존 `업종 n개` 옆에 붙인다.

### 5.2 조건 구역: `환율·유가` 소구역
- 계열마다(원/달러, WTI) 두 줄을 둔다. 토글, 숫자 칸, 한 줄 설명을 기존 `ConditionRow` 패턴으로 만든다.
  - **민감도**: `환율이 1% 오를 때 주가가 평균 몇 % 움직였는지예요. +면 같이 오르고, −면 반대로 움직여요.` 숫자 칸은 최소·최대다.
  - **흐름 따라가기**: `최근 며칠 동안 환율이 크게 오르면 같이 오르는 종목을, 크게 내리면 반대로 움직이는 종목을 골라요.` 숫자 칸은 기간, 기준 %, 최소 민감도이고, 흐름이 약할 때의 처리는 `이 조건 건너뛰기` / `현금으로 두기` 중에서 고른다.
  - WTI 문구는 `환율`을 `유가`로 바꾼다.
- 공통 `민감도 계산 기간`(betaDays) 칸을 하나 둔다.
- 데이터가 v1이면 소구역 전체를 비활성으로 두고 `다시 수집하면 쓸 수 있어요`를 보인다.

### 5.3 결과
- 선정 이력을 펼쳤을 때 조건값에 β와 흐름을 보인다. 형식은 `원/달러 민감도 0.82 · 최근 20일 +3.4%`다.
- 도움말에 `'themeSnapshot'` 메모를 보인다. 환율·유가 조건을 썼다면 `환율·유가는 매주 묶어서 공개돼 최근 1~2주는 반영되지 않아요`도 보인다.
- 오늘 기준 선별은 1단계 그대로다.

## 9. 테스트
- **β 손계산:** 합성 계열(환율 +1%일 때 종목 +2% → β = 2)로 확인한다. 롤링 창 경계(`betaDays`), 쌍 부족, 분산 0인 경우도 다룬다.
- **미래 정보 차단(공개 시점 포함):**
  - `macroKnownFrom` 표 테스트: 원/달러는 월~금 관측 각각, 월요일·일요일 경계. WTI는 수요일 관측과 그다음 날 관측.
  - **아직 공개되지 않은 값**, 즉 `knownFrom > p`인 관측값(관측일이 p보다 앞서도)을 극단값으로 바꿔도 `selectAt(d)` 결과가 같아야 한다.
  - p 이후 데이터를 잘라도 같아야 한다(1단계 절단 프로브와 같은 방식).
  - **기간 맞추기:** 환율이 한 주는 매일 +1%, 다음 주는 매일 −1%를 반복하고 주가가 관측 기간 기준 변화율의 정확히 2배로 움직이는 합성 계열에서, p를 충분히 뒤에 두면 β = +2.0이다(공개일로 옮겨 짝지으면 약 −0.40이 되는 리뷰 재현). `i*(p)` 위치를 읽는지도 확인한다.
- **0 이하 값:** WTI −36.98 → 8.91 쌍은 빠지고 β가 유한하다. 이전값 0인 쌍도 빠진다. 끝값이 음수면 흐름을 계산하지 않고 `macroGap`이다.
- **흐름 따라가기:** 오름, 내림, 약함 × `whenFlat` 두 값.
- **합집합 후보 범위:**
  - 업종만, 테마만, 묶음만, 셋을 섞은 경우
  - 업종만 고른 기존 기준의 결과가 그대로인지(회귀)
- **형식:**
  - v1·v2 검증, v3는 `version-newer`
  - v1 데이터에서 UI 비활성
  - v1 파일을 `--update`하면 v2
- **수집:** FRED CSV의 `.` 값, 실패 시 빈 계열과 요약 문구, 테마 파싱 fixture, 파일에 없는 종목 제거
- **내 묶음:** 저장, 손상 복구, 한도, 내보내기·가져오기, 관심 그룹·테마에서 가져오기, 지워진 묶음 경고
- **e2e:** v2 데모 파일로 "원/달러 민감도 ≥ 0.3 + 테마 1개"인 기준을 실행하고, 이력에 β 값이 보이는지와 axe 검사를 확인한다.
