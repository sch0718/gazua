# 선정 기준 2단계 설계: 재무·가치

작성 2026-10-17. 기반 스펙은 [1단계](2026-10-16-selection-criteria-validation-design.md), [4단계 환율·유가와 테마](2026-10-16-macro-theme-criteria-design.md), [3단계 투자자 매매동향](2026-10-16-investor-flow-criteria-design.md)이다. 앞 단계의 원칙은 그대로 이어받는다.

- 과거 시점에서 선별한다.
- 재선정일의 전 거래일 p까지 알려진 정보만 쓴다.
- 사용자가 직접 수집한 파일을 쓴다.
- 데이터가 없는 파일에서는 새 조건을 끈 채 안내한다.

## 1. 목표와 범위

### 1.1 목적
선정 기준에 재무·가치 조건(PER·PBR, ROE·영업이익률, 매출·영업이익 증가율, 부채비율, 흑자)과 재무 순 정렬을 더한다.

성공 기준: 다음 같은 기준을 만들어 1단계와 똑같이 검증하고 결과를 읽을 수 있다.
- "PER 10 이하이면서 ROE 10% 이상"
- "영업이익이 1년 새 20% 넘게 늘어난 흑자 기업 중 PBR 낮은 순 10개"

### 1.2 대화에서 확정한 것 (2026-10-17)

| 항목 | 결정 |
|---|---|
| 지표 | 가치(PER·PBR), 수익성(ROE·영업이익률), 성장(매출·영업이익 증가율), 안정성(부채비율·흑자). 모두 |
| 출처 | KIS 재무 TR만 쓴다. DART는 쓰지 않는다 |
| 공시 시점 | 공시일이 없으므로 보수적 지연 규칙(2.3)을 쓴다 |
| 실적 기준 | 최근 4분기 합(TTM). 성장률은 TTM을 1년 전 TTM과 비교한다 |

### 1.3 범위 밖
- DART 공시일, 연결·별도 구분 선택, 업종별 상대 지표(업종 평균 대비 PER)는 넣지 않는다.
- 배당·현금흐름 지표는 넣지 않는다.
- 재무를 매매 규칙(②)의 신호로 쓰지 않는다.

## 2. 데이터

### 2.1 출처
- KIS 국내주식 재무 TR 두 개를 쓴다.
  - 손익계산서 `FHKST66430200`: 매출액, 영업이익, 당기순이익
  - 대차대조표 `FHKST66430100`: 자본총계, 부채총계
- 둘 다 연간(`FID_DIV_CLS_CODE` 0)과 분기(1)를 받는다. 연간은 결산월을 알아내고 4분기 값을 구하는 데만 쓴다.
- **분기 손익은 회계연도 첫날부터의 누적값으로 가정한다.** 분기 값은 다음과 같이 차분해서 구한다.
  - 같은 회계연도의 직전 누적값을 뺀다.
  - 결산월 분기(4분기)는 연간 값에서 같은 회계연도 마지막 분기 이전 누적값을 뺀다.
  - 대차대조표 값은 분기말 시점 값이라 차분하지 않는다.
- **결산월.** 연간 행의 `stac_yymm`이 그 회계연도의 마지막 분기다. 종목 하나에 결산월을 하나만 두지 않고, **분기마다 연간 결산 분기인지(`a`)를 기록한다.** 그래서 결산월을 바꾼 기업(예: 3월 → 12월)의 과거 연간 분기도 +100일 규칙을 그대로 지킨다(PR #16 리뷰, 결정 D8). 회계연도 경계도 연간 행으로 정하므로, 결산월 변경으로 생긴 짧은 회계연도도 같은 차분 규칙으로 처리한다. 12월이 아닌 결산 법인도 같다.
- **실연결 점검 ㉕에서 확인할 가정.** 아래 값은 `scripts/fetch-fundamentals.mjs`의 상수 한 곳(`FIN_API`)에 가정값으로 두고, 점검 결과에 맞춰 바꾼다.
  - 경로와 필드 이름
  - 금액 단위: 억 원으로 가정한다
  - 누적 여부
  - 과거 깊이: 몇 분기까지 주는지
- 수집은 기존 KIS 클라이언트(초당 호출 제한, 재시도, 비밀값 가리기)를 쓴다. **프록시 허용 목록은 바꾸지 않는다.**

### 2.2 파일 형식 v4
v3에 종목별 `fin`을 더한다.

```ts
interface FinSeries {
  q: string[];    // 분기말 YYYYMM, 엄격히 오름차순, 연속(빠진 분기 없음)
  a: number[];    // 분기마다 1 = 그 분기가 회계연도 마지막(연간 결산) 분기, 0 = 아님. 결산월 변경을 보존한다
  rev: number[];  // 그 분기 하나의 매출액(억 원)
  op: number[];   // 그 분기 하나의 영업이익(억 원)
  ni: number[];   // 그 분기 하나의 당기순이익(억 원)
  eq: number[];   // 분기말 자본총계(억 원)
  debt: number[]; // 분기말 부채총계(억 원)
}
// stocks[k].fin?: FinSeries
interface MarketDataFileV4 extends Omit<MarketDataFileV3, 'version'> { version: 4 }
```

- **연속성.** `q`는 3개월 간격으로 이어진다. 수집에서 중간 분기가 빠지면 0으로 채우지 않는다. 빠진 분기 앞을 버려 연속 구간만 남긴다(3단계 F3과 같은 원칙).
- **값.** 모두 유한한 수다. 소수 둘째 자리까지 반올림한다. 손익은 음수일 수 있다.
- **검증.** 다음을 지키지 않으면 `corrupt`다.
  - `q`가 1개 이상이고 형식·오름차순·3개월 간격이 맞는다.
  - `a`의 값이 0 또는 1이다.
  - 여섯 배열(`a`·`rev`·`op`·`ni`·`eq`·`debt`)의 길이가 `q`와 같다.
  - 값이 유한하다.
- **호환.** v1~v3를 그대로 받는다. 5 이상은 `version-newer`다.
- **저장소 요약.** `info()`에 `hasFin`(재무가 있는 종목이 하나라도 있다)과 `finStocks`를 더한다. 데이터 요약은 ` · 재무 포함`을 붙인다.

### 2.3 미래 정보 차단: 공시 시점 규칙
- **알려진 날(`finKnownFrom`).** 분기말 날짜(그 달 말일)에 아래 날수를 더한 날이다. 연간 결산 분기인지는 그 분기의 `a`로 정한다(종목의 현재 결산월로 다시 계산하지 않는다).
  - 연간 결산 분기(`a` = 1, 4분기·연간 실적): **+100일**
  - 그 밖의 분기: **+60일**
- 법정 기한(분기·반기 45일, 사업보고서 90일)에 늦은 공시를 감안한 여유를 더한 값이다.
- **사용 가능.** 분기 k는 `finKnownFrom(k) < p`일 때만 쓴다. p는 재선정일 d의 전 거래일이다.
- **4분기 값의 사용 시점.** 4분기 값은 연간 값에서 차분하므로, 그 분기는 +100일이 지나야 쓸 수 있다. 그 전까지 TTM은 3분기까지의 연속 4개 분기로 계산한다.
- **TTM.** p에 쓸 수 있는 마지막 분기 L에서 거꾸로 4개 분기 [L−3, L]가 모두 있어야 계산한다. 1년 전 TTM은 [L−7, L−4]다. 모자라면 계산 불가다.
- 예시(12월 결산 기업)
  - 2025년 연간(4분기) 실적: 2025-12-31 + 100일 = 2026-04-10. 그날 이후의 p부터 쓴다.
  - 2026년 1분기 실적: 2026-03-31 + 60일 = 2026-05-30부터 쓴다.

### 2.4 시가총액
- PER·PBR의 시가총액은 `p 종가 × 상장주식수`다.
- 종가는 수정주가이고 상장주식수는 수집일 값이다. 그래서 액면분할·병합은 서로 상쇄되지만, 증자·감자로 주식 수가 실제로 바뀐 종목은 과거 시가총액이 어긋난다. 결과 메모 `finShares`로 안내한다(결정 D3).

## 3. 조건과 정렬

### 3.1 지표 (p 기준, 2.3으로 알려진 분기만)

| 키 | 지표 | 계산 | 계산 불가 |
|---|---|---|---|
| `per` | PER | 시가총액 ÷ (TTM 순이익 × 1e8) | TTM 순이익 ≤ 0, 상장주식수 ≤ 0 |
| `pbr` | PBR | 시가총액 ÷ (L 분기말 자본 × 1e8) | 자본 ≤ 0, 상장주식수 ≤ 0 |
| `roe` | ROE(%) | TTM 순이익 ÷ ((L 자본 + L−4 자본) / 2) × 100 | 평균 자본 ≤ 0, L−4 없음 |
| `opMargin` | 영업이익률(%) | TTM 영업이익 ÷ TTM 매출 × 100 | TTM 매출 ≤ 0 |
| `revGrowth` | 매출 증가율(%) | (TTM 매출 ÷ 1년 전 TTM 매출 − 1) × 100 | 1년 전 값 ≤ 0, 8분기 부족 |
| `opGrowth` | 영업이익 증가율(%) | (TTM 영업이익 ÷ 1년 전 TTM 영업이익 − 1) × 100 | 1년 전 값 ≤ 0, 8분기 부족 |
| `debtRatio` | 부채비율(%) | L 부채 ÷ L 자본 × 100 | 자본 ≤ 0 |
| `profitable` | 흑자 | TTM 순이익 > 0 | TTM 계산 불가 |

- p에 종목 봉이 없거나 종가가 없으면 PER·PBR은 계산 불가다. **상장주식수가 0 이하이면(수집기가 마스터에서 읽지 못하면 0을 쓴다) 시가총액이 0이 되어 PER·PBR 0으로 저평가 조건을 통과하므로, 계산 불가로 둔다**(PR #16 리뷰, 결정 D9). 시가총액이 필요하지 않은 지표는 봉과 무관하게 계산하지만, 선정은 기존 규칙대로 p에 봉이 있는 종목만 대상으로 한다.

### 3.2 조건 모델 (`SelectionCriteria.conditions.fin`)

```ts
fin: {
  per: { on: boolean; min: number; max: number };
  pbr: { on: boolean; min: number; max: number };
  roe: { on: boolean; min: number };
  opMargin: { on: boolean; min: number };
  revGrowth: { on: boolean; min: number };
  opGrowth: { on: boolean; min: number };
  debtRatio: { on: boolean; max: number };
  profitable: { on: boolean };
}
type FinMetric = 'per' | 'pbr' | 'roe' | 'opMargin' | 'revGrowth' | 'opGrowth';
rank: { …; fin?: { metric: FinMetric } }  // rank.by에 'fin'을 더한다
```

| 항목 | 기본값 | 범위 |
|---|---|---|
| `per` | 끔, 0 ~ 15 | 0 ~ 1000 |
| `pbr` | 끔, 0 ~ 1.5 | 0 ~ 100 |
| `roe` | 끔, min 10 | −100 ~ 100 |
| `opMargin` | 끔, min 5 | −100 ~ 100 |
| `revGrowth` | 끔, min 10 | −100 ~ 1000 |
| `opGrowth` | 끔, min 20 | −100 ~ 1000 |
| `debtRatio` | 끔, max 100 | 0 ~ 10000 |
| `profitable` | 끔 | — |
| `rank.fin` | `metric` `'per'` | — |

- **통과 조건.** 켠 조건을 모두 만족하면 통과다. 범위는 경계를 포함한다. 계산 불가인 종목은 그 조건에서 탈락한다.
- **재무 순 정렬.** `rank.by === 'fin'`이면 `rank.fin.metric`으로 정렬한다.
  - `per`·`pbr`은 낮은 순, 나머지는 높은 순이다.
  - 계산 불가 종목은 정렬과 통과 수에서 모두 뺀다(3단계 P6과 같다).
- **기존 프로필.** `fin`·`rank.fin`이 없는 기존 프로필은 기본값으로 조용히 채운다(`repaired=false`). 범위를 벗어난 값은 고친다(`repaired=true`). 최소가 최대보다 큰 범위는 고치지 않고 막는 경고로 둔다.

### 3.3 막는 경고 (`criteriaIssues`)
- `per`나 `pbr`이 켜져 있고 min > max이면 실행을 막는다. 문구는 `PER 범위의 최소가 최대보다 커요` 또는 `PBR 범위의 최소가 최대보다 커요`다.
- 재무가 없는 데이터(`hasFin` false)에서 재무 조건을 켰거나 `rank.by === 'fin'`이면 실행을 막는다.
  - 문구: `이 데이터에는 재무 정보가 없어요`
  - 재무 조건이 켜져 있으면 `conditions` 구역에, 정렬만 재무 순이면 `rank` 구역에 한 번만 보인다(3단계 P7과 같다).
- `dataInfo.hasFin`은 필수 필드다.

### 3.4 미리 계산
- 재무를 쓸 때만(`usesFin`) 계산한다.
- 종목마다 다음을 만든다.
  - 분기별 `finKnownFrom` 날짜 배열
  - 매출·영업이익·순이익의 분기 누적합(`Float64Array`, 길이 n+1)
- p마다 쓸 수 있는 마지막 분기 L은 이진 탐색으로 찾는다. 그러면 TTM과 1년 전 TTM이 O(1)이다.
- 분기 수는 종목당 수십 개라 메모리 부담이 거의 없다.
- `params.fin`은 `{ used: true }` 또는 null이다. 기준과 맞지 않으면 `PrecomputeMismatchError`다.

## 4. 화면

### 4.1 조건 구역: `재무·가치` 소구역
- 위치: `투자자 매매동향` 소구역 아래. 구조·접근성 처리는 `FlowConditions`와 같다.
- 네 묶음으로 나눈다.
  - `가치`: PER(최소~최대), PBR(최소~최대)
  - `수익성`: ROE(최소 %), 영업이익률(최소 %)
  - `성장`: 매출 증가율(최소 %), 영업이익 증가율(최소 %)
  - `안정성`: 부채비율(최대 %), 흑자
- 공통 안내: `재무는 공시가 늦을 수 있어 분기 결산 60일, 연간 결산 100일 뒤부터 써요`
- PER 설명: `주가가 1년 순이익의 몇 배인지예요. 적자 기업은 빠져요`
- 증가율 설명: `최근 4분기 합을 1년 전 4분기 합과 비교해요`
- 재무가 없는 데이터에서는 다음과 같다.
  - 토글은 `aria-disabled`이고, `다시 수집하면 쓸 수 있어요`를 `aria-describedby`로 잇는다.
  - 켜기만 막고, 이미 켜진 조건은 끌 수 있다. 끈 뒤에도 포커스는 토글에 남는다.
- 접힌 구역에 범위를 벗어난 값이 있으면 실행을 막고, 구역을 펼쳐 그 칸으로 포커스한다.

### 4.2 정렬
- 정렬 고르기에 `재무 순`을 더한다. 고르면 지표 고르기가 나온다.
- 지표 이름: `PER 낮은 순`, `PBR 낮은 순`, `ROE 높은 순`, `영업이익률 높은 순`, `매출 증가율 높은 순`, `영업이익 증가율 높은 순`
- 재무가 없는 데이터의 막는 경고는 3.3과 같다.

### 4.3 기준 목록 한 줄 요약
켠 재무 조건을 넣는다. 예: `PER 0~15 · ROE 10%↑ · 부채비율 100%↓ · 흑자`. 3단계에서 고친 누락이 반복되지 않게 한다.

### 4.4 결과
- **선정 이력**(행을 펼쳤을 때): 켠 조건과 정렬에 쓴 값을 보인다.
  - 예: `PER 8.3 · ROE 14.2% · 부채비율 62% (2026년 2분기까지)`
  - 괄호에는 그 재선정일에 쓴 마지막 분기 L을 `YYYY년 N분기`로 적는다. N은 결산월 기준 회계 분기가 아니라 달력 분기 `ceil(분기말 월 ÷ 3)`이다. 예: 2월 말 → 1분기, 5월 말 → 2분기, 11월 말 → 4분기.
  - 소수 한 자리이고, 음수는 `−`로 쓴다.
- **결과 도움말 메모**
  - `finLag`(재무를 쓸 때 늘): `재무는 분기 결산 60일, 연간 결산 100일 뒤부터 써요`
  - `finShares`(PER·PBR을 쓸 때): `PER·PBR의 시가총액은 지금 상장주식수로 계산해서, 과거에 증자한 종목은 값이 조금 클 수 있어요`
  - `finGap`(어떤 재선정일에 재무 때문에 후보 전체가 계산 불가일 때): `재무 데이터가 없는 구간이 있어 그 재선정일에는 고른 종목이 없거나 적어요`
- **실행 오류** `no-fin`: 문구는 3.3과 같다.

## 5. 수집 스크립트 변경
- **새 파일 `scripts/fetch-fundamentals.mjs`**
  - `FIN_API` 상수를 둔다.
  - `fetchFundamentals(client, symbol)`은 연간·분기 손익과 대차대조표를 받는다. 종목당 4번 호출한다.
  - `buildFin(rows)`은 받은 행을 `FinSeries`로 바꾼다.
    - 결산월을 판단한다.
    - 누적 손익을 차분한다.
    - 4분기는 연간 값에서 구한다.
    - 연속 구간만 남긴다.
    - 소수 둘째 자리로 반올림한다.
- **`collect-market-data.mjs`**
  - 일봉·수급 다음에 종목마다 재무를 받아 v4로 쓴다.
  - 실패 처리는 3단계 수급과 같다.
    - 종목 하나가 실패하면 그 종목만 `fin`을 비운다.
    - 치명적이지 않은 실패가 20번 이어지면 남은 종목의 재무 받기를 멈춘다. 파일은 그래도 쓴다.
    - 치명 오류(401/403)는 멈추고 partial을 남긴다.
    - 절반 넘게 실패하면 경고한다.
  - 새 옵션 `--no-fins`를 둔다.
  - `--update`
    - 재무를 다시 받아 덮어쓴다. 재무 TR은 기간 인자 없이 최근 이력을 통째로 주므로 겹쳐 받기가 따로 필요 없다.
    - 받은 이력이 이전 `fin`보다 짧으면 이전 분기를 앞에 이어 붙인다(연속일 때만). 이어 붙인 분기는 이전 파일의 `a`를 그대로 쓴다(지금 결산월로 다시 정하지 않는다).
    - 실패하면 이전 `fin`을 유지한다.
  - partial 이어받기는 3단계처럼 `kind:'fin'` 줄을 쓴다.
  - 요약 줄에 `재무 N종목 · 최초 YYYY년 N분기`를 더한다.
- **`make-demo-market-data.mjs`**: v4를 만들고 설계한 재무 종목을 넣는다.
  - 저PER·저PBR 3종목(PER 약 5, PBR 약 0.6)
  - 고ROE·고이익률 2종목(ROE 약 25%, 영업이익률 약 20%)
  - 고성장 2종목(매출 약 +40%/년, 영업이익 약 +60%/년)
  - 적자 1종목
  - 재무가 데모 기간 중간부터 시작하는 1종목
  - 나머지 종목은 평범한 값(PER 15~40)이다.
  - 결정적으로 만들고, 설계 코드를 상수로 내보낸다. 앞 단계의 데이터는 바꾸지 않는다.
- 키는 `KIS_APP_KEY`·`KIS_APP_SECRET`에서만 읽는다. 요청 URL·로그·오류·partial·출력 파일에 넣지 않는다.

## 6. 오류·예외

| 상황 | 동작 |
|---|---|
| v1~v3 파일 | 열린다. 재무 조건은 끈 채 `다시 수집하면 쓸 수 있어요` |
| 재무 없는 데이터에서 재무 기준 실행 | 화면이 막고, Worker는 `no-fin`으로 거절한다 |
| 공개된 분기가 4개(성장률은 8개) 미만 | 그 지표는 계산 불가로 탈락하고 정렬에서 빠진다. 후보 전체가 그렇게 비면 `finGap` |
| 적자·자본잠식 | 3.1 표대로 계산 불가로 탈락한다 |
| 파일의 `fin` 형식 오류 | `corrupt` |
| 수집 중 종목 실패 | 그 종목만 비우고 계속한다. 끝에 경고 |
| 누적이 아닌데 차분한 경우 | ㉕에서 발견하면 `FIN_API.cumulative`를 false로 바꾼다. 코드는 두 경우를 모두 지원한다 |

## 8. 테스트
- **형식**
  - v4 검증: `q` 형식·간격, `a`(0·1), 길이, 유한 값
  - `fin` 없는 종목은 정상
  - v1~v3 호환, 5 이상 거절
- **수집** (주입한 가짜 클라이언트로)
  - `buildFin`: 12월 결산과 3월 결산 각각의 누적 차분, 4분기 = 연간 − 3분기 누적, 빠진 분기 앞 버리기, `cumulative:false` 경로
  - 종목 실패 시 계속하기, 연속 20번 실패 시 멈추고 파일 쓰기, 치명 오류 시 중단
  - `--no-fins`
  - `--update`: 덮어쓰기와 앞 이어 붙이기, 실패 시 이전 값 유지
  - 이어받기
  - 키가 노출되지 않음
- **계산**
  - `finKnownFrom` 표 테스트: 12월·3월 결산, 각 분기, 말일, 윤년
  - 3.1의 지표를 직접 계산한 값과 비교한다. 경계와 계산 불가를 포함한다.
  - **미래 정보 누출 검사**: `finKnownFrom ≥ p`인 분기 값을 ×1000·부호 반전·잘라내기로 바꿔도 모든 재선정일의 선정이 같다. 알려진 마지막 분기를 바꾸면 선정이 달라진다.
  - 재무를 쓰지 않는 기준의 결과는 기준선 파일과 같다.
- **기준 모델**: 기본값, 범위, 막는 경고, 기존 프로필 채우기, 내보내기·가져오기 왕복.
- **화면**
  - 소구역의 토글과 칸
  - v1~v3에서 비활성이고 포커스가 유지되는지
  - 접힌 구역 차단
  - `재무 순` 정렬
  - 목록 한 줄 요약
  - 이력 값 형식과 분기 표기
  - 메모 세 가지
- **e2e** (4개 프로젝트)
  - v4 데모를 가져와 PER 0~10으로 미리 보기·실행을 한다.
  - 고른 종목이 모두 설계한 저PER 종목인지 확인한다(설계 코드는 import한다).
  - 이력 값 `PER x.x` 형식을 확인한다.
  - `finLag` 메모를 확인한다.
  - axe 검사를 한다.

## 9. 결정 기록 (사용자 리뷰 대상)

| # | 결정 | 이유 | 바꾸면 |
|---|---|---|---|
| D1 | 공시 지연은 분기 +60일, 연간 +100일 | 법정 기한(45·90일)에 지연 공시 여유를 더했다. 공시일이 없어 보수적으로 잡는다 | ㉕나 DART로 실제 분포를 보면 줄일 수 있다 |
| D2 | TTM과 1년 전 TTM은 연속 분기로만 계산 | 빠진 분기를 0으로 보면 실적이 왜곡된다 | 데이터가 짧은 종목은 성장률이 늦게 나온다 |
| D3 | 시가총액은 p 수정종가 × 수집일 상장주식수 | 과거 상장주식수가 없다. 분할은 상쇄된다 | 증자 종목의 과거 PER·PBR이 다소 크다. 메모로 안내한다 |
| D4 | ROE 분모는 L과 L−4 자본의 평균 | 기말 자본만 쓰면 증자 직후 ROE가 낮게 나온다 | L−4가 없으면 계산 불가 |
| D5 | 영업이익 증가율은 1년 전 값이 0 이하이면 계산 불가 | 적자에서 흑자 전환은 비율이 무의미하다 | 흑자 전환 종목은 `흑자` 조건으로 고른다 |
| D6 | 재무 순 정렬의 계산 불가 종목은 통과 수에서도 뺀다 | 3단계 P6과 같다 | — |
| D7 | 분기 표기는 달력 분기 `ceil(월 ÷ 3)` | 결산월이 다른 종목도 한 줄로 비교하기 쉽다. 2·5·8·11월 말 분기도 정수가 된다 | 결산 분기와 다를 수 있다(3월 결산의 6월 분기는 1분기 결산) |
| D8 | 연간 결산 분기 여부는 분기마다(`a`) 기록 | 결산월을 바꾼 기업의 과거 연간 분기가 +60일로 앞당겨지는 누설을 막는다(PR #16 리뷰) | 파일이 분기당 숫자 하나 커진다 |
| D9 | 상장주식수 ≤ 0이면 PER·PBR 계산 불가 | 주식수를 못 읽은 종목이 PER·PBR 0으로 저평가처럼 보이는 것을 막는다(PR #16 리뷰) | 그 종목은 PER·PBR 조건·정렬에서 빠진다 |
