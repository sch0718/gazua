# 내 투자 성과 설계

작성 2026-10-23. 기반 스펙은 [비교 화면 설계](2026-10-11-stock-compare-design.md)와 [시뮬레이션 설계](2026-10-12-backtest-simulation-design.md)다.

## 1. 목표와 범위

### 1.1 목적
토스증권 계좌에서 **실제로 체결된 주문**을 받아 온다. 그리고 같은 날 같은 금액으로 지수나 지수 ETF를 샀다면 지금 얼마일지와 비교한다.

성공 기준: 다음 질문에 화면 하나로 답할 수 있다.
- "내 매매가 그냥 KODEX 200을 산 것보다 나았나?"
- "어느 종목이 시장을 이기고, 어느 종목이 졌나?"
- "올해만 보면 어땠나?"

### 1.2 왜 토스만인가
여러 증권사 계좌를 합치려면 마이데이터가 필요하다. 그런데 개인은 마이데이터를 쓸 수 없다. 그래서 첫 단계는 토스 계좌만 다룬다. 공급자 인터페이스(`AccountSource`, 2.2)는 공급자와 상관없게 두어, 나중에 다른 출처를 붙일 수 있게 한다.

### 1.3 대화에서 확정한 것 (2026-10-23)

| 항목 | 결정 |
|---|---|
| 화면 위치 | 새 화면 `#/performance`. 상단 바와 PC 레일에 `내 성과`를 더한다 |
| 벤치마크 | 화면에서 고른다. 기본값은 설정 `benchmark` 규칙(AUTO면 종목마다 그 시장 지수). KODEX 200·KODEX 코스닥150 ETF도 고를 수 있다 |
| 가상 체결 | 그날 **종가**로, **소수 수량**까지 산다. 금액이 실제와 정확히 같다 |
| 차트 | 실제와 가상의 `평가금액 + 회수액` 두 선과, `넣은 돈`(누적 매수액) 점선 |
| 기간 | 전체 기간으로 계산한다. 그리고 **연도별 보기**를 더한다 |
| 주문 저장 | IndexedDB에 캐시하고 이어 받는다. 키 잠금을 켜면 저장하지 않는다(4.2) |
| 초과 매도 | 기록된 수량을 넘게 판 부분은 실제·가상 양쪽에서 뺀다. 그 종목은 `맞지 않음`으로 표시한다 |

### 1.4 범위 밖
- 입출금, 배당, 이자, 다른 증권사에서 옮겨 온 주식(입고)은 다루지 않는다. 토스 Open API에 그 내역이 없다.
- 해외 주식(통화가 KRW가 아닌 주문)은 다루지 않는다. 몇 건을 뺐는지만 알린다.
- 장전·장후 시간외 종가 주문은 API에 나오지 않는다. 그래서 수량 대조로만 드러난다.
- 체결 건별 시각은 다루지 않는다. API는 주문 하나를 한 행으로 합쳐 준다.
- 주문을 내거나 고치는 기능은 없다. 프록시는 계속 주문 경로를 막는다(2.1).

## 2. 데이터

### 2.1 프록시 허용 목록 (사용자가 허락한 예외)
- `proxy/src/allowlist.ts`의 toss `exact`에 `'/api/v1/orders': ['GET']` **하나만** 더한다.
- 같은 경로의 `POST`(주문 생성)는 계속 막는다. 다음 경로도 계속 막는다.
  - `/api/v1/orders/{id}`, `/api/v1/orders/{id}/modify`, `/api/v1/orders/{id}/cancel`
  - `/api/v1/conditional-orders`(와 그 아래)
  - `/api/v1/buying-power`, `/api/v1/sellable-quantity`, `/api/v1/commissions`
- 프록시 테스트가 위 경로가 막히는 것을 확인한다.
- README의 보안 주의와 `proxy/README.md`에 이 예외를 적는다.
- `X-Tossinvest-Account` 헤더는 이미 프록시가 전달한다(보유 주식에 쓰는 중). 바꾸지 않는다.

### 2.2 공급자 인터페이스
`MarketDataProvider`에 선택 필드 `account?: AccountSource`를 더한다. 토스와 데모만 구현하고, KIS에는 없다.

```ts
interface AccountSource {
  /** 계좌를 구분하는 값(토스 accountSeq). 캐시 키에 쓴다. 화면에는 보이지 않는다. */
  accountId(): Promise<string>;
  /** 종료된 주문 중 체결이 있는 것. from/to는 주문일(KST) 기준, 양끝 포함, 없으면 전체 기간. */
  closedOrders(opts: { from?: string; to?: string; onPage?: (n: number) => void }): Promise<AccountOrder[]>;
  /** 국내 보유 수량 */
  holdings(): Promise<{ symbol: string; name: string; quantity: number }[]>;
}

interface AccountOrder {
  orderId: string;
  symbol: string;       // 공급자 코드(토스 ETN은 6자리)
  side: 'BUY' | 'SELL';
  status: string;       // 원래 값(FILLED·CANCELED 등). 모르는 값도 받는다
  currency: string;     // 'KRW'가 아니면 계산에서 뺀다
  orderedAt: string;    // ISO, KST
  filledAt: string | null;
  quantity: number;     // 체결 수량(filledQuantity)
  price: number;        // 평균 체결가
  amount: number;       // 체결 금액(filledAmount)
  commission: number;
  tax: number;
}
```

### 2.3 토스 응답 해석
- `GET /api/v1/orders?status=CLOSED&limit=100`를 `X-Tossinvest-Account` 헤더와 함께 부른다. `hasNext`가 true면 `nextCursor`를 `cursor`로 넘겨 이어 받는다.
  - 페이지 한도는 200(주문 2만 건)이다. 넘으면 upstream 오류를 낸다.
  - 같은 커서가 다시 오면 멈춘다(무한 반복 방지).
- 한도 그룹은 `ORDER_HISTORY`다. 수치가 공개되지 않아, 큐에 초당 1회로 둔다(`ACCOUNT`·`ASSET`와 같다).
- 계좌는 `groupImport.holdings`와 같은 규칙으로 고른다. 종합매매(`BROKERAGE`)가 있으면 그것, 없으면 첫 계좌다. 두 곳이 같은 함수를 쓰게 고친다.
- 행 거르기:
  - `execution.filledQuantity`가 0 이하이거나 숫자가 아니면 뺀다.
  - 상태 `CANCEL_REJECTED`·`REPLACE_REJECTED`는 뺀다. 명세상 원주문과 별도로 생기는 레코드라 체결이 두 번 셀 수 있다([live-check ㉗](../../live-check.md)).
  - `averageFilledPrice`가 없으면 `filledAmount ÷ filledQuantity`로 구한다. 둘 다 없으면 뺀다.
  - `filledAmount`가 없으면 `수량 × 평균가`로 구한다.
  - `commission`·`tax`가 없으면 0으로 본다.
- 체결일은 `filledAt`의 KST 날짜다. 없으면 `orderedAt`의 날짜를 쓴다.
- 알려지지 않은 `status`·`orderType`·`timeInForce` 값도 받아들인다(명세의 요구).

### 2.4 데모 계좌
데모 공급자는 결정적인 가짜 계좌를 준다.
- 2025-02부터 오늘 전까지, 데모 종목 넷(005930·000660·042700·000990)에서 정해 둔 매수 9건과 매도 5건을 거래일 축의 비율 위치에 둔다. 가격은 그날 데모 일봉의 종가 근처(seed로 ±0.5%)다. 해외 주문 1건도 섞는다.
- 보유 수량 하나는 일부러 1주 더 많게 둔다. 그래야 `맞지 않음` 화면을 데모에서 볼 수 있다.
- 실제 키 없이 e2e가 이 계좌로 돈다.

### 2.5 시세
- 종목 일봉: `provider.getCandles({ interval: '1d' })`. 범위는 첫 체결일부터 오늘까지다. 거래소는 시뮬레이션과 같은 규칙으로 고른다(KRX가 있으면 KRX, 없으면 통합).
  - 오늘 봉이 있으면 그 종가를 지금 가격으로 쓴다.
- 지수 일봉: `provider.getIndexCandles(KOSPI|KOSDAQ, '1d', …)`
- ETF 일봉: 종목과 같다.
- 시가·고가·저가·종가가 유한한 양수인 봉만 쓴다(`loadSimData`와 같은 규칙).
- 같은 화면을 다시 계산할 때(벤치마크 바꾸기, 연도 바꾸기)는 받아 둔 봉을 다시 쓴다. 메모리에만 둔다. 봉은 저장하지 않는다(기존 캐시 정책 그대로).

### 2.6 수정주가와 실제 체결가
- 일봉은 수정주가다. 체결가는 그날의 실제 가격이다. 액면분할이 있었으면 둘의 단위가 다르다.
- 체결가가 그날 수정 일봉의 [저가 × 0.97, 고가 × 1.03] 안에 있으면 배율을 1로 본다.
- 밖에 있으면 배율 k = 체결가 ÷ 그날 수정 종가를 쓰고 그 종목에 `분할 보정` 배지를 단다.
- 보유 단위(수정 기준 수량)는 체결 수량 × k로 계산한다.
- 평가금액은 보유 단위 × 그날 수정 종가다.
- 수량 대조(3.4)는 배율을 쓰지 않은 실제 수량으로 한다.

## 3. 계산

모든 계산은 `src/lib/perf/` 아래 순수 함수로 둔다. 시각과 날짜는 KST다. 금액은 `roundMoney`(0.0001원)로 맞춘다.

### 3.1 거래일 축
- 첫 체결일부터 마지막 평가일까지, 종목·벤치마크 봉 날짜를 합집합으로 모은다.
- 마지막 평가일은 받은 봉 중 가장 늦은 날이다.
- 어느 날 봉이 없는 종목이나 벤치마크는 직전 종가를 쓴다(거래정지·휴장 차이).

### 3.2 실제 포트폴리오
종목마다 날짜순으로 처리한다. 같은 날에는 매수를 먼저, 그다음 매도를 처리한다. 순서는 주문 시각, 그다음 주문 id로 정한다.

- **매수**: `보유 수량 += q`, `넣은 돈 += 금액 + 수수료`
- **매도**: 처리할 수량 q' = min(q, 기록된 보유 수량)
  - `회수액 += (금액 − 수수료 − 세금) × q'/q`
  - 남는 q − q'(초과 매도)는 실제·가상 양쪽에서 뺀다. 그 종목에는 `초과 매도 n주`를 단다.
- 평가금액(날) = Σ 보유 단위 × 그날 수정 종가
- **부(富)**(날) = 평가금액 + 지금까지의 회수액. 차트의 실제 선이다.

### 3.3 가상 포트폴리오
실제 종목마다 그림자 포지션을 하나씩 둔다. 이렇게 하면 종목별 기여도를 바로 구할 수 있다.

- **벤치마크 고르기**: `자동`이면 종목의 시장(KOSPI → KOSPI 지수, KOSDAQ → KOSDAQ 지수, 그 밖(ETF 등) → KOSPI 지수)이다. 아니면 고른 하나를 모든 종목에 쓴다.
- **매수**: 실제로 나간 돈 c = 금액 + 수수료를 그날 벤치마크 종가 P로 산다.
  - 지수: `단위 += c ÷ P`. 비용은 없다.
  - ETF: 수수료율 r은 그 실제 주문의 수수료 ÷ 금액이다(없으면 시뮬레이션 기본 0.015%). `단위 += c ÷ (P × (1 + r))`
- **매도**: 실제 매도가 그 종목의 기록된 보유 수량에서 판 비율 f = q' ÷ (매도 직전 보유 수량)만큼 그림자 단위를 판다.
  - 지수: `회수액 += f × 단위 × P`
  - ETF: 수수료는 같은 방식으로 r을 쓰고, 세금은 `sellTaxPct(날짜, 시장, isEtf=true)`(지금은 0)를 쓴다.
  - `단위 −= f × 단위`. 다 팔면(f = 1) 정확히 0으로 둔다.
- **벤치마크 봉이 없는 날**(아직 상장 전 등): 그 거래 이후 처음 봉이 있는 날 종가로 산다. 끝까지 없으면 그 거래를 가상 계산에서 빼고 `비교 못 한 거래 n건`으로 알린다. 실제 쪽에서는 빼지 않는다.

### 3.4 수량 대조
- 종목마다 `계산 수량 = Σ 매수 − Σ 매도`(초과 매도 포함, 원래 체결 수량)를 구해 `holdings`의 수량과 비교한다.
- 같으면 `맞음`, 다르면 `맞지 않음`이다. 이유는 다음과 같이 안내한다.
  - 보유가 더 많음: `입고했거나 시간외 종가로 산 주식이 있을 수 있어요`
  - 보유가 더 적음: `출고했거나 시간외 종가로 판 주식이 있을 수 있어요`
- 주문 기록이 없는데 보유한 종목도 `맞지 않음`으로 목록에 보인다. 이 종목은 계산에 넣지 않는다.
- 보유 수량을 받지 못하면 대조 칸을 `확인 못 함`으로 둔다. 계산은 그대로 한다.

### 3.5 지표
- **IRR(금액가중, 연율)**
  - 현금흐름: 매수는 −(금액 + 수수료), 매도는 +회수액, 마지막 날은 +평가금액이다.
  - 실제와 가상은 각자의 흐름으로 구한다. 가상의 매수 흐름은 실제와 같다.
  - XIRR을 쓴다: Σ CFᵢ ÷ (1 + r)^((tᵢ − t₀) ÷ 365) = 0. 뉴턴법을 쓰고, 수렴하지 않으면 [−0.9999, 100]에서 이분법을 쓴다.
  - 부호가 바뀌지 않거나 해가 없으면 null(`계산할 수 없어요`).
  - 기간이 365일보다 짧으면 연율과 함께 기간 수익률 ((1 + r)^(일수 ÷ 365) − 1)도 보인다.
- **손익(원)** = 마지막 날 부 − 넣은 돈. 실제와 가상을 각각 구한다.
- **초과수익**
  - `초과 IRR` = 실제 IRR − 가상 IRR(%p)
  - `초과 손익` = 실제 손익 − 가상 손익(원)
- **종목별 기여도**: 종목마다 실제 손익, 가상 손익, 차이(원), 실제 IRR을 구한다.
  - 차이 = 그 종목의 초과 손익이다. 모든 종목의 차이를 더하면 전체 초과 손익과 같다.
  - 목록은 차이가 큰 순이다.

### 3.6 연도별 보기
- 선택지는 `전체`와 데이터가 있는 해들(최근 해가 앞)이다.
- 연도 Y는 전 해 마지막 평가일의 상태에서 시작한다.
  - 실제·가상 각각, 그날 평가금액을 Y의 첫 현금흐름(−)으로 둔다. 날짜는 Y의 첫 거래일이다.
  - Y 안의 거래 흐름을 더하고, Y의 마지막 평가일(올해면 오늘) 평가금액을 마지막 흐름(+)으로 둔다.
- 손익 = 끝 평가금액 + Y 안 회수액 − 시작 평가금액 − Y 안 넣은 돈
- 차트는 전체 곡선에서 Y 구간만 잘라 보인다. 회수액은 Y 시작에서 0으로 다시 센다. 그래야 선이 시작 평가금액에서 출발한다.
- 종목별 기여도도 같은 방식으로 Y 구간만 계산한다.

## 4. 동작

### 4.1 화면 상태
- 공급자에 `account`가 없음(KIS): `내 성과는 토스증권 계좌에서 볼 수 있어요` 빈 화면과 `설정 열기` 버튼을 보인다.
- 데모: 데모 배너는 앱 전체에 이미 뜬다. 화면 머리에 `데모 계좌예요` 배지도 단다.
- 불러오는 중: `주문 내역을 받는 중 · n건`을 보인다. 페이지마다 갱신한다. 그다음 `시세를 받는 중 · i/N`을 보인다.
- 오류: 연결 오류는 기존 오류 문구(`describeError` 계열)를 쓰고 `다시 시도` 버튼을 둔다. 403 `proxy-path-blocked`이면 `프록시가 주문 조회를 막고 있어요 · 프록시를 새 버전으로 바꿔 주세요`를 보인다.
- 체결 0건: `체결된 국내 주문이 없어요`

### 4.2 주문 캐시 (IndexedDB)
- DB `gazua-account`의 store `orders`를 쓴다. 키는 `<profileId>|<providerId>|<accountId>`이고, 값은 `{ orders: AccountOrder[], syncedAt, syncedThrough }`다.
- 처음에는 전체를 받는다. 다음부터는 `from = syncedThrough − 7일`로 받는다. 받은 행은 `orderId`로 덮어써 합친다. 7일 겹침은 늦게 종료된 주문을 잡으려는 것이다.
- `syncedThrough` = 받은 날(KST)
- 화면에 `마지막으로 받은 때 hh:mm`과 `처음부터 다시 받기` 버튼을 둔다.
- **키 잠금(`keyLock`)이 켜져 있으면 저장하지 않는다.** 메모리에만 두고 탭을 닫으면 사라진다. 켜는 순간 저장된 주문을 지운다.
- `이 기기에서 키 삭제`, 프로필 삭제, `데이터 › 모두 지우기`가 이 DB의 해당 항목도 지운다.
- 데모 공급자는 캐시를 쓰지 않는다.
- IndexedDB를 열 수 없으면(사생활 보호 모드) 메모리로 계속한다.

### 4.3 화면 구성 (위에서 아래)
1. **머리줄**: 제목 `내 성과`, 벤치마크 선택(`자동(시장 지수)` · `KOSPI` · `KOSDAQ` · `KODEX 200` · `KODEX 코스닥150`), 기간 선택(`전체` · `2026` · `2025` …)
   - 벤치마크 선택은 이 화면에서만 기억한다(`perfBenchmark` 프로필 설정). 기본은 설정 `benchmark`(AUTO → 자동)다.
2. **요약 카드 셋**
   - `내 IRR` 12.3% / `벤치마크 IRR` 8.1% / `초과` +4.2%p
   - 각 카드 아래에 손익(원)을 적는다. 초과 카드에는 초과 손익을 적는다.
   - 색은 앱 규칙(`colorConvention`)대로다.
3. **차트**: 실제 부(종목 색 s1), 가상 부(회색), 넣은 돈(점선)
   - 기존 `EquityChart` 패턴(lightweight-charts)을 따른다.
   - 스크럽하면 그날 세 값을 보인다.
   - `표 보기`는 날짜 × 세 값 표다(접근성).
4. **종목별 기여도 표**: 종목, 실제 손익, 벤치마크 손익, 차이, 수량 대조 배지(`맞음`·`맞지 않음`·`확인 못 함`). 그리고 `분할 보정`, `초과 매도 n주` 배지가 붙는다. 행을 누르면 그 종목의 체결 목록이 펼쳐진다(날짜, 매수/매도, 수량, 체결가, 금액).
5. **안내**: 맞지 않는 종목이 있으면 이유 목록을 보인다. 늘 작은 글씨로 다음을 적는다.
   - `배당·입출금·입고는 토스 API에 없어 빠져요 · 시간외 종가 주문은 조회되지 않아요 · 가상 매수는 그날 종가로 계산해요`
   - 뺀 주문이 있으면 `해외 주문 n건은 뺐어요`를 덧붙인다.

### 4.4 반응형·접근성
- 폰: 카드 세 장을 가로 스크롤 없이 3열로 줄여 보인다. 좁으면(<360px) 세로로 쌓는다. 표는 종목, 차이, 대조 배지만 보이고 나머지는 펼친 줄에 둔다.
- PC(≥1024): 레일에 `내 성과` 항목을 두고, 차트와 표를 2열로 놓는다.
- 숫자에 `tabular-nums`를 쓴다. 선택지는 기존 `Segmented`/`select`를 쓴다. axe 위반이 0이어야 한다.

## 5. 보안
- 키, 토큰, accountSeq를 로그와 오류 문구에 넣지 않는다. 오류 로그에는 코드만 남긴다(기존 `warnOnce` 규칙).
- 테스트와 fixture는 가짜 응답만 쓴다. orderId와 accountSeq는 지어낸 값이다.
- 주문 캐시는 계좌 내역이다. 4.2의 규칙(키 잠금이면 저장 안 함, 키 삭제 때 지움)을 지킨다.

## 6. 테스트
- 프록시: `/api/v1/orders` GET은 허용한다. POST, 하위 경로, conditional-orders, buying-power, sellable-quantity, commissions는 거절한다.
- 토스: 페이지 이어 받기, 같은 커서 반복 멈춤, 행 거르기(2.3), 헤더 전달, 계좌 고르기.
- 계산
  - 실제·가상 포트폴리오(지수·ETF, 부분 매도, 초과 매도, 봉 빠진 날, 분할 보정)
  - XIRR(알려진 값, 해 없음)
  - 연도별 보기
  - 기여도 합 = 전체 초과 손익
- 캐시: 이어 받기 `from`, orderId 덮어쓰기, 키 잠금 때 저장 안 함, 지우기
- 화면(컴포넌트): 빈 화면, 불러오는 중, 오류, 결과, 맞지 않음 안내
- e2e(데모): 화면 열기, 벤치마크·연도 바꾸기, 기여도 행 펼치기, axe
