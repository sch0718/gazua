# 해외 지표 알람 설계 (개장 전 + 장중 급변)

2026-11-11. 사용자 1명, 맥 한 대 + 휴대폰, 무료 운영. Codex 검토 1회차(Critical 2·Warning 11) 반영.

## 1. 목적과 근거

국내 반도체·소부장은 미국 지수 선물을, 일부 종목은 유가·미국 금리·달러를 따라 움직이고, 금융·안전자산은 반대로 가는 경향이 있다. 이 경향을 내 관심 종목별로 숫자로 재서 두 시점에 휴대폰으로 알린다.

- 개장 전(08:40): 밤사이 미국 지수 선물 변화 × 종목별 민감도 → 오늘 시초가가 오를지·내릴지 예상. 유가·금리·달러는 방향 참고만 붙인다.
- 장중(10분마다): 미국 지수 선물이 급변하면 함께 움직일 종목

**이미 있는 것으로 안 되는 이유**: 환율·유가 민감도는 선정 기준 검증 화면 안에서만 쓰이고(`src/lib/screen/`), 정해진 시각에 돌거나 밖으로 알리는 장치가 없다. 미국 지수·선물·금리·달러지수는 받지 않는다.

### 1.1 실측(2026-11-11, 11/4~11/10 다섯 거래일, 10분 수익률, 표본 약 145)

| 종목 | 같은 10분 상관(ES/NQ) | 선물이 10분 먼저(ES/NQ) | 다음 10분 방향 적중 |
|---|---|---|---|
| SK하이닉스 | 0.55 / 0.57 | 0.14 / 0.17 | 54~55% |
| 삼성전자 | 0.56 / 0.58 | 0.09 / 0.12 | 56% |
| 한미반도체 | 0.59 / 0.61 | 0.21 / 0.24 | 56% |
| KODEX200 | 0.64 / 0.68 | 0.11 / 0.15 | 54~55% |
| KB금융 | 0.35 / 0.39 | 0.12 / 0.14 | 52~56% |

장중에는 같은 10분 안에서 함께 움직이고, 먼저 맞히는 힘은 약하다. 그래서 장중 알람은 예측이 아니라 「함께 움직일 종목」으로 쓴다. 개장 전은 미국장이 국내장보다 먼저 끝나므로 실제로 시차가 있는 구간이다. 개장 전 모델의 실제 성능은 아직 재지 않았다. 구현 중에 §4.4 백테스트로 재고, 55%를 못 넘으면 개장 전 알람은 켜지 않고 장중만 쓴다.

네이버 10분 자료는 구간 시작 시각으로 표기하고 값은 구간 끝 가격이다(국내 1분봉과 138/138 일치, +9분). 계산할 때 표기 시각에 10분을 더한다.

## 2. 데이터 출처

모두 키 없이 받는다. 증권사 키·토큰을 쓰지 않는다. 경로는 모두 2026-11-11에 받아 확인했다.

| 용도 | 출처 | 비고 |
|---|---|---|
| 개장 전 예측(학습·실행 모두) | 네이버 `api.stock.naver.com/chart/foreign/futures/{ES,NQ}cv1/day?startDateTime=…&endDateTime=…` | 2년 약 560봉. 마지막 봉은 진행 중인 세션이다 |
| 국내 일봉 | 네이버 `api.stock.naver.com/chart/domestic/item/{code}/day?startDateTime=…&endDateTime=…` | 2년 약 530봉, 시가 포함 |
| 유가·금리·달러 민감도(방향 참고용) | FRED `DCOILWTICO`, `DGS10`, `DTWEXBGS` | 기존 `scripts/fetch-fred.mjs`와 같은 CSV 경로. 며칠 늦게 올라온다 |
| 유가·금리·달러 오늘 변화 | 네이버 `marketindex/energy/CLcv1`, `marketindex/bond/US10YT=RR`, `marketindex/exchange/.DXY` | 전일 대비 등락(`fluctuationsRatio`·`compareToPreviousClosePrice`)과 `localTradedAt` |
| 장중 선물 10분 | 네이버 `chart/foreign/futures/{ES,NQ}cv1?periodType=week` | 5거래일 10분 간격, 10분 지연 |
| 장중 국내 10분 | 네이버 `chart/domestic/item/{code}?periodType=week` | 5거래일 10분 간격 |
| 휴장 판단 | 네이버 `polling.finance.naver.com/api/realtime/domestic/index/KOSPI`의 `marketStatus` | 영업일 08:44 `PREOPEN` 확인. 휴장일 값은 확인 필요 |

- 네이버 경로는 공식 API가 아니다. 응답 모양이 바뀌면 그 지표만 빼고 나머지로 계속 돌고, 알림 끝에 「빠진 지표: …」를 붙인다.
- 요청은 종목당 실행마다 1~2번, 30종목이면 10분마다 30~60번이다. 요청 사이 100ms를 둔다.

## 3. 구성

알람은 CLI에서만 쓰므로 `cli/src/alert/`에 둔다.

| 위치 | 하는 일 |
|---|---|
| `cli/src/alert/regress.ts` | 단일 계열 회귀(상수항 포함), 표본·분산 검사. 순수 함수 |
| `cli/src/alert/premarket.ts` | 일봉 정렬, 민감도, 오늘 예상, 백테스트, 문구 |
| `cli/src/alert/intraday.ts` | 10분 수익률, 급변 판정, 동행 민감도, 쿨다운·일일 상한, 문구 |
| `cli/src/alert/state.ts` | 실행 간 상태와 기록 파일 |
| `cli/src/naverMarket.ts` | 네이버 응답 읽기·정규화(시각 보정 포함) |
| `cli/src/commands/alert.ts` | `gazua alert premarket \| watch \| stats \| test`, ntfy 전송 |
| `cli/src/execute.ts` | `COMMANDS`에 `alert` 등록, `SECRET_ENV`에 `GAZUA_ALERT_NTFY_TOPIC` 추가 |
| `cli/src/args.ts` | `--symbols` 옵션 추가. 하위 명령은 기존 `positionals[0]` |
| `cli/macos/alert-agent/install.sh`, `uninstall.sh` | launchd 에이전트 설치·제거, ntfy 토픽 생성 |

경로는 모두 기존 `ctx.dir`(`configDir`, `XDG_CONFIG_HOME`을 따른다) 기준이다. 아래 `<dir>`이 그것이다.

### 3.1 대상 종목

동기화된 프로필의 관심 그룹 종목(기존 `watchlists`와 같은 경로, `gazua login` 필요). 숨긴 종목은 뺀다. 최대 30종목이고, 넘으면 그룹 순서대로 앞 30개를 쓴다. 프로필이 여럿이면 기존 규칙대로 `--profile`이 필요하므로, 설치 때 프로필 ID를 받아 실행 인자에 넣는다. `--symbols 000660,005930`을 주면 프로필을 읽지 않으므로 로그인 없이 돈다.

### 3.2 설정 `<dir>/alert.env` (파일 600)

```
GAZUA_ALERT_NTFY_TOPIC=<설치 때 무작위 생성>
GAZUA_ALERT_NTFY_SERVER=https://ntfy.sh
GAZUA_ALERT_SPIKE_SIGMA=2.5        # 장중 급변 기준
GAZUA_ALERT_COOLDOWN_MIN=0         # 같은 지표 재알림 간격(분). 0 = 제한 없음
GAZUA_ALERT_DAILY_MAX=0            # 하루 알람 상한. 0 = 제한 없음
GAZUA_ALERT_TOP=5                  # 알림 한 건에 넣을 종목 수(오르는 쪽·내리는 쪽 각각)
```

명령은 기존 `--env-file <dir>/alert.env`로 이 파일을 읽는다. 값이 숫자가 아니거나 음수면 `invalid-args`로 끝낸다.

토픽 이름은 저장소 어디에도 적지 않는다. ntfy 공개 서버는 토픽 이름을 아는 사람이면 누구나 구독할 수 있으므로 추측하기 어려운 이름(무작위 24자)을 쓴다. 토픽은 `SECRET_ENV`에 넣어 표준 출력·오류·로그에서 가린다. ntfy 오류 메시지에는 URL을 넣지 않고 HTTP 상태만 적는다. 설치 스크립트가 구독 안내로 터미널에 한 번 보이는 것만 예외다. 보내는 내용은 종목명·방향·퍼센트뿐이다.

## 4. 개장 전 알람 (`gazua alert premarket`, 평일 08:40)

### 4.1 실행 조건

- KST 08:00~08:59에만 보낸다. 잠자기 뒤 늦게 깬 회차(launchd는 놓친 회차를 깨어난 뒤 한 번 돌린다)가 09:00 이후면 기록만 남기고 보내지 않는다.
- `marketStatus`가 `PREOPEN`·`OPEN`이면 영업일, 그 밖의 값이면 휴장으로 보고 보내지 않는다. 판단이 안 되면 보내고 끝에 「휴장 여부 확인 못 함」을 붙인다.
- 같은 KST 날짜에 이미 보냈으면 다시 보내지 않는다(상태 파일).

### 4.2 민감도

국내 거래일 t마다:

- `y_t = ln(시가_t / 종가_{t-1})` — 국내 전 거래일 종가에서 오늘 시가까지.
- `x_t = ln(F[t] / F[t-1])`. `F[d]`는 `localDate < d`인 선물 일봉 중 마지막 봉의 종가다. 선물 일봉은 미국 동부 17:00(KST 07:00 무렵)에 끝나므로, 국내 날짜 d보다 앞선 봉은 d의 개장 전에 끝난 봉이다. 국내 연휴로 미국 세션이 여러 개 끼면 그만큼 쌓인 변화가 된다.
- ES·NQ는 서로 상관이 0.95를 넘어 함께 넣으면 계수가 흔들린다. 종목마다 `y = α + β·x`를 ES·NQ 각각으로 맞추고 결정계수가 큰 쪽 하나를 쓴다.
- 학습 구간은 지난 250거래일. 유효 표본이 120일보다 적거나, x·y가 유한하지 않거나, x의 분산이 0이면 그 종목은 뺀다. `|y| > 30%`인 날(분할·병합 의심)은 뺀다.

유가·금리·달러: 국내 종가 기준 일간 변화(`ln(종가_t/종가_{t-1})`)를 같은 날짜의 FRED 변화(유가·달러는 로그 변화, 금리는 %p 차이)에 단일 회귀해 베타의 부호와 t값만 쓴다. `|t| ≥ 2`인 종목만 「같은 쪽」·「반대쪽」으로 묶는다. FRED가 늦게 올라온 날은 빠진 채로 학습한다.

### 4.3 오늘 예상

- `x_today = ln(F[오늘] / F[국내 전 거래일])`. 학습과 같은 정의다(진행 중인 봉은 쓰지 않는다).
- 예상 시초가 등락 = `expm1(α + β·x_today)`. 이 값의 부호가 방향이다.
- 유가·금리·달러는 네이버 전일 대비 등락을 그대로 보이고, 4.2에서 묶은 종목을 방향만 붙인다. `localTradedAt`이 36시간보다 오래됐으면 그 지표는 뺀다.

```
개장 전 · ES +0.8% NQ +1.1% (11/10 미국 세션)
▲ SK하이닉스 +1.2%(NQ) ▲ 한미반도체 +1.0%(NQ) …
▼ KB금융 −0.2%(ES) …
금리 +4bp ↑ 같은 쪽: KB금융·신한지주 / 반대쪽: …
최근 60일 방향 적중 58%(60일, 표본 1,740 · 늘 오름 기준 51%) · 과거 경향이며 투자 조언이 아님
```

### 4.4 백테스트

- 2년치를 받아 마지막 60거래일을 평가한다. 평가일 d마다 d 직전 250거래일로만 학습하고(d와 그 뒤 자료를 보지 않는다) d를 예측한다.
- 방향 적중 = `sign(예상) == sign(y_d)`. `y_d == 0`인 날은 뺀다. 비교 기준으로 「늘 오름」 적중률을 같이 낸다.
- 시험: 평가일 뒤 값을 바꿔도 예측이 같은지 본다.

## 5. 장중 급변 알람 (`gazua alert watch`, 평일 09:10~15:20 10분마다)

### 5.1 실행 조건

- KST 09:00~15:30이고 `marketStatus`가 `OPEN`일 때만 돈다. 아니면 기록 없이 끝낸다.
- 선물 10분 자료의 마지막 완성 봉(표기 시각 + 10분이 지금보다 이른 봉)이 30분보다 오래됐으면 보내지 않는다.

### 5.2 판정

1. ES·NQ마다 마지막 완성 봉의 10분 로그 변화와, 지난 5거래일 국내 정규장 시간대 10분 변화의 표준편차를 구한다. 앞 봉과 10분 간격이 아니면(빠진 봉) 그 회차는 판정하지 않는다. 표준편차가 0이거나 표본이 60보다 적으면 그 지표는 건너뛴다.
2. `|변화| ≥ SPIKE_SIGMA × 표준편차`이면 급변이다.
3. 급변한 지표마다 종목별 동행 민감도(지난 5거래일 같은 10분 수익률의 단일 회귀 베타) × 변화로 상위 종목을 고른다.
4. 같은 지표의 같은 봉은 설정과 상관없이 두 번 보내지 않는다. `COOLDOWN_MIN`이 0보다 크면 같은 지표는 그 시간 안에 다시 보내지 않는다. `DAILY_MAX`가 0보다 크면 KST 하루에 그 수를 넘겨 보내지 않는다. 기본값은 둘 다 0(제한 없음).

```
장중 10:40 · ES −0.5%(10:20~10:30 봉, 데이터 10분 지연) 급변
함께 눌릴 종목 ▼ SK하이닉스 −0.9% ▼ 삼성전자 −0.7% …
참고(전일 대비) 유가 +0.4% 달러 +0.1% 금리 +2bp
```

## 6. 상태·기록·적중률

- 상태는 명령마다 따로 둔다. `<dir>/alerts/premarket-state.json`에는 마지막으로 보낸 날짜와 로그인 필요 알림을 보낸 날짜를, `<dir>/alerts/watch-state.json`에는 지표별 마지막 처리 봉·마지막 발송 시각, KST 날짜별 발송 수, 로그인 필요 알림 날짜를 둔다. 쓰기는 기존 `writeJsonFile`(임시 파일 → rename)로 한다. 읽을 수 없으면 빈 상태로 다시 시작한다. launchd는 같은 에이전트를 겹쳐 돌리지 않고, 두 에이전트는 시간대가 겹치지 않으므로(premarket은 09:00 전에만 보낸다) 잠금은 두지 않는다.
- 알람마다 `<dir>/alerts/YYYY-MM.jsonl`에 한 줄: 종류, 관측 구간(봉 시작·끝), 받은 시각, 보낸 시각, 지표 변화, 종목별 예상, 발송 결과.
- 맞춰 보기: 개장 전은 `sign(예상)` 대 `시가/전일 종가`. 장중은 보낸 시각 뒤 첫 완성 10분 봉의 종목 수익률 방향이다(같은 봉 동행이 아니라 받은 뒤의 결과). `stats`를 돌릴 때와 다음 `premarket` 실행 때 맞춰 본다.
- `stats`: 종류별 방향 적중률, 평가 거래일 수, 표본 수, 「늘 오름」 기준, 최근 20일 추이. 실제로 보낸 기록만 센다.
- 개장 전 알림의 적중 줄은 실제 기록이 20거래일 이상이면 기록에서, 그 전에는 4.4 백테스트에서 내고 「백테스트」라고 표시한다. 둘을 섞지 않는다.

## 7. launchd

- 에이전트 두 개: `com.gazua.alert.premarket`(월~금 08:40), `com.gazua.alert.watch`(월~금 09:10~15:20 10분 간격, `StartCalendarInterval` 목록).
- 실행: `<node 절대 경로> <저장소>/cli/dist/gazua.mjs alert premarket --env-file <dir>/alert.env [--profile <ID>]`. node 경로는 설치 때 `command -v node`로 고정한다. 로그는 `~/Library/Logs/gazua/alert.log`.
- `install.sh`:
  1. node(22.13 이상)와 `cli/dist/gazua.mjs`가 있는지 확인하고, 없으면 아무것도 바꾸지 않고 끝낸다.
  2. `alert.env`가 없을 때만 만든다(토픽 생성 포함). 프로필이 여럿이면 `gazua profiles`를 보여 주고 ID를 받는다.
  3. 두 plist를 쓰고 `plutil -lint`로 검사한 뒤, 이미 올라가 있으면 `launchctl bootout`하고 `bootstrap`한다(다시 설치해도 같다). 둘 중 하나라도 실패하면 둘 다 내리고 plist를 지운다.
  4. `gazua alert test`로 시험 알림을 한 번 보내고, 「휴대폰 ntfy 앱에서 이 토픽을 구독하세요」와 토픽을 터미널에만 출력한다.
- `uninstall.sh`: 두 에이전트를 `bootout`하고 plist를 지운다(하나만 있어도 된다). `alert.env`·기록·로그는 남기고, 지울 경로를 알려 준다.
- 저장소를 옮기거나 다시 빌드하면 `install.sh`를 다시 돌린다.

## 8. 오류 처리

- 네이버·FRED 요청 실패: 해당 지표만 빼고 진행하고, 빠진 것을 알림에 적는다. 선물(ES·NQ)이 둘 다 실패하면 알림 대신 로그만 남긴다. 종목 일봉 실패는 그 종목만 뺀다.
- ntfy 실패: 로그에 남기고 기록에는 「보내지 못함」으로 적는다. 재시도는 하지 않는다.
- 프로필을 못 읽음(로그인 만료): 그날 처음 한 번만 「gazua login 필요」를 보낸다(상태 파일).

## 9. 하지 않는 것

앱 화면·앱 푸시, 토스 데이마켓 실시간 시세, 머신러닝 모델, 유가·금리·달러의 퍼센트 예측, 장 마감 뒤 시간외 알람, 매수·매도 권유 문구.

## 10. 시험

- 단위: 회귀(알려진 계수 복원, 표본 부족·분산 0 제외), 선물 일봉 정렬(미국 휴일·국내 연휴로 세션이 쌓이는 경우, 진행 중인 봉 제외), 백테스트 누설(평가일 뒤 값을 바꿔도 예측이 같음), 급변 판정(빠진 봉·표준편차 0 건너뜀), 같은 봉 중복 방지, 쿨다운·일일 상한(0 = 제한 없음 포함), 실행 시간대·휴장·오래된 자료 차단, 문구.
- 네이버 응답 정규화: 2026-11-11 받은 응답을 고정 데이터로(시각 +10분 보정 포함).
- CLI: ntfy·네이버를 가짜 fetch로 바꿔 `premarket`·`watch`·`stats`·`test` 한 번씩. ntfy 오류 출력에 토픽이 나오지 않는지.
- launchd 스크립트: `bash -n`, plist `plutil -lint`, 그리고 이 맥에서 설치 → `launchctl kickstart`로 한 번 실행 → 다시 설치 → 제거를 손으로 한 번.

## 11. 규모와 사용 확인

- 새 파일 9개 안팎, 900~1,300줄 예상. PR을 둘로 나눈다. 첫 PR은 장중 급변과 `test`·설치, 둘째 PR은 개장 전이다. 둘째 PR은 백테스트가 55% 이상이고 「늘 오름」 기준보다 높을 때만 낸다.
- 2026-12-11에 확인한다. 실제 기록 20거래일 이상에서 개장 전 적중률이 55% 미만이거나 「늘 오름」 기준보다 낮으면, 또는 알람을 보지 않았으면 걷어내는 PR을 제안한다.
