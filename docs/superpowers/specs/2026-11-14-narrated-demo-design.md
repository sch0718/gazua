# 음성 내레이션 데모 영상 설계 (2026-11-14)

## 왜 만드나

PR #112의 메뉴별 녹화(`pnpm demo:video`)는 소리 없는 10~20초 조각 7개라, 사용자가 원한 「앱 소개 영상」이 아니었다. 사용자는 음성으로 설명하고 사람이 실제로 쓰는 것처럼 보이는 3~5분 한 편을 원한다. 유튜브 업로드는 사용자가 직접 한다.

이미 있는 것으로 안 되는 이유: `demo-video.mjs`는 소리·자막·커서가 없고, 조작이 기계 속도라 사람처럼 보이지 않는다. 그래서 화면 조작 도우미(`scripts/lib/app-preview.mjs`)만 다시 쓰고 새 스크립트를 둔다. `demo-video.mjs`는 건드리지 않는다.

전제: 운영자 1명 + 지인 몇 명, 무료, 비상업 소개 영상. 사람이 지켜보지 않는 세션에서 만들므로 판단이 갈리면 작은 쪽을 고르고 여기에 적는다.

## 고른 방법과 이유

### 화면 구성: 폰 화면을 가운데

앱은 휴대폰 우선 PWA라 넓은 화면(1920 폭)으로 열면 빈 공간이 많고 실제 쓰는 모습과 다르다. 그래서 폰 화면(뷰포트 390×844, deviceScaleFactor 2로 캡처해 선명하게)을 1920×1080 가운데에 세로 약 920px로 놓는다.
- 왼쪽 빈 곳: 지금 장(章) 이름과 한 줄 설명, 9개 장 진행 표시(지금 장 강조, 첫 화면·마무리도 한 칸).
- 아래: 자막 띠(폰 아래쪽 바깥, 한 줄 38px 안팎).
- 배경: 어두운 단색 그라데이션. 폰 테두리(둥근 모서리 베젤)는 겹침 PNG에 그린다.

### 녹화: CDP screencast 프레임 → ffmpeg

Playwright `recordVideo`는 VP8 저비트레이트라 글자가 뭉개진다. `Page.startScreencast`(JPEG 품질 90)로 프레임과 타임스탬프를 받아 `work/frames/`에 저장하고, ffmpeg concat 목록(프레임마다 `duration`)으로 30fps 고정 영상으로 묶는다. 화면이 안 바뀌면 프레임이 안 오므로, 각 프레임은 다음 프레임 시각까지 유지하고 마지막 프레임은 아래에서 정한 녹화 종료 시각까지 유지한다. 마지막 프레임의 `duration`은 「녹화 종료 시각 − 마지막 프레임 시각」으로 계산한다.

### 사람처럼 보이는 조작: 페이지 안에 손가락 표시를 그린다

폰 화면이라 화살표 커서 대신 반투명 원(손가락 표시)을 쓴다. `addInitScript`로 `pointer-events: none`, `aria-hidden`인 고정 위치 요소를 넣고, Node 쪽 도우미가 움직인다.
- 이동: 지금 위치에서 목표 요소 가운데(약간 흔들림)까지 2차 베지어 곡선, ease-in-out, 거리에 따라 350~900ms. 페이지 안 `requestAnimationFrame`으로 움직이고 끝날 때까지 기다린다.
- 클릭: 도착 후 짧게 멈춤(120ms) → 원이 작아지고 물결(ripple) 퍼짐 → `locator.click()`(Playwright가 실제 클릭).
- 타이핑: 칸을 누른 뒤 `pressSequentially(글자, { delay: 110~160ms })`.
- 스크롤: 대상의 스크롤 부모(없으면 문서)의 `scrollTop`을 ease-in-out으로 500~800ms 동안 바꿔 대상을 화면 가운데쯤으로 가져온다. 순간 이동(`scrollIntoViewIfNeeded`)은 쓰지 않는다.
- 파일 고르기(시장 데이터 가져오기): 버튼을 누르는 모습을 보여 주고 `filechooser` 이벤트에서 `tests/fixtures/market-data-demo.json.gz`를 넣는다.

손가락 표시를 화면 위에 따로 그리는(후처리) 방법보다 작다. 위치 기록·보간이 필요 없다.

### 시간 맞추기: 녹화가 실제로 걸린 시각에 음성을 놓는다

1. 먼저 모든 문장을 음성으로 만들어 길이를 안다(`voice` 단계).
2. 녹화 중 문장마다: 시작 시각을 기록 → 그 문장의 조작을 실행 → `시작 + 앞 쉼 + 음성 길이 + 뒤 쉼`까지 남은 시간만큼 기다린다. 조작이 더 오래 걸리면 기다리지 않고 다음으로 간다(그 사이는 조용히 조작만 보인다).
3. 기록한 실제 시작 시각(`marks.json`)으로 음성을 놓고 자막·겹침을 바꾼다. 그래서 조작이 늦어져도 음성·자막·화면이 어긋나지 않는다.

녹화 시작은 처음 화면이 준비되어 캡처를 시작하는 시점이며 이를 0초로 둔다. CDP 프레임 타임스탬프와 문장 시작 시각은 모두 이 녹화 시작 기준의 경과 초로 환산해 기록한다. 녹화 종료 시각은 마지막 문장의 조작과 「앞 쉼 + 음성 길이 + 뒤 쉼」 대기가 모두 끝난 시점이다. 프레임 수신이 멎은 시각을 녹화 종료로 삼지 않는다. 첫 프레임은 0초부터 유지한다(0초 이전에 받은 마지막 프레임, 없으면 첫 프레임을 0초에 둔다). CDP `timestamp`(epoch 초)와 Node의 `Date.now()/1000`은 같은 기기의 같은 시계라 둘 다 녹화 시작 epoch를 빼서 환산한다.

녹화 종료까지의 경과 시간을 공통 총길이로 사용한다. 화면은 마지막 프레임을 유지하고, 음성은 문장 앞뒤의 쉼과 조작 초과 구간을 무음으로 채우며, 겹침 PNG도 마지막 문장의 뒤 쉼과 조작 초과 구간까지 이어서 화면·음성·겹침의 총길이를 맞춘다.

조작을 음성 길이에 억지로 맞추지 않으므로 영상 길이는 「음성 합 + 쉼 + 조작 초과분」이다. 3~5분을 벗어나면 대본·쉼을 고친다.

쉼: 장 첫 문장 앞 0.4초, 문장 사이 0.5초, 장 끝 0.9초. 처음 화면이 뜨기 전(빌드·서버 시작)은 녹화에 넣지 않는다.

### 음성: Edge TTS `ko-KR-SunHiNeural`

무료, 키 없음. 친근한 해요체와 어울리는 여성 음성. `rate: '+5%'`. 스킬의 `tts.mjs` `speak`를 모듈로 불러 쓰고(해시 캐시, 무음 자르기), 문장은 끝(`.?!`)마다 한 줄로 나눈다. 비공식 경로라 막히면 대안은 `say`의 Yuna(품질 낮음)이고 이번엔 쓰지 않는다. 배경음악은 넣지 않는다.

### 자막: Chrome으로 그린 투명 PNG를 overlay

이 Mac의 ffmpeg에는 libass·drawtext가 없다. 문장마다 1920×1080 PNG 한 장(배경·장 표시·폰 베젤·자막, 폰 화면 자리는 투명)을 헤드리스 Chromium(Playwright)으로 그린다. ffmpeg 한 번으로 합친다: 폰 화면 영상을 축소해 1920×1080 검은 바탕 가운데에 올리고(`pad`), 그 위에 문장별 겹침 PNG(화면 자리만 투명)를 concat 목록(문장마다 `duration`)으로 이어 붙인 스트림을 `overlay`한다. 겹침은 한 층이다.

`subtitles.srt`는 같은 `marks.json`으로 만든다(문장 = 자막 한 칸, 음성 시작~끝).

## 대본과 장면 정의

- `scripts/demo-narrated/script.md`: 사람이 읽는 대본(장 제목 + 문장). `scenes.mjs`에서 만든 파일이라 둘이 어긋나지 않는다.
- `scripts/demo-narrated/scenes.mjs`: 실제로 쓰는 장면 정의. import가 없어 시험에서 바로 읽힌다.

```js
export const VOICE = { provider: 'edge', id: 'ko-KR-SunHiNeural', rate: '+5%' };
export const SCENES = [
  { id: 'intro', title: '가즈아', note: '관심종목 비교·전략 시뮬레이션', lines: [
    { t: '안녕하세요, 가즈아를 소개할게요.', do: async (h) => { /* h.open() 등 */ } },
  ] },
  ...
];
```

- `do(h)`는 문장을 읽는 동안 할 조작이다. `h`는 녹화 도우미(`page`, `tap(locator)`, `type(locator, text)`, `scrollTo(locator)`, `wait(ms)`, `chooseFile(locator, path)`)와 `expect`를 담는다. `do`가 없으면 화면을 그대로 둔다.
- `app-preview.mjs`에서는 `startPreview`·`envPort`·`openApp`(첫 화면 열기)·`FIXED_NOW`만 그대로 쓴다. `enterDemo`·`openSimulation` 같은 함수는 안에서 바로 `.click()`해 손가락 표시를 거치지 않으므로, 장면에서는 같은 선택자를 `h.tap()`으로 누르고 확인은 `expect`로 한다. `newAppContext`는 `deviceScaleFactor`를 넘기지 않으므로 녹화 컨텍스트는 `make.mjs`에서 같은 옵션(로캘·시간대·서비스 워커 차단·도움말 본 것 표시·고정 시각)에 `deviceScaleFactor: 2`를 더해 직접 만든다. `app-preview.mjs`와 `demo-video.mjs`는 고치지 않는다.
- 장 흐름(9장): 첫 화면 → 데모로 둘러보기 → 비교 차트 → 종목 추가·그룹 → 매매 규칙 시뮬레이션과 재생 → 선정 기준 검증 → 내 성과 → 설정(공급자·색 테마) → 마무리.
- 분량: 문장(`t`) 합 1,200~1,900자(공백 포함). 처음엔 900~1,400자로 잡았으나 Edge 음성이 초당 약 8.6자로 읽어 1,226자가 142초(영상 177.6초)였다. 3분을 넘기려고 설명 문장을 더했다(쉼·동작은 늘리지 않음).
- 문장에 `say`가 있으면 음성은 `say`를 읽고 자막은 `t`를 쓴다. 주소처럼 글자와 읽는 소리가 다른 곳에만 쓴다. 마무리에서 `{ t: '주소는 gazua.sch0718.dev예요.', say: '주소는 가즈아 점 에스씨에이치 공칠일팔 점 데브예요.' }`처럼 앱 주소를 말하고, 「투자 조언이 아니에요」를 말한다.
- 데모 모드(가상 시세)만 쓴다. 설정에서는 공급자를 눌러 입력 칸만 보여 주고 저장·진단·암호 설정은 실행하지 않는다. 색 테마는 실제로 하나 바꿔 보여 준 뒤 그대로 둔다(새 컨텍스트라 영향 없음).

데모로 못 보여 주는 것(대본에서 말로만 짧게 언급하거나 뺀다): 실제 증권사 시세 연결, 토스 보유 종목 가져오기·토스 섹터, 내 성과의 실제 토스 계좌, CLI·MCP, 맥 자동화(알람·자동 실행기·실계좌 주문), 동기화·공유.

## 스크립트 구성

`scripts/demo-narrated/` 아래:

| 파일 | 하는 일 |
|---|---|
| `scenes.mjs` | 대본·장면 정의(위) |
| `script.md` | 사람이 읽는 대본. `make.mjs script`가 `scenes.mjs`에서 만든다(손으로 고치지 않는다) |
| `make.mjs` | 단계 실행: `voice` → `record` → `render` → `finish`. 인자 없으면 전부. `--only <단계>` 대신 위치 인자로 단계 이름을 받는다 |
| `human.mjs` | 손가락 표시 주입, 이동·클릭·타이핑·스크롤 도우미, screencast 시작·정지 |
| `frame.html` | 겹침 PNG 틀(배경·장 표시·베젤·자막) |

`package.json`: `"demo:narrated": "pnpm build && node scripts/demo-narrated/make.mjs"`. 포트는 `DEMO_NARRATED_PORT`(기본 4194, 4182와 겹치지 않게).

단계별 출력(`work/` 아래): `voice/*.wav`+`voice.json`(문장별 파일·길이), `frames/*.jpg`+`frames.json`(녹화 시작 기준 프레임 시각과 녹화 종료 시각), `marks.json`(문장별 실제 시작 시각, 녹화 시작 기준 초), `ov/NNN.png`, `screen.mp4`, `audio.wav`, `timeline.json`. 마지막에 `finish.sh`로 `final.mp4`·`final-phone.mp4`, 그리고 `subtitles.srt`·`title.txt`·`desc.txt`.

시작할 때 `tts.mjs`·`finish.sh`(기본 `~/.claude/skills/narrated-video/scripts/`, `NARRATED_VIDEO_SCRIPTS`로 바꿈)와 `uvx`·`ffmpeg`·`ffprobe`가 있는지 보고, 없으면 무엇이 없는지 말하고 끝낸다. 대본을 고치면 전부(`voice`부터) 다시 돌린다.

실패 처리: 녹화 중 조작이 실패하면 그 장 이름과 문장을 출력하고 종료 코드 1. 부분 재시작은 단계 단위(`record`만 다시)로 충분하다. 서버·브라우저는 `finally`로 닫는다.

## 시험

`tests/demo-narrated.test.mjs`(`test:scripts`에 자동 포함) — 장면 정의만 본다:
- 장 9개, id가 정해진 순서와 같다.
- 모든 문장이 비어 있지 않고, 끝이 `.?!`로 끝나며, 문장 안에 다른 문장 끝(`[.?!] `)이 없다.
- `do`가 있으면 함수다. `say`가 있으면 비어 있지 않은 문자열이다.
- 문장 합 길이가 1,200~1,900자.
- 마무리 장에 `투자 조언이 아니에요`가 들어 있다.

녹화·렌더는 시험하지 않는다(브라우저·ffmpeg·네트워크가 필요하고 결과는 사람이 본다).

## 확인

- `ffprobe`로 `final.mp4` 길이 180~300초, 1920×1080, 30fps, H.264·AAC, 영상·음성 스트림 길이 차이 0.2초 이내. `finish` 단계가 끝에 이 값을 출력한다.
- 시간표 계산은 따로 시험하지 않는다(사용자 지시: 시험은 장면 정의만). 위 스트림 길이 검사와 프레임 확인으로 대신한다.
- 10~15개 시각의 프레임을 뽑아 Read로 보고, 자막과 화면 조작이 맞는지 본다.
- 음성은 사람이 들어 봐야 하므로 「들어 보지 못함」으로 보고한다.
